# M7-1 案例检索、结构化筛选与教学详情实施文档

## 1. 阶段目标

M7-1 将 M7-0 的匿名案例从“可以安全保存”升级为“可以安全检索和学习”。本阶段完成：

1. 为匿名快照建立独立的结构化检索索引。
2. 支持命宫、命宫主星、四化、格局、五行局和事件类别组合筛选。
3. 把教学检索与本地案例管理分成两个视图。
4. 只让已复核且教学授权有效的案例进入教学检索和教学详情。
5. 使用确定性命盘事实和格局规则生成教学证据，不依赖 AI 自由编写盘面事实。

## 2. 权限和隐私边界

教学案例必须同时满足：

```text
case_records.status = reviewed
AND case_consents.scope = teaching
AND case_consents.status = active
```

该条件固定写在服务端查询和教学详情服务中。前端不能通过修改查询参数查看草稿、归档或已撤销授权的教学内容。

检索索引只读取：

- `case_records.chart_snapshot_json` 中的匿名结构。
- `case_event_snapshots` 中的匿名事件类别。

索引不会读取：

- 原始 `conversations`。
- `birth_info_json`。
- 聊天消息、摘要、记忆或上下文运行记录。
- 人生事件原始标题、描述和精确日期。

## 3. SQLite v19 检索索引

### 3.1 `case_records.search_index_version`

记录当前案例使用的结构索引版本。升级索引规则时，可以只重建版本落后的案例，不需要修改匿名快照。

### 3.2 `case_search_facets`

每条记录表示一个可检索结构事实：

| `facet_type` | 含义 | 示例 |
|---|---|---|
| `ming_branch` | 命宫地支 | `2 / 寅宫` |
| `ming_major_star` | 命宫主星；空宫使用借对宫主星 | `紫微` |
| `sihua` | 匿名盘面存在的四化类型 | `禄 / 化禄` |
| `pattern` | 确定性格局引擎识别结果 | `杀破狼` |
| `wuxing_ju` | 五行局 | `水二局` |
| `event_category` | 已确认匿名事件类别 | `career / 工作与创业` |

唯一约束 `(case_id, facet_type, facet_value)` 防止同一案例的重复标签。`facet_type + facet_value + case_id` 索引用于组合条件查询。

## 4. 索引生成与回填

首次检索时，服务会查找 `search_index_version` 落后的案例，并从匿名快照重建索引。这样已经由 M7-0 创建的案例无需重新导入。

格局索引复用项目现有的确定性 `detectPatterns` 引擎。为了避免补回隐私字段，检索服务只在内存中构造满足算法接口的最小命盘对象；占位出生资料不会写入数据库、接口响应或导出文件。

索引版本当前为 `1`。后续格局算法或筛选维度变化时，应提升版本并执行重建。

## 5. 搜索服务

接口：

```text
GET /api/cases/search
```

支持参数：

- `q`：匹配匿名标题、案例编号或结构标签。
- `mingBranch`：命宫地支索引 `0-11`。
- `majorStar`：命宫主星。
- `sihua`：禄、权、科、忌。
- `pattern`：格局名称。
- `wuxingJu`：五行局名称。
- `eventCategory`：标准匿名事件类别。
- `limit`、`offset`：分页参数。

多个结构条件使用 AND 组合。例如“命宫在寅 + 紫微 + 化权 + 杀破狼”只返回同时满足全部条件的案例。

响应同时包含：

- 结果总数。
- 可用筛选项和每项案例数量。
- 每个案例的匹配依据。
- 索引版本。

搜索结果不返回匿名快照全文、来源会话编号、授权记录或审计日志。

## 6. 教学详情

页面：

```text
/cases/[caseId]/study
```

接口：

```text
GET /api/cases/[id]/teaching
```

教学详情包含：

1. 建议学习顺序：基础坐标、三方四正、格局条件、事件回看。
2. 匿名十二宫结构。
3. 格局名称、成立条件、加分项、破格项和规则来源。
4. 已概括事件的类别、年龄段和影响级别。
5. 命盘事实、格局引擎和确认事件三类证据清单。
6. 根据本案例结构生成的讨论问题。
7. 单一案例不能证明普遍因果的学习边界。

教学详情由程序确定性生成，不调用模型，不产生 Token 成本。格局解释沿用项目现有规则内容和来源说明。

## 7. 页面信息架构

`/cases` 现在包含两个明确视图：

### 7.1 教学检索

- 默认打开。
- 只展示可教学案例。
- 支持关键词和六类结构筛选。
- 卡片显示命宫主星、格局、五行局、匿名事件数和匹配依据。
- 点击进入教学详情。

### 7.2 本地案例管理

- 展示草稿、已复核和已归档案例。
- 保留原有授权、复核、导出、归档和删除流程。
- 已复核且有教学授权时，可以从管理详情直接打开教学详情。

## 8. 测试覆盖

`npm run test:case-search` 使用独立临时 SQLite 验证：

- SQLite v19 迁移与旧案例索引回填。
- 草稿、无教学授权和归档案例不会进入教学检索。
- 命宫、主星、四化、格局、五行局、事件类别和关键词筛选。
- 不存在结构条件时返回空结果。
- 教学详情包含四组证据、四步学习顺序和四个讨论问题。
- 搜索结果和教学详情不包含来源会话编号、姓名、精确出生日期、地点或事件原文。
- 撤销教学授权后，案例立即从搜索结果消失，教学详情接口同时拒绝访问。
- 恢复授权和复核状态后，案例重新进入检索结果。

## 9. 已知边界

1. 当前数据规模面向本地 SQLite，尚未增加 FTS5 中文分词；关键词使用匿名标题、案例编号和结构标签匹配。
2. 命宫空宫时，主星筛选使用快照中已保存的借对宫主星。
3. 四化筛选当前按“化禄/化权/化科/化忌是否存在”过滤，尚未支持“某星化某项”的联合筛选。
4. 事件筛选只按标准类别，不使用自定义事件名称，避免间接身份信息进入索引。
5. 教学讨论问题是确定性模板，不保存作答记录；后续可接入现有练习系统。

## 10. 下一阶段 M7-2

M7-2 将实现：

- 从教学案例库选择两张匿名命盘并列比较。
- 同一命盘两个大限或年份的结构比较。
- 相同格局在不同案例中的共同点与差异点。
- 对比项逐条展示“相同、不同、无法判断”。
- 对比结论引用两侧匿名案例编号和结构证据。
- 不因为两个案例出现相似事件就推断普遍因果。
