# M9-8 动态十神与作用方向证据审计实施说明

## 1. 阶段目标

M9-8 在 M9-6 跨层干支关系证据和 M9-7 条件冲突审计之上，建立独立的动态十神版本层。程序回答：

- 当前大运、流年表层天干相对日主是什么十神；
- 当前大运、流年地支依次藏有哪些天干，分别是什么十神；
- 藏干属于本气、中气还是余气；
- M9-6 已有关系证据把大运或流年指向原局哪个具体柱位；
- 该指向是否附带 M9-7 的条件齐备、条件缺失、关系并见或暂缓状态。

本阶段不回答十神吉凶、旺衰变化、喜忌、藏干是否引动，以及婚姻、财富、健康、职业等具体事件。

## 2. 数据链路

```text
确定性四柱（日主）
   ↓
M9-5 流年与跨运时间片段
   ↓
M9-6 跨层干支关系证据
   ↓
M9-7 条件与冲突状态
   ↓
M9-8 动态十神角色 + 有证据的原局指向
```

M9-8 不重新计算干支关系，也不改写 M9-6、M9-7 的结论。每个版本同时绑定命盘、流年时间轴、关系证据和条件裁决的版本 ID 与指纹。

## 3. 十神确定规则

十神唯一参照是原局日主天干。对任意动态天干，先比较五行生克，再比较阴阳同异：

| 与日主关系 | 同阴阳 | 异阴阳 |
| --- | --- | --- |
| 同五行 | 比肩 | 劫财 |
| 日主所生 | 食神 | 伤官 |
| 日主所克 | 偏财 | 正财 |
| 生助日主 | 偏印 | 正印 |
| 克制日主 | 七杀 | 正官 |

例如丙日主见丙为比肩、见丁为劫财、见庚为偏财、见辛为正财、见壬为七杀、见癸为正官。

项目用 6tail `lunar-java` 的 `EightChar` 官方实现复核映射口径：天干十神由日干与目标干组成的键查询，地支十神先读取藏干再逐个映射。传统关系名称以《三命通会》卷七中“克我、我克、生我、我生、比和”的分类为校勘来源。

## 4. 藏干模型

十二地支藏干顺序版本化保存在方法配置中：

| 地支 | 藏干顺序 |
| --- | --- |
| 子 | 癸 |
| 丑 | 己、癸、辛 |
| 寅 | 甲、丙、戊 |
| 卯 | 乙 |
| 辰 | 戊、乙、癸 |
| 巳 | 丙、庚、戊 |
| 午 | 丁、己 |
| 未 | 己、丁、乙 |
| 申 | 庚、壬、戊 |
| 酉 | 辛 |
| 戌 | 戊、辛、丁 |
| 亥 | 壬、甲 |

数组第一个记录为本气，第二个记录为中气，第三个记录为余气。只有两个藏干时只生成本气和中气。

“地支包含某藏干”只是一项结构事实，不表示该藏干已经透出、引动、发动或产生实际作用。因此藏干角色不会自行生成原局作用目标。

## 5. 作用方向证据

### 5.1 方向来源

方向链接必须来自同一真实时间片段内的 M9-6 证据，并且同时包含：

- 一个大运或流年动态节点；
- 至少一个原局年、月、日或时柱节点。

程序为每个原局参与柱位生成独立链接，保存：

- 动态层级和干支符号；
- 天干或地支领域；
- 原局柱位、符号；
- 关系类型、关系标签、作用范围；
- M9-6 证据 ID；
- 可用时附着 M9-7 条件记录 ID 和状态。

### 5.2 不做的推断

- 流年与大运之间的关系不会冒充“指向原局”；
- 地支关系属于动态地支整体，不转嫁给某个藏干；
- 没有 M9-6 证据时不自行补充目标；
- “指向月柱”不等于月柱受损、受益或必然发生某类事件；
- M9-7“条件齐备”仍不等于合化成立。

## 6. 跨运流年

如果一个流年跨越实际交运时刻，M9-8 继承 M9-5 的半开区间，生成两个独立片段：

```text
交运前：流年角色 + 流年指向
交运后：流年角色 + 新大运角色 + 各自的原局指向
```

两个片段的关系证据和条件状态不得交叉复用。

## 7. SQLite v30

新增 `bazi_dynamic_ten_god_versions`：

- 绑定命盘、流年时间轴、M9-6 关系证据和 M9-7 条件裁决版本；
- 保存四层上游指纹与动态十神结果指纹；
- 保存方法版本、引擎版本和完整结果 JSON；
- 相同上游版本与方法版本自动复用。

`bazi_conversations` 新增 `dynamic_ten_god_version_id`。新旧会话打开时自动补齐 M9-8 版本，提示词升级为 `bazi-chat-dynamic-ten-god-v7`。

## 8. 接口与页面

新增接口：

```text
GET  /api/bazi/charts/:id/dynamic-ten-gods
POST /api/bazi/charts/:id/dynamic-ten-gods
```

排盘页新增 M9-8 面板，并与 M9-5 至 M9-7 共用流年选择状态：

- 每个真实片段分别显示流年和大运卡片；
- 表层天干与藏干角色分层展示；
- 原局指向显示天干／地支、目标柱位、关系证据和条件状态；
- 无大运或无方向证据时显示明确空状态；
- 页面固定说明“藏干角色不等于引动、证据指向不等于作用结果”。

## 9. 对话上下文与输出守卫

上下文新增“权威八字动态十神与作用方向证据快照”，只注入用户问题指定年份；没有识别到年份时聚焦当前年份。

新增允许能力：

- `dynamic_ten_god_direction_audit`。

新增禁止能力：

- `ten_god_event_mapping`；
- `hidden_stem_activation_verdict`。

输出守卫新增两类拦截：

- 把正财、正官等十神直接写成必然人物或事件；
- 宣告本气、中气、余气或藏干已经透出、引动、发动。

## 10. 来源与方法边界

- [6tail lunar-java `EightChar` 官方实现](https://github.com/6tail/lunar-java/blob/master/src/main/java/com/nlf/calendar/EightChar.java)：用于复核十神与藏干映射的程序口径；
- [6tail lunar-java 项目说明](https://github.com/6tail/lunar-java)：确认官方库覆盖八字、五行与十神能力；
- [《三命通会》卷七](https://zh.wikisource.org/zh-hans/%E4%B8%89%E5%91%BD%E9%80%9A%E6%9C%83/%E5%8D%B7%E4%B8%83)：用于十神生克关系术语校勘。

十神和干支关系属于传统命理分类，不是现代科学因果模型。项目只把可确定计算的关系标签、版本和证据链结构化，不宣称其具备科学预测效力。
