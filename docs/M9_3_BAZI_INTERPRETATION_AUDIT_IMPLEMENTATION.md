# M9-3 旺衰、格局与用神证据审计实施说明

## 1. 阶段目标

M9-3 不把传统命理判断包装成一个不可追溯的“旺衰分数”，而是建立版本化证据审计：程序明确记录月令、根气、透干和地支结构，再生成旺衰证据标签、月令格局候选和分方法取用方向。

本阶段只回答“当前有哪些规则证据”和“哪些结论仍缺条件”，不回答最终身强身弱、成格破格、最终用神、大运流年或具体吉凶。

方法版本：`bazi-interpretation-audit-v1`

引擎版本：`bazi-analysis-engine-v1`

## 2. 来源与方法边界

### 2.1 月令优先，但不能单独决定旺衰

《子平真诠》原本的“论十干得时不旺失时不弱”明确要求结合年、日、时损益和通根，不能见得令便判旺、见失令便判弱。因此本项目把月令设为首要证据，而非最终裁决器。

来源：[《子平真诠》原本](https://www.vr-d.com/pdf-file/%E5%91%BD%E7%90%86/%E5%AD%90%E5%B9%B3%E7%9C%9F%E8%AF%A0%E5%8E%9F%E6%9C%AC.pdf)

### 2.2 通根必须落到实际藏干

首版只把地支实际藏有日主同五行天干称为根气，并区分本气、中气和余气。地支表面五行、十二长生标签和天干比肩不能直接替代藏干通根。《子平真诠》同时强调“干多不如根重”，这也是项目拒绝按字符个数计分的原因。

### 2.3 格局从月令生成候选

《三命通会》提出先看月支，再看透出；《子平真诠》则以日干配月令地支区分财、官、印、食、煞、伤、劫、刃。本项目据此生成月令候选，但不自动推导成败、救应、纯杂或格局高低。

来源：[《三命通会》卷十·看命口诀一](https://www.gushiwen.cn/guwen/bookv_c3f9151be6c8.aspx)

### 2.4 不同“用神”语义必须分开

项目分别保存：

- 月令格局法：用神指月令格局核心。
- 扶抑法：根据生扶与泄耗制证据筛选后续方向。
- 调候法：处理寒暖燥湿。
- 通关与病药法：处理对峙、偏枯和流通。

这些方法不能被合并成一个没有来源的“喜用五行”。调候参考《穷通宝鉴》，但首版只记录寒季温暖、热季润燥等方向；十天干十二月精细表尚未完成版本化校勘，因此状态固定为“待校勘”。

来源：[《穷通宝鉴》](https://zh.wikisource.org/zh-hans/%E7%A9%B7%E9%80%9A%E5%AE%9D%E9%89%B4)、[《滴天髓阐微》](https://zh.wikisource.org/wiki/%E6%BB%B4%E5%A4%A9%E9%AB%93%E9%97%A1%E5%BE%AE)

## 3. 旺衰证据模型

### 3.1 证据层

程序记录：

- 月支本气与日主的生克关系。
- 四支实际藏干中的日主同五行根气。
- 年、月、时天干对日主形成的生扶或泄耗制关系。
- 月支是否参与冲、六合、三合或三会候选。
- 时柱是否缺失。

证据分为首要证据、次要证据和谨慎项，不生成百分比或总分。

### 3.2 允许的输出标签

- `supporting_evidence_established`：生扶证据较明确。
- `draining_evidence_established`：泄耗制证据较明确。
- `mixed_evidence`：两类证据并见。
- `insufficient_due_to_unknown_time`：时柱缺失，证据不足。

这些标签描述证据分布，不等于最终身强或身弱。月支参与结构作用时，置信度自动降为低；未知时辰直接进入证据不足状态。

## 4. 格局候选模型

月支本气是第一候选来源；中气或余气只有在年、月、时天干透出时才加入候选。

候选状态：

- `supported_candidate`：月令本气候选且有透干支持。
- `candidate`：月令本气基础候选。
- `review_required`：杂气月、非本气透出或月支参与结构作用，需要复核。

辰、戌、丑、未统一按杂气月处理。程序会检测冲、六合、三合和三会，但只记录 `detected_not_transformed`，不会自动宣告合化、解冲或变格。

## 5. 分方法取用审计

### 5.1 月令格局法

记录月令候选的十神与元素，状态为候选方向；必须继续检查格局成败、救应、纯杂和制化。

### 5.2 扶抑法

只有旺衰证据单侧较明确时才生成方向：

- 生扶证据较明确：列出食伤、财、官杀方向。
- 泄耗制证据较明确：列出印、比劫方向。
- 证据混合或时柱缺失：保持空值。

方向列表不是最终用神，并且不能覆盖格局与调候的冲突。

### 5.3 调候法

- 亥、子、丑月：只标记温暖方向。
- 巳、午、未月：只标记润燥降温方向。
- 春秋及具体天干月份：等待原表校勘，不自动指定元素。

### 5.4 通关与病药法

首版保持暂缓。完成合化、刑冲解法和两行对峙规则前，不允许按五行数量自动选取通关或病药用神。

## 6. SQLite v25 解释版本

新增 `bazi_analysis_versions`：

- 关联具体八字命盘版本。
- 保存解释方法版本和引擎版本。
- 保存原命盘指纹和解释结果指纹。
- 保存完整解释证据快照。
- 同一命盘、方法版本和引擎版本只生成一份记录。

`bazi_conversations` 新增 `analysis_version_id`。八字会话不仅固定命盘版本，也固定解释证据版本；旧会话首次读取时自动补齐当前解释版本和提示词版本。

## 7. 对话能力升级

提示词版本升级为 `bazi-chat-interpretation-audit-v2`。Context Builder 新增“权威八字解释证据快照”，允许 AI 解释：

- 旺衰证据为什么得到当前标签。
- 月令格局候选及需要复核的原因。
- 格局、扶抑、调候、通关病药的术语差异。

AI 仍不得：

- 把证据标签改写为最终身强身弱。
- 宣告成格、破格或格局高低。
- 把候选元素说成最终用神、喜神或忌神。
- 推导大运、流年和具体事件。

## 8. 页面展示

八字排盘页新增三栏证据面板：

- 旺衰证据与置信度。
- 月令格局候选与复核状态。
- 月令格局、扶抑、调候、通关病药的分方法取用状态。

已保存命盘会在后台建立 v25 解释版本；进入聊天后，对话固定引用该版本。

## 9. 自动化验收

新增：

```bash
npm run test:bazi-interpretation
```

覆盖：

- 方法论结构和来源完整性。
- 生扶、泄耗制、证据混合和未知时辰四种路径。
- 实际藏干通根。
- 月令本气格局候选。
- 月支冲合后的人工复核。
- 扶抑候选方向和调候待校勘边界。
- 禁止旺衰分数和最终用神。
- SQLite v25 解释版本去重、指纹、会话绑定和级联删除。
- Context Builder 注入证据快照与能力清单。
