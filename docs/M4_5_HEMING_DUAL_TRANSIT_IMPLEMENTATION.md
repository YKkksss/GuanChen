# M4-5 双人年度运限实施说明

> 完成日期：2026-08-15
> 范围：双人年度快照、关系维度激活、分层规则、持久化、年度对话与工作台

## 1. 阶段结果

M4-5 已把两套单盘年度运势能力接入合盘模块。用户可以从合盘工作台进入“双人运限”，选择双方都在有效年龄范围内的年份，同时查看甲方与乙方的流年、大限、四化和重点宫位，并按当前关系类型查看各关系维度由哪一方激活。

同一合盘、同一年份、同一算法版本和相同关系背景只计算一次。刷新页面或再次进入会优先读取 SQLite 快照；命盘、关系类型或已确认关系背景发生变化时，输入指纹改变，系统会自动重建该年份快照。

## 2. 计算与分层模型

双人运限不是另起一套排盘算法，而是分别调用现有 `buildAnnualTransitSnapshot` 生成 A、B 两份权威年度快照，再按所选年份把双方命盘对齐到各自大限，调用合盘规则引擎完成阶段评估。

页面和 AI 上下文统一分为三层：

1. 本命关系基线：不随所选年份改变的关系结构和规则结果。
2. 双方阶段：甲乙各自所处大限，以及由此触发的阶段规则。
3. 年度关注：流年重点宫位与当前关系维度的交集，标记为双方、甲方、乙方或暂未直接激活。

年度激活只表示某个关系主题在该年更值得观察，不表示事件必然发生，也不产生关系匹配分、吉凶总分或确定性日期。

## 3. 持久化与缓存

数据库迁移版本 8 新增 `heming_transit_snapshots`：

- 以会话、年份、命盘引擎版本、运限引擎版本和方法论版本构成唯一缓存键。
- `snapshot_json` 保存完整的双人年度确定性快照。
- `inputFingerprint` 覆盖双方命盘、关系类型和关系背景，用于发现同一缓存键下的输入变化。
- 删除合盘会话时，年度快照通过外键级联删除。

单盘和双人运限采用独立数据表，避免把双盘身份和关系维度塞入单盘快照，保留后续独立演进空间。

## 4. 页面与接口

新增：

- 页面：`/heming/[id]/timeline`
- 接口：`GET /api/conversations/[id]/heming-transits?year=YYYY`
- 合盘工作台入口：“双人运限”

年度页面包含年份切换、双方年度卡片、四化、关系维度标签、本命基线、所选年份阶段结果、风险提示，以及固定高度的年度专属聊天区。

可选年份取双方范围的交集：从较晚的出生年份开始，到双方 130 岁上限与系统 2200 年上限中的最小值结束。服务端会再次校验，不能通过修改请求绕过。

## 5. AI 上下文

年度页面发起提问时，消息元数据写入：

```json
{
  "transit": {
    "level": "year",
    "targetDate": "2026"
  }
}
```

双命盘 Context Builder 根据该元数据读取或创建对应年度快照，并增加 L4“双人确定性运限”层。该层只提供甲乙分离的结构化事实、关系维度激活、阶段规则和警告；模型仍受本命权威层、方法论边界和用户确认事实约束。

普通合盘聊天不携带年度元数据，因此不会无条件增加年度 Token。年度对话仍复用已有的历史持久化、最近消息、关键记忆、滚动摘要和预算裁剪机制。

## 6. 安全边界

- 不生成结婚、分手、签约、投资、疾病等确定性事件或日期。
- 不把双方同时激活解释为“好时机”，也不把未同步解释为关系失败。
- 不发送姓名、出生地点、自化等方法论禁用字段给模型。
- 未知出生时辰会保留低置信度警告。
- 本命基线和年度阶段分开呈现，年度变化不能反向改写本命规则。

## 7. 自动化验证

新增 `npm run test:heming-transits`，覆盖：

- A、B 年度快照归属和四化完整性。
- 同年缓存复用与跨年快照隔离。
- 关系类型或背景变化后的输入指纹失效。
- 本命基线跨年份保持稳定。
- 年度关系维度的双方激活状态。
- 年度事实进入双命盘上下文且敏感、禁用字段不进入模型。
- 非法年份拒绝与删除会话后的级联清理。

同时要求通过 TypeScript、现有单盘运限、M4 全链路测试、生产构建和端口 30001 的真实页面验收。
