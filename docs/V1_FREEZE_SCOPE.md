# v1.0 固定范围与收尾顺序

确认日期：2026-09-07。用户已确认本范围，并授权按顺序继续开发。

## 定位与范围规则

v1.0 是面向个人及可信局域网使用的命理研究工作台。保留已实现的 M0–M9 核心闭环，以及 F01–F12、聊天布局、聊天设置和 Markdown 改进。

本文件是 v1 收尾的执行依据；原开发规划与 09-05 交接中的更远期建议作为后续版本候选，不能自动扩大 v1 范围。冻结前只增加完成核心流程所必需的修复。发现新问题时，先判断是否导致错误数据、数据丢失、核心流程不可用或明显操作障碍；非阻断项记入后续版本。

## 当前优先级：功能主线优先（用户已确认）

用户在第四批收尾后调整优先级：先补核心功能与实际使用价值，暂停备份等衍生模块扩展。此决策覆盖下方原收尾顺序中“立即进入发布验收”的安排，也允许补齐核心功能缺口，不再仅限工程阻断修复。

1. 命盘与 AI 解读：上下文准确、连续追问、解读围绕问题。已补宫位/指定运限追问延续、降级专题事实，以及自然语言年度运限和最多三年份比较；真实模型回答质量继续随功能验收核对。
2. 事件与运势分析：已确认事件、时间轴与运限之间的有效关联。已补年度、流月与流日 AI 上下文的事件匹配和日期精度区分；下一步推进专题报告的信息价值与事实组织。
3. 专题报告：信息价值、重复与空泛内容、关键事实遗漏。
4. 合盘、八字、生时校正：逐项补齐实际业务流程。

已有备份功能保留，不继续扩展；核心功能完成后，在正式冻结前做必要恢复验证与整体验收。未新增 M10，不提前冻结 v1。

## 冻结验收门槛

- [ ] 合成资料走通录入 → 起盘 → AI 聊天 → 历史重开 → 事件确认 → 报告查看与导出。
- [ ] 独立测试数据库实际完成备份恢复、单命盘导入导出，核对恢复结果。
- [ ] 验证失败、停止、刷新和快速切换：不误覆盖资料，操作结果与恢复入口清晰。
- [ ] 桌面浏览器验收通过。
- [ ] 至少一台真实手机及另一台局域网主机验收通过；响应式模拟不替代实机确认。
- [ ] 生产构建通过，安装、升级、备份与已知限制说明齐备。
- [ ] 用户确认最终使用验收；保留发布备份，记录冻结提交并创建 v1.0.0 标签。

范围固定不等于版本已冻结。任何未验证项不得填写为通过；在上述门槛满足前不提前修改版本为正式 v1.0.0、不提前打发布标签。

## 开发与验收约束

按可验收批次记录修改、检查结果和余项，提交到 dev；不自动合并 main。开发验证使用合成出生资料、独立 SQLite 和本地 AI 模拟服务，不读取真实档案或外呼真实 AI。无需变更数据库结构时保持当前 v47。

局域网数据保存在部署电脑，访问者共享该部署的数据；v1 不包含多用户账号隔离和跨设备独立数据库。公开商业发布、法律主体和品牌确认另行处理，不在本轮自行虚构。
