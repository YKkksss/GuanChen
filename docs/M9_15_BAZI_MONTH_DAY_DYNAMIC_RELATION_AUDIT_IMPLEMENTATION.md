# M9-15 八字流月、流日五层动态关系证据审计实施说明

## 1. 阶段结论

M9-15 在 M9-14 精确流月流日时间事实层上，补齐了指定日期的五层动态关系证据审计。系统现在可以按某个有效日期组合：

- 原局四柱；
- 当时所在的大运；
- 当时所在的流年；
- 当时所在的流月；
- 当日流日。

系统会对流日内部每一个精确时间片段分别计算干支关系、条件状态和动态十神角色，并把结果按日期保存。此阶段只说明“有哪些结构关系、关系条件是否齐备、参与者分别是谁”，不计算吉凶、力量分数，也不推断具体事件。

## 2. 为什么必须建立五层证据层

M9-6 至 M9-8 已经分别解决了原局、大运、流年的关系目录、条件状态和动态十神映射，但流月、流日加入后，不能把五层干支简单拼成一段自然语言交给模型。这样做会产生三个问题：

1. 模型可能漏掉或虚构冲、合、刑、害关系；
2. 跨节或跨运的同一天可能被错误地当作单一状态；
3. “存在关系”容易被越权解释成“关系已经产生某种吉凶结果”。

因此 M9-15 继续采用确定性规则引擎：程序先生成结构化证据，AI 只在允许边界内解释这些证据。

## 3. 复用边界

本阶段没有重新发明第二套关系规则，而是复用已经测试过的能力：

| 上游阶段 | 复用内容 | M9-15 的限制 |
| --- | --- | --- |
| M9-6 | 天干生克、天干五合、地支冲合刑害、三合三会等关系目录 | 只保留至少包含流月或流日参与者的证据 |
| M9-7 | 条件齐备、三字缺一、关系并见、暂缓裁决 | 不判断合化、解冲、优先级和最终作用 |
| M9-8 | 以原局日主为唯一参照的动态十神映射 | 藏干只记录角色，不宣告已经透出或发动 |
| M9-14 | 精确流月、流日及跨节、跨运片段 | 每个时间片段独立审计，证据不得跨片段混用 |

底层关系审计器被抽取为可接收任意节点集合的公共能力。原有三层结果仍保持兼容，五层审计通过同一套检测器生成证据，从而避免规则漂移。

## 4. 五层节点和关系范围

每个片段最多包含以下节点：

```text
原局：年柱、月柱、日柱、时柱（时辰未知时缺失）
大运：当前大运干支（未交首运时缺失）
流年：当前流年干支
流月：当前流月干支
流日：当前流日干支
```

关系证据扩展了以下动态范围：

- 流月对原局、流月对大运、流月对流年；
- 流日对原局、流日对大运、流日对流年、流日对流月；
- 流月内部或流日内部参与三合、三会、三刑等多参与者条件关系。

最终结果不会重复输出与当日无关的纯原局、大运、流年旧证据。过滤规则要求每条 M9-15 证据至少出现一个 `month` 或 `day` 参与者，保证本阶段回答的是“这一个月、这一天新增了什么结构联系”。

## 5. 精确片段审计

一个有效流日可能在当天中途遇到节界或交运时刻。M9-15 不把当天关系强行合并，而是继承 M9-14 的前闭后开区间并逐段计算。

例如某日 `06:51:00` 交入新大运：

```text
00:00:00 — 06:51:00  原局 + 流年 + 流月 + 流日
06:51:00 — 24:00:00  原局 + 新大运 + 流年 + 流月 + 流日
```

前一片段没有大运节点，后一片段才允许出现流月对大运、流日对大运等证据。每条参与者数据同时携带层级、柱位或运序、流月序号、有效日期，便于界面和 AI 追溯来源。

## 6. 条件状态与十神角色

### 6.1 条件状态

关系检测后继续使用 M9-7 的条件语义：

- `full_condition`：当前片段参与者齐备；
- `partial_three_set`：三合、三会或三刑缺少一个成员；
- `deferred_combination`：存在合类结构，但合化条件和结果暂缓；
- `coexistence`：同一参与者上存在多种关系，需要并列展示。

这些状态是结构门槛，不是吉凶裁决，也不代表某一种关系压过另一种关系。

### 6.2 动态十神

大运、流年、流月、流日的表层天干和藏干都以原局日干为参照映射十神。结果保存：

- 动态层级；
- 表层天干十神；
- 各藏干十神；
- 对应干支和时间定位。

藏干十神在 M9-15 只是角色元数据。是否透干、是否得根、是否被流月流日触达，留到 M9-16 单独审计。

## 7. 数据模型与按日缓存

SQLite 升级到 v37，新增 `bazi_month_day_relation_versions`：

- `chart_version_id`：绑定不可变命盘版本；
- `month_day_timeline_version_id`：绑定 M9-14 目标流年的时间事实版本；
- `target_date`：当前证据版本对应的有效日期；
- 方法版本、引擎版本和两个上游指纹；
- 完整五层片段、关系、条件和十神 JSON 快照；
- 当前结果指纹与创建、更新时间。

唯一键由命盘版本、流月流日时间轴版本、有效日期、方法版本和引擎版本组成。相同输入和日期重复请求会复用旧版本；规则或上游版本升级后可以并存新版本。

`bazi_conversations.month_day_relation_version_id` 保存对话默认绑定的日期证据版本。用户明确询问其他日期时，上下文构建器会按需生成或读取该日版本，并在本次上下文清单中记录实际版本 ID、日期和指纹。

按日缓存避免把每个流年约 365 个日期的五层关系一次性全部写入数据库，也避免用户只查看一天时计算整年关系。

## 8. API

新增：

- `POST /api/bazi/charts/:id/month-day-relations`：传入 `targetDate`，生成或复用指定日期证据；可选 `targetYear` 用于显式绑定上游流年版本。
- `GET /api/bazi/charts/:id/month-day-relations?date=2030-12-12`：读取指定日期的最新证据，并返回该命盘已缓存的日期版本列表。

`targetDate` 必须使用 `YYYY-MM-DD` 格式。服务端会根据流年立春有效区间解析该日期所属的目标流年，而不是简单使用公历年份。

## 9. 工作台交互

八字工作台在 M9-14 流日核验器下新增“M9-15 五层动态关系证据审计”：

- 与用户选择的流日联动；
- 按精确片段展示当时存在的动态层；
- 展示流月、流日及其他动态层的表层、藏干十神角色；
- 展示每条关系的参与者、范围和证据说明；
- 展示条件齐备、缺一、暂缓和并见状态；
- 明确显示跨节、跨运时各片段证据互不混用。

已保存命盘在选择日期后会后台持久化；尚未保存的临时排盘可以在浏览器内得到同样的确定性结果，但不会写入 SQLite。

## 10. AI 上下文与输出边界

提示词升级为 `bazi-chat-month-day-relation-v14`。

当问题包含明确日期，或询问“今天/今日”时，上下文会注入“权威八字流月流日五层关系证据快照”，内容包括：

- 实际审计日期和精确片段；
- 各片段动态十神角色；
- 至少包含流月或流日的关系证据；
- 条件状态和关系并见；
- 方法版本、结果指纹和能力边界。

普通流年问题不会无条件注入按日五层快照，避免占用长上下文预算。

新增允许能力：

- `month_day_relation_evidence_audit`

新增禁止能力：

- `month_day_relation_effect_verdict`

输出守卫会拦截把流月流日冲、合、刑、害等结构直接改写成必然吉凶或具体事件的越权回答。

## 11. 降级规则

- 时辰未知：保留年、月、日三柱及动态层，状态标记为 `partial_unknown_time`，不伪造时柱关系。
- 非 `Asia/Shanghai`：如果 M9-14 无法提供可信的精确流日片段，状态标记为 `sequence_only_unavailable`，不生成伪造的五层证据。
- 未交首运：对应片段不创建大运节点，不用空值冒充大运关系。
- 日期不在目标时间轴：明确报错，不静默改用相邻日期。

## 12. 测试覆盖

专项测试 `test:bazi-month-day-relations` 覆盖：

- 方法契约与禁止项；
- 原局、大运、流年、流月、流日节点组合；
- 同一天跨交运时刻的双片段隔离；
- 证据必须包含流月或流日参与者；
- 流月、流日对各层的关系范围；
- 三字缺一、合类暂缓和关系并见状态；
- 表层与藏干动态十神角色；
- 未知时辰和非支持时区安全降级；
- SQLite v37 迁移、按日版本指纹和幂等复用；
- API、对话默认绑定和问题日期动态路由；
- 流月流日最终作用与吉凶越权输出守卫。

## 13. 当前仍不能回答的问题

M9-15 完成后仍不能自动回答：

- 某种冲合最终是吉是凶；
- 某关系是否已经合化、解冲或压过其他关系；
- 流月流日加入后日主具体增强或减弱多少；
- 藏干是否已经透出、得根或被有效触发；
- 某天必然发生事业、感情、健康或财务事件；
- 是否适合投资、结婚、就医、辞职等重大决策。

## 14. 下一阶段：M9-16

下一阶段建议开发“流月、流日显隐重复、透干通根与藏干触达条件审计”。它将在 M9-15 已完成的精确日期五层节点上复用 M9-9 至 M9-11 的规则，回答流月、流日加入后哪些十神角色只是藏而未显、哪些形成表层重复、哪些具备透干或通根证据、哪些藏干被动态层结构触达。仍然只给条件证据，不计算吉凶、力量分数或具体事件。
