# 观辰 v2.0.0 冻结前完整开发规划

基准日期：2026-10-18。本文是执行级工作分解；发布门槛与版本策略见 [v2.0.0 版本固化规划](./V2_RELEASE_PLAN.md)。

> 执行顺序与阶段门以 [V2_PHASE_PLAN.md](./V2_PHASE_PLAN.md) 为准；本文工程日与周计划仅作工作量参考，不构成工期承诺。

## 0. 定位与假设

- 本文回答“从现在到 v2.0 冻结，还需要开发/补齐什么”，不是新一轮术数理论开发。
- 假设 1 名主开发 + AI 执行代码、测试、文档；真机、部署主机、真实模型预算、GitHub 推送需要人工决策。
- 工程日按“含自测、文档、评审”计；AI 可压缩编码时间，但不压缩真实设备、部署演练、模型审阅和人工判断。
- **承诺目标：2026-12-27 发布 `v2.0.0`。冲刺目标：2026-12-13（仅在外部资源全部就绪且砍掉 P1 时成立）。**

## 1. 现状：已经完成什么

| 项目 | 现状 |
| --- | --- |

| 账号 | 注册、登录、改密、管理员、账号隔离、登录限额 |

| 最新规则层 | 八字司令分日、月令取用入口 |
| 未完成 | 发布工程、正式部署、真机/浏览器验收、真实模型审阅、迁移/恢复演练、文档收口 |

**结论：不需要再开发新的命理模块；需要把已有能力收口成可交付产品。**

## 2. 冻结前不做的事

- 不新增规则层（五合去留、六爻三合墓绝、奇门暗干、梅花外应全部放 v2.1）。
- 不做大重构（`BaziWorkspace` 1787 行、`db/client.ts` 2680 行暂不拆）。
- 不换数据库、不引入 Redis/队列、不做多实例。
- 不做支付、会员、人物档案中心、Android。
- 不做 UI 全面改版，只修一致性、空/错状态和移动端问题。
- 不为“数字好看”删测试或改写历史验收记录。

## 3. 发布阻断与可延后

### P0：不完成不能发

数据丢失、跨账号泄漏、鉴权绕过、迁移/恢复失败、干净机器部署失败、核心链路不可用、密钥泄漏、破坏性回退。

### P1：应完成，资源不足时可带已知限制发布

CI、健康检查、定时备份、axe、空/错状态、账号找回兜底、AI 配额、性能基线。

### P2：可放 v2.1

文案统一、截图更新、大组件拆分、冷门规则、性能微调、设计系统。
