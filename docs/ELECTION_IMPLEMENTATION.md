# 择日工具实施记录

开发日期：2026-10-12（UTC+08:00）。第五模块第一版，属于 `1.1.0-dev`。入口 `/election`，首页和工作台“命理工具”均可进入。

## 功能流程

选择婚嫁、搬家入宅、开业、出行、修造装修、签约立券、祭祀七种事项及公历日期区间，可选可用星期、需要避开的日冲生肖。筛选以传统黄历的实际事项词为准，不把相近事项混在一起：婚嫁对应嫁娶，入宅不自动等同移徙，签约立券不直接等同所有交易。

支持 1900-01-01 至 2100-12-31，单次最多含首尾 92 天。浏览结果不保存档案；用户选择后可显式保存，最多对照三个日期，也可以只选一个或暂不选择。方案保存原始筛选条件、完整逐日黄历依据、分类、所选日期与备注。刷新和重新登录按保存时口径回看，修改备注或对照日期不重新计算旧结果。重新筛选从原条件建立新方案，避免覆盖原快照。

方案列表提供名称查询、回看、移除确认和取消。候选日期、全部日期、日期对照三种视图分别展示结果；日期对照可核对各自宜忌、月界、冲煞与排除条件。

## 黄历口径与来源

第一版复用已安装 `lunar-javascript 1.7.3` 的黄历数据，不自行补写“吉日”规则，不需要 AI。原库 `getDayYi/getDayJi` 的 sect=1 使用按交节日期更新的月干支，sect=2 使用精确交节时刻的月干支。依据已核对 [固定版本源码](https://github.com/6tail/lunar-javascript/blob/v1.7.3/lunar.js) 的 `_computeMonth`、`getMonthInGanZhi`、`getMonthInGanZhiExact`、`getDayYi`、`getDayJi`。

默认同时对照两种口径，也可以明确选择其中一种。两者来自同一库，不是两套独立流派互证。所有日期使用北京时间标准时 UTC+08:00；精确口径以当天 12:00 为代表时刻，同时检查 00:00 与 23:59:59 的月干支。若月干支日内切换且选择了精确口径，该日期保留为“待核”，展示交节前后月干支，不能以午间宜忌判定全天适用。

建除值星与黄道/黑道日标签继续按照原库的交节日期口径展示，作为参考字段，不擅自改成精确月界，也不直接决定候选。公历星期计算使用 UTC 日历字段，避免访问设备或服务进程时区改变日期。

## 分类与取舍

- 候选：所有所选黄历口径明确列宜、未列该事项为忌，符合所选星期与日冲排除条件，精确口径没有日内交节待核。
- 待核：黄历口径事项记录不同，或所用精确口径日内换月；保留各自依据。
- 事项忌：稳定月界下，所选口径有该事项忌项或“诸事不宜”；宜忌都出现同一事项时保留冲突并谨慎处理。
- 未列明：没有明确事项依据；未列为忌不等于适宜，“诸事不忌”也不自动成为全部事项的支持。
- 条件排除：命中用户设置的不可用星期或日冲生肖条件，仍可展开黄历并与其他日期对照。

结果按公历日期先后展示，不计算吉凶分数、成功概率或未经校核的最佳日期。日冲生肖只按用户所选条件排除，不自动从出生年份推定生肖，也不替代个人八字、双方命盘的完整生辰合忌。

## 数据与安全

业务库升级至 v52，新增独立表 `election_plans`。所有接口经过统一账号验证与同源写入检查。预览无持久化写入，保存时服务端重新计算，忽略客户端伪造的结果或账号字段。重复规范请求幂等，更新只开放名称、备注与对照日期；修改筛选条件需要新建方案。名称限 80 字，备注限 1000 字，日期及数组有范围约束，错误信息不包含内部数据库细节。

整库备份包含独立方案，单紫微命盘包明确不包括择日资料。旧备份仍按严格数据库版本匹配策略，先在对应版本还原后升级，不能直接作为 v52 包导入。新增表不改变原有命盘或合参的关系。

## 第一版边界

这是黄历事项择日第一版，尚未实现吉时、真太阳时、完整八字喜忌匹配、三合等专门择日规则。候选仅表示符合已开放的传统规则及所选条件，不保证事件结果；实际日期仍要结合现实安排核对。专业规则应逐项校核后扩展，不能把两个黄历参数包装成完整流派覆盖。

专项测试使用独立临时账号与合成方案，主动禁止外呼，验证本模块不依赖 AI；覆盖七事项三口径、交节日、春节、闰月、世纪闰年、公历跨年、时区稳定、筛选逻辑、边界输入、保存修改、快照、事务、账号隔离、整库备份恢复及 v51 升级。
