# M9-17 八字流月流日旺衰综合证据矩阵实施说明

## 1. 阶段结论

M9-17 已把指定流日的旺衰相关证据整理成按精确片段审计的三层方向矩阵：

1. 大运、流年已经存在的表层方向；
2. 流月、流日新增的表层方向；
3. 四个动态层合并后的表层方向。

静态基线继续原样引用 M9-3 的证据标签。M9-16 的流月流日藏干位置、日主根气、月令触达和其他藏干触达被单列为条件上下文，完全不参与方向计算。

系统只输出生扶、泄耗制、同向、异向、并见和证据来源，不计算最终旺衰分数，不宣告日主变强、变弱、抵消或反转，也不推断吉凶和具体事件。

## 2. 为什么要拆成三层方向

如果直接把大运、流年、流月和流日的所有证据放在一起，用户无法判断某个方向原本就存在，还是由当天的流月、流日新增。更严重的是，藏干、根气候选和触达入口容易被误当成已经生效的力量。

因此本阶段使用以下结构：

```text
M9-3 静态基线（保留原标签，不重判）
  ├─ M9-15 大运／流年可见表层 → 既有方向
  ├─ M9-15 流月／流日可见表层 → 新增方向
  ├─ 两组可见表层合并          → 五层表层方向
  └─ M9-16 藏干／根气／触达    → 条件上下文，不参与方向
```

这种拆分可以回答“流月流日与既有岁运在表层证据上是否同向”，但不会把方向比较偷换成实际力量变化。

## 3. 上游证据与职责

### 3.1 M9-3 静态基线

复用内容：

- 静态旺衰证据标签；
- 月令证据、原局表层和实际藏干根气的既有方向；
- 置信度和未知时辰边界。

M9-17 不按指定日期重新计算或覆盖静态标签，也不对 M9-3 证据重新设置权重。

### 3.2 M9-15 五层关系与十神角色

只有 `surface_stem` 表层角色可以进入方向列：

- 比肩、劫财、正印、偏印归入生扶方向；
- 食神、伤官、正财、偏财、正官、七杀归入泄耗制方向。

大运和流年进入“既有方向”，流月和流日进入“新增方向”。每个表层角色只保留分类，不设置数量权重。

### 3.3 M9-16 显隐、透根与触达

以下证据全部进入条件上下文：

- 流月、流日地支内的藏干位置；
- 日主严格同干根候选与同五行支持参照；
- 月令藏干命中的触达入口；
- 其他藏干命中的同干表层、同支重复或明确关系触达入口。

即使某项条件命中多类入口，也不能进入生扶或泄耗制方向列。

## 4. 方向与比较规则

每组表层证据使用同一套无权重分类：

| 表层证据状态 | 方向标签 |
| --- | --- |
| 只出现生扶类十神 | 只见生扶方向 |
| 只出现泄耗制类十神 | 只见泄耗制方向 |
| 两类同时出现 | 生扶与泄耗制方向并见 |
| 没有可见表层角色 | 表层方向缺失 |

流月流日新增方向与既有岁运方向比较后，只允许得到：

- 同向；
- 异向；
- 流月流日两类方向并见；
- 既有岁运两类方向并见；
- 某一组方向缺失；
- 时柱未知，比较证据不完整。

五层表层合并方向再与 M9-3 静态标签比较，继续沿用 M9-12 的“同向、异向、并见、缺失或不完整”语义。

“同向”只表示分类一致，不表示增强；“异向”只表示分类不同，不表示抵消、压过或反转。

## 5. 精确片段隔离

M9-17 严格复用 M9-15、M9-16 的片段编号和前闭后开时间边界。

例如一个流日在 `06:51:00` 交入新大运：

- `00:00:00` 至 `06:51:00` 前的既有方向只能读取流年表层；
- `06:51:00` 至次日 `00:00:00` 前才允许读取新大运与流年表层；
- 流月、流日表层虽然可能相同，也分别在两个片段中独立留证；
- 前一片段的根气和触达条件不能累计到后一片段。

如果 M9-15 与 M9-16 的日期、年份、片段起止或五层快照不一致，引擎直接拒绝合成，避免错配版本。

## 6. 输出结构

每个精确片段包含：

- 流年、大运、流月和流日干支；
- 大运／流年既有表层方向及逐项证据；
- 流月／流日新增表层方向及逐项证据；
- 五层表层合并方向；
- 新增与既有方向比较；
- 五层表层与静态基线比较；
- 流月流日藏干位置；
- 日主根气条件；
- 月令触达和其他藏干触达上下文；
- 支持、泄耗制、上下文、位置和条件证据数量。

数量只用于界面概览和审计，不形成分数、百分比、净值或权重。

## 7. 数据持久化

SQLite 升级到 v39，新增 `bazi_month_day_strength_versions`。

每个结果同时绑定：

- 不可变八字命盘版本和指纹；
- M9-3 解释证据版本和指纹；
- M9-15 指定日期五层关系版本和指纹；
- M9-16 指定日期显隐条件版本和指纹；
- 目标日期、方法版本和引擎版本；
- M9-17 结果 JSON 与 SHA-256 指纹。

唯一键覆盖四类上游版本、日期和本阶段方法版本。相同输入重复生成时复用旧结果；任何上游版本变化都会生成新的可追溯版本。

`bazi_conversations.month_day_strength_version_id` 保存会话默认日期的 M9-17 版本。打开旧会话时会幂等补齐，并同步升级提示词版本。

## 8. API

新增接口：

- `POST /api/bazi/charts/:id/month-day-strength`：按 `targetDate` 生成或复用证据矩阵；
- `GET /api/bazi/charts/:id/month-day-strength?date=2030-12-12`：读取指定日期最新版本及缓存列表。

服务端按顺序确保 M9-3、M9-15、M9-16 版本存在，并校验 M9-16 确实绑定同一个 M9-15 版本。

## 9. 工作台交互

工作台在 M9-16 面板后增加 M9-17 面板：

- 顶部显示指定日期、静态基线与精确片段数；
- 每个片段使用三张卡并列展示既有、新增和合并方向；
- 两组表层角色逐项标注生扶或泄耗制；
- 条件上下文默认折叠，避免和方向证据混淆；
- 页面明确提示“同向不等于增强，异向不等于抵消或反转”；
- 已保存命盘切换流日后自动按日期持久化。

聊天侧栏同步展示 M9-17 版本和比较口径，并增加三个快捷问题，引导用户按片段、按证据组提问。

## 10. AI 上下文与输出守卫

提示词升级为 `bazi-chat-month-day-strength-v16`。

问题包含明确日期或“今天／今日”时，上下文按一致版本链注入：

1. M9-14 精确时间轴；
2. M9-15 五层关系与十神角色；
3. M9-16 显隐、透根与触达条件；
4. M9-17 三层方向综合矩阵。

上下文清单新增：

- `monthDayStrengthVersionId`；
- `monthDayStrengthFingerprint`；
- `monthDayStrengthTargetDate`。

允许能力新增 `month_day_strength_composite_audit`，禁止能力新增 `month_day_final_strength_verdict`。

输出守卫会拦截把流月、流日或五层表层的同向、异向、生扶、泄耗制、根气和触达改写为日主变强、变弱、转强、转弱、旺衰反转、抵消、压过或评分的回答。

## 11. 降级规则

- 时辰未知：保留三柱和动态层证据，所有比较标记为不完整；
- 非支持时区：上游没有精确片段时返回 `sequence_only_unavailable`，不伪造方向；
- 未交首运：既有方向只有流年表层，不补写大运；
- 日期越界：沿用 M9-15 的明确错误；
- 没有条件证据：显示空状态，不由 AI 补写；
- 上游片段错配：拒绝生成，不静默合并。

## 12. 测试覆盖

专项测试 `test:bazi-month-day-strength` 覆盖：

- 方法契约和禁止结论；
- 交运日前后双片段边界；
- 交运前只有流年表层，交运后才加入大运表层；
- 每个片段恰有流月、流日两个新增表层角色；
- 既有、新增、合并方向只从对应表层证据计算；
- 藏干、根气与触达始终为 `context`，不能进入方向；
- 静态标签原样继承 M9-3；
- 未知时辰与非支持时区降级；
- SQLite v39 迁移、四上游版本指纹和同日幂等复用；
- API、会话默认绑定、明确日期动态路由；
- 上下文快照、允许／禁止能力和越权输出守卫。

全量回归继续覆盖 M9-0 至 M9-16，确认 M9-12 导出的公共方向函数没有改变年度矩阵结果。

## 13. 当前仍不能回答的问题

M9-17 完成后仍不能自动回答：

- 某日最终是身强还是身弱；
- 流月流日使日主增强或减弱多少；
- 某个方向是否抵消、压过或反转另一个方向；
- 根气候选是否为强根、真根或实际有效；
- 藏干触达后是否已经发动；
- 格局在某日是否成立、受损或完成救应；
- 最终用神、喜神或忌神；
- 某日事业、感情、健康、财富等吉凶事件。

## 14. 下一阶段：M9-18

下一阶段建议开发“流月流日格局条件映射”。它将复用 M9-13 已版本化的成格支持、破格风险和救应候选规则，并要求每项新增证据必须来自当前 M9-15／M9-16 精确片段。

M9-18 应把静态格局条件、岁运既有条件和流月流日新增条件分开，仍然只输出条件命中、缺失、并见和来源，不宣告某日成格、破格、救应完成、格局高低、吉凶或具体事件。
