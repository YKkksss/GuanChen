# 动态紫微八字合参实施记录

本文保留初版观察点阶段的实施与验收；后续主题四化与跨层结构复核见 [动态合参深化记录](./SYNTHESIS_DYNAMIC_REVIEW_IMPLEMENTATION.md)，旧阶段仍按原版本回看。

本阶段承接奇门条件复核，入口为 `/synthesis` 已建立双盘内的“动态阶段”。它按同一个北京时间观察点，对照紫微大限、流年与流月，以及八字大运、流年与节令月；原本命合参与旧报告继续独立使用。

## 使用方式

选择综合、事业、感情、财运或学习主题，填写观察日期及准确时分秒，选择流年或流月层级并应用。流年层级包含两侧运限和流年；流月层级再加入两侧流月。这里的年、月是观察层级，不表示整个年度或月份只有同一状态。

浏览、切换和保存阶段依据不调用AI。已保存阶段可跨主题回看；按需生成的五章解读包括两侧独立视角、共同观察、不同观点与待核条件、行动与复核建议。每章必须引用对应阶段的实际依据。重新生成保留旧版本，切换阶段或主题不会混用报告。

重新进入动态阶段时优先打开当前主题最近保存的阶段；该主题尚未保存时，以最近历史的观察点作新主题预览。历史下拉可明确切回其他主题及其保存阶段。

## 固定口径与边界

- 观察时刻使用固定UTC+08:00文本，不依赖设备时区，也不再次叠加出生地真太阳时修正。输入补齐秒，拒绝非法日期、带偏移时刻及出生前、超范围观察。
- 紫微流年在真实观察日定位，保留农历年、虚岁、大限或童限。流月新增专用观察日入口，保留所属农历月和iztro的闰月后半月行为；原有农历初一缓存入口不改变。
- 八字流年以精确立春交接，流月以十二节交接，区间前闭后开。不能以春节或农历初一替代节界，也不强求两套体系的年、月标签一致。
- 八字大运复用原分钟折算、顺逆及八步十年排期。首运前单独提示；未知时辰、太阳时四柱与民用排期冲突时撤回精确归属；第八步以后不补造第九步或循环套用。
- 大运、流年和流月的表干及支中藏干十神均以本命日主为参照。仅展示角色位置，不据此裁定喜忌、强弱、引动或具体事件。
- 出生时间未知时，紫微保留子时试排，八字不补时柱；出生当日的观察点不能假装已经确认在出生之后。
- 观察范围取原始出生瞬间与紫微有效出生日期的较晚者，至出生公历年加130年末、最大2200年。紫微与八字各自超出已排运限时保留不可用状态，历法定位不表示有完整运限能力。

固定阶段版本为 `synthesis-dynamic-v1-fixed-utc8-observation`。紫微复用项目的iztro运限映射；八字年月复用lunar-javascript精确节气及干支，大运复用既有排期引擎。合参出生资料固定为 `Etc/GMT-8`，而旧排期器的能力标签只列 `Asia/Shanghai`；适配层只复制图表并修改传给纯墙钟排期器的支持标签，不执行IANA历史偏移或夏令时换算，不改写本命快照。此适配不扩展为任意时区支持。

## 保存、兼容与安全

数据库仍为v56。复用合参版本表，在事实JSON内加入可选动态阶段及版本键，不变更本命出生资料，也不迁移或重算旧报告。本命版本与动态阶段通过阶段键分开查询；每个主题的版本编号继续累计，所以同一阶段列表可能出现不连续编号。

无需AI的阶段快照存为已完成但正文为空的事实版本，界面明确区分“依据已保存”和“AI解读已完成”。读取已保存阶段优先使用固定事实；报告正文和引用使用各自版本的事实。相同依据保存可复用；不同主题、时间和层级分开。

同主题同时只允许一个生成任务，其他阶段生成请求返回409；过期任务可恢复，迟到及错误任务标识不能发布。失败脱敏并保留旧版，重复读取或同依据生成复用不再次调用供应商。AI只能解释已计算的动态层级，每节必须有相应 `ziwei:dynamic:` 或 `bazi:dynamic:` 引用，本命依据不能代替阶段依据。

新接口为 `/api/synthesis/[id]/dynamic`，沿用账号隔离、同源写入校验和私有不缓存响应。服务端只从当前账号的双盘资料计算，忽略客户端伪造事实。快照随整库备份与恢复保留，删除合参或关联底层盘沿用原级联语义；单紫微命盘包仍不包含独立八字与合参关系。

历史入口携带保存时的完整阶段键，服务端在当前账号、会话和主题下查找。即使阶段规则版本不同，仍返回旧事实及旧报告；键不存在或主题不匹配拒绝读取，不能用客户端事实伪造旧版本。新观察不携带旧键，继续采用当前规则版本。
