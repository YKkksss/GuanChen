# M9-13 八字格局成败、破格与救应条件证据审计实施说明

## 1. 阶段目标

M9-13 在 M9-3 月令格局候选之上建立可追溯的三层条件矩阵：

1. 成格支持条件：当前原局中有哪些角色或结构能够支持某条格局路径。
2. 破格风险条件：当前原局中有哪些冲突、缺项或并见结构需要复核。
3. 救应候选：针对已经观察到或尚未排除的风险，原局中有哪些制化、五合或会合入口值得继续核对。

本阶段仍不输出“已经成格”“已经破格”“救应完成”、格局高低、富贵贫贱、最终用神或吉凶事件。

方法版本：`bazi-pattern-condition-audit-v1`

引擎版本：`bazi-pattern-condition-engine-v1`

数据库迁移：SQLite v35

会话提示词版本：`bazi-chat-pattern-condition-v12`

## 2. 为什么采用条件矩阵

格局成败不是单一十神出现即可确定。传统文本本身反复讨论：

- 同一候选可能同时存在支持条件和风险条件。
- 风险出现后还要继续寻找制化或救应。
- 财、官、印、食、煞、伤、劫、刃的条件结构不同。
- 天干位置、藏干、月支刑冲会合和身用承载不能混成一个分数。

因此项目没有实现“格局成功率”，而是把证据拆开，让用户和后续人工规则能够定位每一个条件的来源与未决项。

## 3. 方法来源与使用边界

### 3.1 《子平真诠评注》

参考：<https://ctext.org/wiki.pl?chapter=974137&if=gb>

“论用神成败救应”集中列举官、财、印、食、煞、伤、阳刃、建禄月劫的成、败和救应例式。项目只提取这些例式的条件骨架，转写为可验证的角色和结构条件，不继承古籍中的富贵吉凶判断。

### 3.2 《三命通会》卷五

参考：<https://zh.wikisource.org/wiki/%E4%B8%89%E5%91%BD%E9%80%9A%E6%9C%83/%E5%8D%B7%E4%BA%94>

用于核对财、官、印、食及生克制化的基本纲领。项目仍以自身版本化规则表为唯一程序入口，AI 不得脱离快照继续补算。

### 3.3 项目上游证据

- M9-3：提供月令格局候选、来源藏干、气级、透出位置、月支结构关系和候选复核状态。
- M9-12：只提供静态旺衰证据标签，作为“身用承载仍待复核”的上下文。
- M9-13：重新扫描原局表层天干和实际藏干，但不重新排盘、不重算旺衰，也不消费大运流年。

## 5. 证据分层

### 5.1 表层天干

年、月、时天干相对日主的十神角色。日主天干只作为参照，不重复计为比肩条件。

需要“透出”的规则优先要求表层证据。

### 5.2 实际藏干

四支实际藏干按本气、中气、余气逐项保存。藏干中的角色只能说明“原局内部存在这个角色位置”。

如果某项规则要求表层，而当前只有藏干：

- 状态为“已见入口，需人工复核”。
- 页面显示“仅藏未透”。
- 不得改写成表层条件已经齐备。

### 5.3 月支结构

只消费 M9-3 已检测的月支六冲、六合、三合或三会结构。

- 关系出现：记录为风险或救应入口。
- 会合并见：仍然只是位置条件。
- 不裁决解冲、合去、合化或关系优先级。

### 5.4 M9-12 静态上下文

每个候选都会附带 M9-12 静态旺衰标签，但统一标记“需人工复核”。原因是传统格局条件经常涉及身与用的承载关系，而 M9-12 明确没有输出最终身强身弱。

## 6. 条件状态

| 状态 | 含义 |
| --- | --- |
| `evidence_present` | 当前原局观察到该项开放证据 |
| `not_observed` | 完整四柱中当前未观察到该项开放证据 |
| `requires_manual_review` | 观察到藏干、五合或其他入口，但规则效果仍未裁决 |
| `unknown_due_to_missing_time` | 时柱未知，无法把当前未见当作完整缺失 |
| `not_applicable` | 对应破格风险未观察到，救应项暂不展开 |

这些状态描述的是“规则检查状态”，不是格局结论。

## 7. 救应与风险的链接

每一项救应候选保存 `linkedBreakingRuleIds`，明确说明它针对哪类风险：

- 正官见伤官风险 → 印星制伤候选。
- 正官混杀风险 → 合杀留官候选。
- 财格比劫风险 → 食伤化劫生财或生官制劫候选。
- 财格露杀风险 → 食神制杀或合杀存财候选。
- 印逢财风险 → 比劫解财或合财存印候选。
- 食神逢枭风险 → 财星护食或就杀路径候选。
- 七杀食制与印星并见风险 → 财星去印存食候选。
- 建禄月劫用官逢伤 → 合伤存官候选。
- 建禄月劫用财带杀 → 合杀存财候选。

只有关联风险已经观察到、需要人工复核或因缺时保持未知时，对应救应才会展开；否则显示“不适用”。

## 8. 五合位置条件

引擎检查甲己、乙庚、丙辛、丁壬、戊癸五组天干组合。

即使检测到相合天干，也只输出：

- 哪个风险角色天干参与五合。
- 与哪一柱天干形成相合位置。
- 该条件仍需人工复核。

不会输出“已经合去”“已经化气”“救应完成”。

## 9. 阳刃路径边界

首版只开放阳日主的常用刃位：

- 甲见卯。
- 丙见午。
- 戊见午。
- 庚见酉。
- 壬见子。

同时必须满足：

- M9-3 月令本气候选为劫财。
- 月支与日主命中上述刃位。

不符合此条件的劫财候选继续进入月劫路径。阴日刃位和流派差异暂不自动裁决。

## 10. 未知时辰降级

当时柱未知：

- 已经观察到的角色和结构仍可记录。
- 所有依赖“未见某角色”的条件改为 `unknown_due_to_missing_time`。
- 不允许把三柱未见直接写成四柱缺失。
- 候选附加 `unknown_time` 复核标记。

## 11. 数据库设计

SQLite v35 新增：

### 11.1 `bazi_pattern_condition_versions`

保存：

- 命盘版本、M9-3 分析版本、M9-12 综合版本。
- 三个上游指纹。
- M9-13 方法版本和引擎版本。
- 格局条件结果 JSON。
- 格局条件结果指纹。

相同上游版本、方法版本和引擎版本只生成一个结果，重复请求直接复用。

### 11.2 `bazi_conversations.pattern_condition_version_id`

八字会话固定引用一份格局条件版本。旧会话读取时会自动补齐 v35 结果并升级到提示词 v12。

## 12. API

新增：

`GET /api/bazi/charts/:id/pattern-conditions`

- 返回当前命盘最新格局条件版本和历史版本。

`POST /api/bazi/charts/:id/pattern-conditions`

- 生成或复用当前上游版本对应的 M9-13 结果。

## 13. 排盘工作台

工作台新增“M9-13 格局条件证据审计”面板：

- 一个 M9-3 候选对应一张卡片。
- 每张卡片分为成格支持、破格风险、救应候选三列。
- 显示证据状态、来源位置和复核标记。
- 显示支持、风险和救应的观察计数，但不形成总分。
- 无候选时展示明确空状态。

## 14. AI 上下文与守卫

AI 上下文新增格局条件权威快照：

- 固定候选来源和上游状态。
- 固定每项检查状态和证据位置。
- 固定救应与风险链接。
- 固定阶段边界。

新增允许能力：

- `pattern_condition_evidence_audit`

新增禁止能力：

- `pattern_success_failure`
- `pattern_rank_or_fortune`
- `pattern_rescue_completion_verdict`

输出守卫新增：

- 越权宣告格局成败或救应完成。
- 越权生成格局分数、成功率或富贵层次。

## 16. 当前不能回答的问题

M9-13 完成后仍不能自动回答：

- 这个命局最终到底是什么格。
- 某候选是否已经成格或已经破格。
- 某个五合是否真正合去某神。
- 救应是否真正完成。
- 格局层次、清浊、纯杂、富贵贫贱。
- 最终用神、喜神、忌神。
- 大运流年是否使格局成功或失败。
- 具体事业、财富、婚姻、健康和事件吉凶。
