# M7-0 匿名案例库基础与脱敏入库实施文档

## 1. 阶段目标

M7-0 建立案例库最重要的数据治理边界，而不是先追求案例数量。本阶段解决四个问题：

1. 本地已有命盘如何转换成不含直接身份信息的案例快照。
2. 用户如何在保存前看清哪些字段被移除、概括或保留。
3. 本地保存、教学使用和匿名导出如何分别授权并随时撤销。
4. 导出数据如何保证不携带来源会话、聊天正文和精确出生资料。

本阶段不包含在线上传、公开发布、社区分享和跨设备同步。

## 2. 产品流程

```text
选择已保存单人命盘
  → 服务端重新读取命盘和已确认事件
  → 生成只读脱敏预览（不写数据库）
  → 用户检查移除/概括/保留字段
  → 用户选择本地教学或匿名导出用途
  → 明确勾选“已查看预览”
  → 服务端再次生成脱敏快照
  → 写入本地匿名案例库
  → 待复核
  → 复核通过后才允许匿名导出
```

创建接口不接受客户端提交的命盘快照。客户端只能提交来源会话编号、匿名标题、可信度、授权范围和确认状态，服务端会从本地数据库重新生成匿名快照，防止客户端绕过脱敏规则。

## 3. 脱敏策略

### 3.1 完全移除

- 姓名和原始会话标题。
- 公历出生年、月、日和时辰原值。
- 农历出生日期、年干支原值。
- 省、市、精确地点和经度。
- 全部聊天消息、滚动摘要、关键记忆和上下文运行记录。
- 人生事件标题、描述、自定义类别文字和来源消息编号。
- 人生事件精确日期。

### 3.2 概括保留

- 当前年龄只保存为十岁年龄段，例如“30-39岁”。
- 已确认人生事件只保存标准类别、事件发生时的十岁年龄段、概括后的时间精度和影响级别。
- 日、月精度统一降为年精度；跨年事件只保留“范围”标记。
- 出生时辰只保留“已知/未知”的可信状态，不保存原始时辰数字。

### 3.3 结构保留

- 命宫、身宫和五行局。
- 十二宫地支、宫干和宫名。
- 星曜名称、类型、亮度和四化。
- 宫干自化、空宫及借对宫结构。
- 大限年龄段、所在宫位和大限四化。

这些字段用于后续案例检索、教学讲解和命盘对比。匿名快照使用独立的 `AnonymousCaseChartSnapshot` 类型，不复用包含 `birthInfo` 的 `ZiweiChart`，从类型层阻止精确出生资料被意外序列化。

## 4. 授权模型

授权按用途拆分：

| 授权范围 | M7-0 行为 |
|---|---|
| `local_only` | 必选；案例存在的基础，不能单独撤销，只能删除整个案例 |
| `teaching` | 可选；允许后续本地教学和案例练习使用 |
| `anonymous_export` | 可选；仅表示允许导出，仍需案例已复核 |
| `public_release` | 数据结构预留，但 M7-0 服务端明确拒绝启用 |

授权采用独立记录，保存授权版本、确认时间、撤销时间和当前状态。撤销 `anonymous_export` 后，导出接口立即拒绝请求。

## 5. 数据库迁移 v18

### 5.1 `case_records`

保存匿名案例编号、匿名标题、复核状态、可信度、匿名命盘快照、脱敏版本和本地来源会话引用。来源会话删除时引用自动设为 `NULL`，匿名案例继续存在。

### 5.2 `case_sources`

记录案例来源类型、引用说明、备注和来源可靠性。当前本地命盘创建流程写入安全的固定说明，不复制来源会话标题。

### 5.3 `case_consents`

分别保存每种授权范围的有效或撤销状态，并使用 `(case_id, scope)` 唯一约束防止重复授权记录。

### 5.4 `case_event_snapshots`

只保存已确认事件的标准类别、年龄段、概括时间精度、影响级别和安全来源类型。

### 5.5 `case_audit_logs`

记录创建、更新、授权、撤销和导出行为。审计元数据只保存用途、版本和数量，不保存原始命盘或事件正文。

## 6. 页面与接口

### 6.1 页面

- `/cases`：案例列表、状态筛选和用途标签。
- `/cases/new`：选择命盘、脱敏预览、用途授权和明确确认。
- `/cases/[caseId]`：匿名结构、概括事件、状态管理、授权管理、审计记录和导出。

### 6.2 接口

- `POST /api/cases/preview`：生成只读脱敏预览，不写数据库。
- `GET /api/cases`：按复核状态列出案例。
- `POST /api/cases`：明确确认后从服务端来源重新生成并保存案例。
- `GET/PATCH/DELETE /api/cases/[id]`：读取、管理和按案例编号二次确认删除。
- `PATCH /api/cases/[id]/consent`：授予或撤销单项用途。
- `GET /api/cases/[id]/export`：执行复核状态和导出授权双重检查后生成 JSON。

## 7. 导出安全边界

匿名 JSON 导出只包含：

- 匿名案例编号和匿名标题。
- 可信度、脱敏版本和导出格式版本。
- 匿名命盘结构。
- 安全的来源说明。
- 概括事件。
- 匿名导出授权版本和确认时间。

导出明确排除：

- 本地来源会话编号。
- 姓名、地点、经度和精确出生日期。
- 聊天消息、摘要、记忆和模型运行信息。
- 事件标题、描述和精确日期。
- 本地数据库主键和审计日志。

匿名标题还会检查是否直接包含来源命盘姓名或类似精确日期，发现后拒绝创建。

## 8. 测试覆盖

`npm run test:cases` 使用独立临时 SQLite 文件验证：

- SQLite v18 迁移。
- 只有用户已确认事件进入预览。
- 姓名、精确日期、地点、经度、联系方式和事件正文不会出现在预览或导出 JSON。
- 未查看预览不能创建案例。
- 匿名标题不能复制来源姓名或精确日期。
- 草稿不能导出。
- 没有有效匿名导出授权不能导出。
- 撤销授权立即阻止导出。
- 本地保存授权不能单独撤销。
- M7-0 不能启用公开发布授权。
- 删除来源命盘后，匿名案例保留且来源引用置空。
- 删除案例需要提交匹配的案例编号。

## 9. 已知边界

1. 本阶段是“字段最小化”的工程匿名化，不承诺对极少见命盘结构实现数学意义上的不可重识别。
2. 匿名标题只能阻止明显姓名和日期，无法自动判断所有间接身份线索，因此复核仍是必要步骤。
3. 当前案例只来源于单人命盘；合盘具有双方授权问题，后续需要单独设计。
4. `public_release` 仅为未来迁移预留，当前没有网络发布入口。
5. 事件只按十岁年龄段保留，适合教学聚类，不适合作为精确年份验证数据。

## 10. 下一阶段 M7-1

M7-1 在本基础上实现：

- 按命宫、主星、四化、格局、五行局和事件类别筛选。
- 案例全文与结构化条件组合检索。
- 案例教学详情和来源说明。
- 只让具有有效 `teaching` 授权的本地用户案例进入教学结果。
- 搜索结果持续显示案例编号、可信度、复核状态和脱敏版本。

M7-1 不应改变 M7-0 的授权语义；检索层只能消费已脱敏数据，不能回读原始聊天正文补充案例。
