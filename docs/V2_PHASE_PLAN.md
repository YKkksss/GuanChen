# 观辰 v2.0.0 冻结前阶段规划（无时间表）

> 本文只定义阶段、工作项、产出物与出口条件，不设日期、不估工期。阶段按“出口条件”推进，不按日历推进。
>
> 发布门槛见 [V2_RELEASE_PLAN.md](./V2_RELEASE_PLAN.md)；任务清单见 [V2_DEVELOPMENT_BACKLOG.md](./V2_DEVELOPMENT_BACKLOG.md)。两份文档中的日期/工程日仅作历史参考，执行顺序以本文阶段门为准。

## 0. 原则

1. **范围锁定优先于进度**：v2.0 范围一旦锁定，只接受 P0/P1 修复，不接受新规则层。
2. **每阶段有硬出口**：未通过出口条件，不进入下一阶段；不靠“差不多”推进。
3. **允许并行的只有独立阶段**：P2 数据/部署与 P3 安全可并行；P4 质量与 P5 AI 可在 staging 可用后并行。
4. **发现 P0 缺陷立即回退修复**：数据丢失、跨账号泄漏、鉴权绕过、迁移/恢复失败、干净部署失败、密钥泄漏。
5. **阶段产出必须留证据**：日志、JSON、截图、runbook、验收记录，不能只写“已通过”。

## 1. 阶段总览

| 阶段 | 名称 | 目标 | 出口门 |
| --- | --- | --- | --- |
| P0 | 范围锁定与仓库收口 | 把“开发态工作区”变成可复现的 release 分支 | G0 范围与仓库 |
| P1 | 发布工程 | 让每次变更可构建、可观测、可自检 | G1 构建与可观测 |
| P2 | 数据与部署 | 证明能装、能迁、能备、能恢复、能回滚 | G2 数据与部署 |
| P3 | 安全与账号收口 | 证明账号隔离与生产边界成立 | G3 安全 |
| P4 | 质量与体验 | 证明桌面、窄屏、真机核心链路可用 | G4 质量 |
| P5 | 真实模型与内容 | 证明真实供应商下报告/问答不越界、成本可知 | G5 AI |
| P6 | 文档、RC 与冻结 | 形成可发布候选并完成观察 | G6 发布 |
| P7 | 发布后观察 | 稳定运行与 v2.1 交接 | G7 运营 |

**功能冻结：P3 出口。代码冻结：P6 的 RC 观察开始后。正式发布：P6 出口。**

## 2. 各阶段详述

### P0 范围锁定与仓库收口

**目标**：先把“到底发什么”和“源码在哪里”定死。

工作项：

- 锁定 v2.0 范围（包含/不包含清单），确认五合去留放 v2.1。
- 盘点全部工作区变更：源码、测试、文档、构建产物、私密数据五类分离。
- 清理不应入库的 `.next-*`、日志、临时文件、真实数据库、备份、`.env.local`。
- 新建 `release/2.0` 分支；打 `v2.0.0-alpha.1`；建 GitHub milestone 与 P0/P1/P2 标签。
- 分批提交：账号、各术数模块、报告/PDF、备份、测试、文档分开，便于回溯。
- 写模块验收矩阵：每个模块的入口、主流程、空/错状态、权限边界、文档、专项测试。
- 更新 CHANGELOG 与发布说明骨架。

产出物：

- `docs/V2_SCOPE.md`（或 release plan 的范围节）
- `docs/WORKSPACE_TRIAGE.md`
- `docs/V2_MODULE_ACCEPTANCE.md`
- `release/2.0` 分支、`v2.0.0-alpha.1`、milestone
- 干净 clone 可构建的记录

出口条件（G0）：

- [ ] 范围清单冻结，包含/不包含明确。
- [ ] 598+ 条变更全部有归类，无“待定”源码。
- [ ] 仓库不含构建产物、私密数据、密钥、真实数据库。
- [ ] `release/2.0` 存在，`v1.0.0` 标签未动。
- [ ] 模块验收矩阵初版完成，每个模块都有负责人/状态。

阻塞点：未授权提交或推送；范围仍在摇摆；构建产物与源码混在一起。

### P1 发布工程

**目标**：让“构建、测试、观测、自检”成为自动动作，而不是手工记忆。

工作项：

- CI：typecheck + build + 全量自动回归；失败阻断。
- 健康检查：`/api/health`，区分进程存活、数据库可用、磁盘可写。
- 结构化日志：request id、账号、路由、耗时、错误码；不打印密钥、Cookie、出生资料、聊天正文。
- 错误上报：最小可用方案（文件日志 + 告警或外部服务），不阻塞发布。
- 依赖审计：`better-sqlite3` 原生模块、PDFKit、中文字体、`npm audit`。
- 发布自检脚本：版本号、迁移号、文档完整性、密钥扫描、产物清单。
- 生产只读验收脚本通用化。

产出物：CI 配置、健康检查、日志样例、审计记录、自检脚本。

出口条件（G1）：

- [ ] release 分支每次变更自动跑 typecheck/build/全量。
- [ ] 健康检查可用，故障时返回非 200。
- [ ] 日志可定位一次请求，且不含敏感信息。
- [ ] 干净环境 `npm ci && npm run build` 通过。
- [ ] 依赖审计无 high/critical，原生模块可在目标系统安装。

阻塞点：仓库无 CI 权限；目标系统未知（Linux/Windows）。

### P2 数据与部署

**目标**：证明这套系统能装、能迁、能备、能恢复、能回滚。

工作项：

- 目标主机、域名、HTTPS、持久磁盘、备份盘准备。
- 干净机器部署文档与脚本：Node 24、依赖、构建、环境变量、字体、启动。
- 反向代理：HTTPS、流式不缓冲、上传限制、超时、请求体限制。
- 进程守护、日志轮转、磁盘监控。
- 服务器侧定时备份（不依赖浏览器 auto-check），保留策略与失败告警。
- 迁移演练：v47→v56（副本）。
- 恢复演练：完整备份→删除→恢复→核对账号/命盘/聊天/报告/附件。
- 加密导出/导入、旧共享库 `import-legacy`、单盘迁移。
- 回滚方案与演练：v2 数据不能直接给 v1 代码。
- staging 部署与冒烟。

产出物：部署文档、迁移记录、恢复记录、回滚 runbook、staging 地址。

出口条件（G2）：

- [ ] 干净机器按文档从零部署成功。
- [ ] HTTPS、Cookie Secure、公开来源配置正确。
- [ ] 定时备份真实执行，失败会告警。
- [ ] 迁移、恢复、回滚各演练一次并留记录。
- [ ] 明确 RTO/RPO（建议恢复 ≤ 30 分钟，RPO ≤ 最近备份间隔）。

阻塞点：没有主机/域名/证书；生产数据不可用于演练（必须用合成或脱敏副本）。

### P3 安全与账号收口

**目标**：证明“不同账号彼此隔离，生产边界成立”。

工作项：

- 跨账号 API 矩阵：读、写、删、生成、导出、下载逐项验证。
- 会话、Cookie、CSRF、同源、代理头复核。
- 管理员边界、登录限额、注册开关。
- 密钥、配置、仓库泄漏扫描。
- 上传/备份/请求体/超时边界。
- 安全响应头与错误信息脱敏。
- 账号找回兜底：管理员本地重置密码命令（v2.0 不做邮件找回）。
- 最小 AI 配额/预算告警：按账号日限额，超额明确提示。

产出物：安全矩阵、扫描记录、配额说明、重置命令文档。

出口条件（G3）：

- [ ] 跨账号读写删生成导出全部被正确拒绝。
- [ ] 未登录、失效会话、跨源写入、超限上传均失败且不泄漏。
- [ ] 仓库无密钥/真实数据；错误响应无堆栈、无供应商原文。
- [ ] AI 配额生效，成本可统计。
- [ ] 密码重置兜底可用并有文档。

**功能冻结：本阶段出口后，不再新增功能。**

阻塞点：没有真实模型预算（配额可先做本地计数）；管理员操作授权。

### P4 质量与体验

**目标**：证明桌面、窄屏、真机核心链路可用。

工作项：

- 补本轮入口面板的真实浏览器验收：320/390/768/1280，展开、切换、来源、快捷草稿、无横向溢出。
- 统一 E2E 种子与会话启动器：合成账号 + 各模块样例 + 隔离端口。
- 桌面关键链路：注册→登录→起盘→聊天→报告→PDF→备份→恢复→账号隔离。
- 窄屏关键链路：320/390/768。
- 真机：iOS/Android 各一台，走完核心链路。
- axe 关键页：登录、首页、命盘、八字、报告、备份、设置、独立术数。
- 空/错/加载/重试状态巡检。
- 控制台/网络错误巡检。
- 旧报告/旧聊天兼容抽查（v1～v6）。
- 导航、账号菜单、移动端布局一致性。

产出物：E2E 脚本、截图、真机记录、axe 结果、缺陷清单。

出口条件（G4）：

- [ ] 桌面 + 320/390/768 关键链路通过。
- [ ] 2 台真机通过。
- [ ] axe 无 critical/serious。
- [ ] 每模块有空/错/加载/重试状态。
- [ ] 旧报告与旧聊天不补算、不串版本。
- [ ] P0/P1 缺陷清零。

阻塞点：没有真机；staging 不可用；E2E 种子依赖真实数据（禁止）。

### P5 真实模型与内容

**目标**：证明真实供应商下输出不越界，成本与失败可管理。

工作项：

- 四类冒烟：命盘问答、八字论命、报告生成、独立术数问答。
- 记录 token、耗时、费用、失败率、取消/重试行为。
- 抽样审阅报告与问答：章节、引用、边界、越权断言。
- 超时、断流、取消、迟到响应、恢复。
- 模型配置、密钥轮换、失败降级说明。
- 真实模型问题回填 P0/P1 修复。

产出物：冒烟记录、成本表、抽样审阅记录、故障演练记录。

出口条件（G5）：

- [ ] 四类真实调用成功，成本有数字且不超预算。
- [ ] 输出无“必定/注定/唯一用神/成格”等越权断言。
- [ ] 超时/取消/失败不会留下卡死状态。
- [ ] 明确“真实模型只做抽样，不承诺全面质量”。

阻塞点：没有供应商密钥/预算；供应商限流。

### P6 文档、RC 与冻结

**目标**：形成可发布候选，完成观察，打正式标签。

工作项：

- README、部署、升级、回滚、备份恢复、故障排查。
- 隐私、条款、FAQ 与实际数据流一致（AI 发送范围、删除、备份、第三方）。
- 发布说明：新增、不兼容、迁移、已知限制、下一版本。
- 已知限制矩阵：每模块边界、未完成规则、部署限制。
- `v2.0.0-rc.1` 上 staging，观察期只修发布阻断问题。
- 最终全量回归、类型检查、构建。
- 打 `v2.0.0`，GitHub Release，发布后监控。

产出物：文档集、RC 记录、最终验收、发布说明、标签。

出口条件（G6）：

- [ ] 八道发布门槛全部满足。
- [ ] RC 观察期无 P0/P1 新增。
- [ ] 最终回归连续两次通过。
- [ ] 发布说明与迁移指南可执行。
- [ ] 备份、回滚、监控在发布前就绪。

阻塞点：文档与实际行为不一致；RC 期间仍加功能。

### P7 发布后观察

**目标**：稳定运行，准备 v2.1。

工作项：

- 监控进程、磁盘、错误率、AI 成本。
- 处理 v2.0.x 热修。
- 收集真实反馈与缺陷。
- 启动 v2.1（五合去留与合化条件）范围讨论。

出口条件（G7）：

- [ ] 发布后观察期无数据/安全问题。
- [ ] 热修流程可用。
- [ ] v2.1 范围与阶段计划确认。

## 4. 资源阻塞点

| 缺少 | 卡住阶段 | 可行替代 |
| --- | --- | --- |
| 提交/推送授权 | P0 | 本地 `release/2.0` 先收口，不推送 |
| 主机/域名/证书 | P2 | 本地/局域网 staging 先演练，不作为正式发布 |

| 管理员操作授权 | P3 | 先写命令与文档，不执行真实账号操作 |

## 5. 冻结点定义

- **功能冻结**：P3 出口。之后只允许 P0/P1 修复，不允许新面板、新规则层、新模块。
- **代码冻结**：P6 的 RC 观察开始后。只允许发布阻断修复，每次修复跑相关专项 + 全量。
- **正式发布**：P6 出口。打 `v2.0.0`，保留 `v2.0.0-rc.*` 记录。
- **回退**：任何阶段发现 P0 缺陷，回退到对应阶段修复；不跳阶段发布。

## 6. 冻结前明确不做

- 五合去留、合化效力、争合妒合（v2.1）。
- 六爻三合/墓绝/反伏吟、奇门暗干/长生、梅花外应。
- 大重构（`BaziWorkspace`、`db/client.ts`）。
- 支付/会员/人物档案中心/Android。
- 多实例、队列、PostgreSQL/Redis。
- 邮件找回、2FA、完整 AI 费用平台。
- UI 全面改版。

## 7. 下一阶段入口

从 **P0** 开始，先做三件事：

1. 锁定范围与五合去留归属。
2. 完成工作区分类，切 `release/2.0`。
3. 写模块验收矩阵，补入口面板浏览器验收。

P0 不通过，不进入 P1。
