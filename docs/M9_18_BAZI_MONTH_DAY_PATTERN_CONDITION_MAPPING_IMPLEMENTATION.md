# M9-18 八字流月流日格局条件映射实施说明

## 1. 阶段结论

M9-18 已把 M9-13 的月令格局候选和静态条件检查，映射到指定流日的每一个精确时间片段。系统现在可以回答：

1. 某项成格支持、破格风险或救应候选在原局中的静态状态是什么；
2. 大运、流年表层是否出现该规则相关的既有十神角色；
3. 流月、流日表层是否新增该规则相关的十神角色；
4. 四个动态表层合并后覆盖了哪些规则角色组；
5. 是否存在与规则相关的五合、月支冲合刑害等明确结构入口；
6. 哪些同类十神只存在于藏干位置或命中了触达入口。

本阶段只做“条件入口映射”，不宣告某日已经成格、破格、格局升级或完成救应，也不计算格局分数、层次、用神喜忌、吉凶和具体事件。

## 2. 为什么不能直接重算格局成败

流月或流日出现某个十神，只能证明当前时间层出现了一个可见角色。它不能自动证明：

- 原局缺失条件已经被永久补齐；
- 风险条件已经实际破坏格局；
- 五合、三合或六合已经完成制化；
- 藏干已经透出或发动；
- 日主具备承载该格局的实际力量；
- 不同条件之间已经完成优先级裁决。

因此 M9-18 使用以下分层，而不是把所有证据混成一个结果：

```text
M9-13 静态格局条件（候选、检查、状态、风险救应链接保持不变）
  ├─ M9-15 大运／流年可见表层角色 → 岁运既有覆盖
  ├─ M9-15 流月／流日可见表层角色 → 月日新增覆盖
  ├─ 四个动态表层合并             → 组合覆盖，仅供核对
  ├─ M9-15 明确干支关系           → 结构入口上下文
  ├─ M9-16 藏干位置与触达         → 隐藏条件上下文
  └─ M9-17 三层旺衰方向           → 身用背景，不参与格局裁决
```

## 3. M9-13 规则语义复用

M9-18 不复制一套新的格局规则，而是由 M9-13 公开规则描述器，复用既有检查的匹配方式：

| 匹配方式 | 动态映射含义 |
| --- | --- |
| 任一角色 | 当前层出现规则列出的任一表层十神 |
| 全部角色组 | 每一个角色组至少出现一个可接受表层十神 |
| 缺项检查 | 只展示相关动态角色，不改写原局缺项状态 |
| 天干五合 | 必须存在 M9-15 明确五合关系入口 |
| 月支关系救应 | 必须存在 M9-15 月支六合、三合或三会入口 |
| 通用月支互动 | 读取 M9-15 中与原局月支连接的明确关系 |
| 候选或旺衰上下文 | 只引用上游背景，不参与动态覆盖判定 |

成格支持、破格风险和救应候选的分类、静态状态、证据及 `linkedBreakingRuleIds` 全部原样保留。

## 4. 三层覆盖规则

每一项 M9-13 检查分别生成：

- `inheritedCoverage`：只读取大运、流年表层天干角色；
- `focusCoverage`：只读取流月、流日表层天干角色；
- `combinedCoverage`：合并上述四个动态表层角色。

允许的覆盖状态包括：

- 规则所需表层角色组已观察到；
- 只观察到部分角色组；
- 未观察到所需表层角色；
- 观察到或未观察到明确结构入口；
- 缺项规则不由动态层重分类；
- 仅保留上游上下文；
- 时柱未知，未见项保持不完整。

“角色组已观察到”只描述可见位置，不等于条件齐备或实际生效。数量只用于审计和界面概览，不形成权重或评分。

## 5. 结构关系与藏干隔离

### 5.1 M9-15 关系入口

天干五合、月支冲合刑害、三合、三会等必须来自当前精确片段的 M9-15 明确关系证据。它们以 `structural` 证据进入 `relationContext`，不能被解释为合化成功、解冲、破格或救应完成。

### 5.2 M9-16 藏干上下文

与规则十神相符的藏干，只能进入 `hiddenContext`：

- 未命中入口时表示该十神位于某支藏干；
- 命中同干表层、同支重复或明确关系时表示存在触达上下文；
- 无论命中几类入口，都不能计入三个表层覆盖组。

这避免了“地支里藏有某字”被错误表述为“表层条件已经齐备”。

## 6. M9-17 方向背景

每个片段会引用 M9-17 的：

- 静态基线标签；
- 大运／流年既有方向；
- 流月／流日新增方向；
- 五层表层合并方向；
- 新增与既有方向比较。

这些内容只用于提醒身用承载仍需复核，不改变任何格局检查的覆盖状态，更不能生成格局成败结论。

## 7. 精确片段隔离

M9-18 要求 M9-15、M9-16 和 M9-17 的目标日期、目标年份、片段编号及前闭后开边界完全一致。

如果某日 `06:51:00` 进入新大运：

- `00:00:00` 至 `06:51:00` 前不得读取新大运角色；
- `06:51:00` 至次日 `00:00:00` 前才绑定新大运；
- 两个片段分别生成完整候选与检查映射；
- 前一片段的角色、关系和触达不得累计到后一片段。

上游日期、年份或片段边界不一致时，引擎直接拒绝合成。

## 8. 数据持久化

SQLite 升级到 v40，新增 `bazi_month_day_pattern_versions`，每个版本同时绑定：

- 八字命盘版本与指纹；
- M9-13 格局条件版本与指纹；
- M9-15 流月流日关系版本与指纹；
- M9-16 显隐透根触达版本与指纹；
- M9-17 旺衰综合矩阵版本与指纹；
- 目标日期、方法版本和引擎版本；
- M9-18 结果 JSON 与 SHA-256 指纹。

相同五类上游版本、日期和方法版本会幂等复用旧结果；任一来源变化都会生成新版本。`bazi_conversations.month_day_pattern_version_id` 保存会话默认日期版本，旧会话打开时自动补齐。

## 9. API 与工作台

新增接口：

- `POST /api/bazi/charts/:id/month-day-patterns`：按 `targetDate` 生成或复用映射；
- `GET /api/bazi/charts/:id/month-day-patterns?date=2030-12-12`：读取指定日期最新版本和缓存列表。

工作台新增“流月流日格局条件映射”面板：

- 顶部显示日期、日干支和精确片段数；
- 每个候选继续分成成格支持、破格风险、救应候选三列；
- 每项检查展示静态状态、岁运既有、月日新增和合并覆盖；
- 表层角色、结构关系和藏干上下文使用不同标识；
- 关系与藏干详情默认折叠；
- 切换日期后自动持久化，重复日期优先复用缓存。

聊天侧栏同步展示日期、片段数、三层口径和方法版本，并提供按精确片段提问的快捷入口。

## 10. AI 上下文与预算管理

提示词升级为 `bazi-chat-month-day-pattern-v17`。问题包含明确日期或“今天／今日”时，按同一版本链注入 M9-14 至 M9-18 证据。

上下文清单新增：

- `monthDayPatternVersionId`；
- `monthDayPatternFingerprint`；
- `monthDayPatternTargetDate`。

允许能力新增 `month_day_pattern_condition_mapping_audit`，禁止能力新增 `month_day_pattern_success_failure_verdict`。

完整 M9-18 结果保存在 SQLite 并可在工作台查看；模型上下文只注入当前日期存在表层角色或明确关系入口的检查，以及精简的纯藏干摘要。事实预算根据模型输入上限动态预留系统提示、当前问题和摘要空间，避免随着证据阶段增加而超过输入预算。

输出守卫会拦截把流月、流日、动态角色或格局条件的覆盖、风险、救应、五合、会合、触达改写成“已经成格、破格、救应完成、合去、解冲、格局升级或受损”的回答。

## 11. 降级规则

- 时辰未知：保留三柱和动态证据，未见角色组标记为不完整；
- 非支持时区：上游没有精确片段时返回 `sequence_only_unavailable`；
- 未交首运：既有层只读取流年，不补写大运；
- 缺项规则：动态角色出现也不修改静态缺项状态；
- 没有动态入口：显示空状态，不由 AI 补写；
- 上游版本或片段错配：拒绝生成，不静默拼接。

## 12. 测试覆盖

专项测试 `test:bazi-month-day-patterns` 覆盖：

- 方法契约和禁止结论；
- M9-13 候选、检查、静态状态和风险救应链接原样保留；
- 任一角色、全部角色组、缺项和结构入口语义；
- 岁运既有、月日新增和合并覆盖分离；
- 藏干永不进入表层覆盖；
- M9-15 关系与 M9-16 藏干来源可追溯；
- M9-17 方向只作为上下文；
- 交运日前后精确双片段；
- 未知时辰和非支持时区降级；
- SQLite v40、五上游版本指纹和同日幂等缓存；
- API、会话绑定、明确日期上下文路由、动态预算和越权输出守卫。

## 13. 当前能力边界

M9-18 完成后仍不能自动回答：

- 某日是否最终成格或破格；
- 风险和救应哪一方最终生效；
- 合冲刑害的最终优先级和作用结果；
- 藏干是否已经透出、发动或成为有效力量；
- 最终身强身弱、用神喜忌和格局层次；
- 事业、感情、财富、健康等吉凶与具体事件。

## 14. 下一阶段

M9-0 至 M9-18 已形成从四柱事实、静态解释、大运流年、关系、十神、显隐透根、藏干触达、旺衰矩阵、格局条件，到精确流月流日映射的基础审计闭环。

按照总路线，下一阶段回到既有产品增强项，优先开发“人生事件智能提取与用户确认”：从聊天中提取候选现实事件，必须经用户确认后才写入时间轴、长期记忆和后续上下文。之后再处理服务端 PDF 导出与报告版本差异。M10 其他术数继续保持独立立项。
