# M8-1 本地提醒中心实施说明

## 1. 阶段目标

M8-1 在 M8-0 的 SQLite 提醒规则、实例生成和状态流转能力之上，提供普通用户可直接操作的本地提醒中心。

本阶段解决三个问题：

1. 用户可以从首页进入提醒中心，并看到当前到期数量。
2. 用户可以创建五类本地提醒，而不需要理解底层规则字段。
3. 用户可以处理提醒实例，也可以启用、停用、归档或删除提醒规则。

## 2. 页面结构

页面路径为 `/reminders`，由两个视图组成。

### 2.1 待办与历史

- 当前到期：已到提醒时间且仍待处理的实例，包括尚未处理的过期提醒。
- 未来计划：尚未到期的实例，按时间排序。
- 处理历史：已完成或已忽略的实例，可重新打开。

每条实例展示提醒时间、规则来源和边界说明。关联单人命盘的提醒可以直接返回对应命盘继续查看。

### 2.2 规则管理

- 查看规则类型、执行周期、时区和引擎版本。
- 启用或停用规则。
- 归档及恢复规则。
- 删除规则，并同步删除其已经生成的实例。

删除属于不可恢复操作，因此页面在执行前要求二次确认。

## 3. 五类创建表单

### 3.1 月度复盘

用户设置每月日期和提醒时间，并可选关联一个单人命盘。遇到二月或没有对应日期的短月份，提醒引擎自动使用当月最后一天。M8-2 起，已关联命盘会在进入月度复盘时自动带入。

### 3.2 生日年度回顾

用户选择已有单人命盘，设置提前天数和提醒时间。生日来自命盘中已经保存的出生信息，表单不重复录入。

### 3.3 流年或大限观察

用户选择已有单人命盘，并选择新流年或新大限层级。提醒只负责提示观察，具体分析仍由项目已有的确定性运限引擎承担。

### 3.4 人生事件周年回顾

用户先选择单人命盘，再从该命盘中选择“用户已确认且精确到日”的人生事件。这样可以避免年份或月份精度不足时生成虚假的周年日期。

### 3.5 自定义提醒

用户设置日期、时间以及仅一次、每月或每年重复方式，适合不属于其他专业模块的本地待办。

## 4. 首页联动

首页加载时会先执行一次幂等实例生成，再查询当前到期提醒：

- 桌面端在顶部导航展示“提醒”入口。
- 移动端使用右下角悬浮入口，避免挤占狭窄导航空间。
- 存在到期提醒时展示数量徽标，超过 99 条显示 `99+`。
- 提醒服务暂时不可用时不会阻塞首页其他功能。

## 5. 数据与状态流

```text
提醒规则
  └─ 幂等生成提醒实例
       ├─ pending + 未到期 -> 未来计划
       ├─ pending + 已到期 -> 当前到期
       ├─ completed -> 处理历史
       └─ dismissed -> 处理历史
```

实例从完成或忽略状态重新打开后，会重新按照当前时间计算为“当前到期”或“未来计划”。停用、归档规则后，其实例不会进入到期列表和首页徽标统计。

## 6. 本地部署边界

- 数据仍只写入当前设备的 SQLite，不引入账号体系。
- 应用打开时才检查和生成提醒。
- 本阶段不发送系统通知、短信、邮件或第三方推送。
- 页面展示的流年、大限提醒属于观察入口，不替代专业分析结果。
- 时区固定为 `Asia/Shanghai`，避免本地部署环境差异造成日期偏移。

## 7. 验证范围

新增 `npm run test:reminder-center`，覆盖：

- 创建到期和未来提醒。
- 非法提醒类型校验。
- 待办、未来和首页到期数量查询。
- 完成提醒与重新打开。
- 停用规则后移出到期列表。
- 删除规则时级联清理实例。

同时继续执行 M8-0 基础测试，保证提醒计算和 SQLite v21 数据能力没有回归。
