# 观辰统一账号服务（1.1.0-dev）

本阶段从冻结的 v1.0.0 开发。所有用户访问同一个观辰网站和后端，注册或登录后使用自己的资料；用户端不需要部署项目。当前开发分支为 `codex/user-accounts`，稳定标签 `v1.0.0` 保留原行为，本阶段尚未合并或发布到 main。

## 账号与资料边界

支持用户名注册、密码登录、退出、修改密码和管理员用户管理。用户名大小写统一，密码为 10–128 个字符，以随机盐和 scrypt 派生存储。随机会话令牌只以哈希保存，Cookie 为 HttpOnly、SameSite=Lax，绝对有效期 7 天。改密码撤销所有设备会话；停用或变更角色撤销该账号已有会话。注册不能指定管理员身份；管理员不能在管理页停用或降级自己。

所有业务 API 在读写前验证会话。后端通过请求的异步账号上下文选择业务数据库和文件目录，客户端提供的 userId、记录 ID 或查询参数不能切换资料空间。聊天、命盘、合盘、八字、校时、报告、事件、学习进度、案例、提醒及备份都按账号隔离。公开古籍知识文件可以共享，用户的笔记与练习记录独立。

管理员可以搜索、分页查看账号和变更启停状态、角色，业务页面仍只访问自己的聊天和档案。服务器部署者具有文件系统权限，因此这种业务隔离不等于对运维人员加密。

统一后端内部使用账号库和各用户的 SQLite 文件：

```text
ACCOUNT_DATA_DIR/
  accounts.sqlite                 # 统一账号、会话和登录限额
  users/<服务端生成的用户 UUID>/
    ziweidoushu.sqlite             # 该账号的完整业务资料，当前开发版结构 v56
    report-exports/                # 该账号的 PDF
    backups/                      # 该账号的备份及策略
  legacy-backups/                  # 部署者迁移旧资料时保留的归档
```

这仍是一套集中部署的服务。选择文件隔离便于复用既有模块的事务、备份与恢复逻辑；每个用户的恢复不会覆盖统一账号库或其他用户资料。连接按账号缓存，只回收未被请求/响应流占用的空闲连接，空闲用户槽位总数限制为 64；活跃请求可暂时超过该值。当前架构采用单个 Node 服务进程，尚未完成多实例共享磁盘、规模压测或 PostgreSQL 迁移。

## 部署配置

本机开发使用 `npm run dev`，默认端口 30001。用户先注册，部署者再指定管理员。正式服务在持久化磁盘上构建并以 `npm start` 运行，通过 HTTPS 反向代理提供唯一访问地址，支持流式响应并关闭代理缓冲。代理应限制上传大小（本项目备份归档上限 128 MiB），根据部署环境配置超时、请求限额和持久化备份。

在 `.env.local` 配置：

```dotenv
ACCOUNT_DATA_DIR=/你的持久化数据目录/accounts
AUTH_REGISTRATION_ENABLED=1
AUTH_COOKIE_SECURE=1
APP_PUBLIC_ORIGIN=https://你的服务域名
```

Windows 可使用绝对路径，例如 `G:/GuanChenData/accounts`。本机 HTTP 测试使用 `AUTH_COOKIE_SECURE=0`，不要设置指向正式域名的 APP_PUBLIC_ORIGIN。通过反向代理部署时，固定公开来源用于同源写入校验，不依赖可伪造的 X-Forwarded-For；登录尝试和注册次数限制持久化在账号库。可设置 `AUTH_REGISTRATION_ENABLED=0` 关闭注册，既有账号仍可登录。

管理员初始化：先在网页注册目标账号，再在部署电脑的项目目录执行：

```sh
npm run accounts:manage -- admin 你的用户名
```

此命令只指定权限，不创建默认密码，也不赋予管理员查看所有聊天的入口。使用最新 `.env.local` 中同一个 ACCOUNT_DATA_DIR，重新登录查看用户管理。

AI 供应商密钥继续只配置在服务端，不由用户浏览器保存。本阶段没有短信/邮箱验证、找回密码邮件、会员或支付功能。正式域名、服务器与证书尚未在本阶段实际部署。

## 原有资料迁移

升级不会把旧共享数据库自动分给第一个注册的人。原 `SQLITE_PATH`（默认 data/ziweidoushu.sqlite）及 `REPORT_EXPORT_DIR` 继续保留，网页业务不会回退读取它们。部署者指定一个空白账号接收资料，**停止服务后**执行：

```sh
npm run accounts:manage -- import-legacy 目标用户名
```

命令先归档旧库及报告附件，再将资料复制到目标账号。目标账号已有业务资料时拒绝覆盖；原库和旧备份继续保留。不要在服务运行时执行迁移或并行操作同一目标库。迁移用户的归属由项目所有者决定，本轮不擅自接管真实历史资料。

## 备份与验证

网页的数据保险箱仅处理当前账号的资料。运营级备份还必须包含统一 accounts.sqlite、所有用户目录和部署配置；服务停止后保留整个 ACCOUNT_DATA_DIR，避免只复制 WAL 模式下的主数据库文件。配置、数据库、备份和报告不进入 Git，也不放入 public 目录。

本阶段的验证记录见 [账号体系验收](ACCOUNT_SERVICE_QA.md)。原有业务回归已调整为真实测试账号和会话，保留鉴权；测试使用独立临时目录及模拟 AI，不读写真实档案。已冻结 v1 的测试记录继续保留，不混作新账号版本的结果。
