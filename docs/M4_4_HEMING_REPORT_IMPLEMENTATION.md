# M4-4 合盘专题报告实施说明

> 完成日期：2026-08-15
> 范围：合盘关系报告、证据链、版本历史、重新生成和打印导出

## 1. 阶段结果

M4-4 已在 M3 专题报告基础设施上增加合盘关系报告。合盘会话现在可以把双命盘事实、M4-2 规则结果和用户确认的现实背景整理成一份可保存、可重新打开、可追溯依据的完整报告。

报告不会复用聊天文字作为权威事实，而是在每次生成时重新读取当前合盘会话和确定性规则评估。关系背景修改后点击“重新生成”，系统创建新版本；只有新版本完整生成并通过结构校验后才会切换为当前版本，失败版本不会覆盖旧的有效报告。

## 2. 报告结构

合盘关系报告固定包含六个章节：

1. 关系基线。
2. 支持性结构。
3. 压力点与差异。
4. 沟通与协作建议。
5. 现实边界与待确认事项。
6. 当前阶段影响。

此外包含核心摘要、三至六条行动建议、待观察问题和风险免责声明。

## 3. 证据模型

合盘报告复用 `reports`、`report_versions` 和 `report_evidence`，没有建立重复表。合盘会话使用 `relationship` 报告槽位，但使用独立标题和提示词版本 `heming-report-v1`。

新增四类报告证据：

- `heming_palace`：带有 A/B 归属、角色、宫位、地支和星曜的双盘事实。
- `heming_rule`：规则编号、版本、维度、阶段、级别、置信度、结论和底层证据归属。
- `heming_context`：关系类型、双方角色、关注问题和用户明确确认的现实背景。
- `heming_stage`：甲乙双方各自的当前大限阶段事实。

每个章节只能引用本次输入中存在的证据 ID。无证据的跨项解释会标记为“综合观察”。报告详情页可以展开查看每节的结构化依据。

## 4. 身份与方法边界

- 甲方 A、乙方 B 和双方互动始终分开，不交换或合并字段。
- 双盘证据不包含姓名、城市或宫干自化等无关、禁用字段。
- 规则结果的级别、置信度、编号和阶段不允许由模型修改。
- 本命关系基线与当前阶段影响分层呈现。
- 结构对应不等于吉，结构差异不等于凶。
- 不输出匹配分数或百分比。
- 未经用户确认的现实经历保持未知。
- 不替用户作出结婚、分手、签约、投资或医疗决定。

## 5. 页面与路由

- `/heming/[id]/reports`：合盘报告中心。
- `/heming/[id]/reports/[reportId]`：合盘报告详情与版本历史。
- 合盘工作台顶部新增“合盘报告”入口。
- 报告详情支持版本切换、重新生成和浏览器打印/另存为 PDF。

合盘详情复用 M3 报告阅读器，但增加合盘标题、返回路径以及甲乙宫位、规则、关系背景和阶段证据的可读摘要。

## 6. 生成与失败策略

1. 第一次生成创建报告主记录和 v1 版本。
2. 相同报告已经完成时直接打开缓存版本。
3. 点击重新生成时创建递增版本。
4. 生成中版本在三分钟内不能被重复认领。
5. 模型输出必须通过 JSON、六章节和证据 ID 白名单校验。
6. 新版本成功后才更新 `active_version_id`。
7. 失败版本保留错误状态，旧版本继续可见。
8. 删除合盘会话时，报告、版本和证据由 SQLite 外键级联删除。

## 7. 验证

新增 `npm run test:heming-reports`，覆盖：

- 甲乙双盘证据和归属。
- 规则、阶段与现实背景证据。
- 姓名、城市和禁用字段不进入报告提示词。
- 固定六章节与证据 ID 白名单。
- 报告主记录复用和版本递增。
- 新版本失败不覆盖旧版本。
- 删除会话后的报告级联清理。

同时回归 M3 单盘专题报告，确保合盘扩展没有改变原有报告行为。
