# M9-10 岁运透干与通根条件证据审计实施说明

## 1. 阶段目标

M9-10 在 M9-9 显隐重复位置簇之上，增加有方向的条件审计：

- 从藏干指向表层天干，检查是否存在完全同干的“透出条件匹配”；
- 从表层天干指向藏干，检查是否存在完全同干的“严格同干根候选”；
- 把同五行但不同干的藏干单列为“同五行支持参照”；
- 表层天干与完全同干藏干位于同一节点时，标记“坐支同干位置”；
- 月支藏干与其他地支藏干分别标记；
- 条件满足、条件缺失和上游证据回指都可追溯。

本阶段仍不裁决透干是否有效、根气强弱、真假根、藏干引动、格局成败、旺衰、喜忌、吉凶或具体事件。

## 2. 数据链路

```text
确定性四柱与实际藏干
   ↓
M9-8 大运／流年表层与藏干位置
   ↓
M9-9 同干显隐重复簇
   ↓
M9-10 透出方向条件 + 根气方向条件 + 条件缺失
```

M9-10 不重新排盘，也不自行生成藏干。所有位置沿用 M9-8／M9-9 的节点、层级、本气／中气／余气和十神元数据。

## 3. 两个方向不能混为一谈

### 3.1 藏干到表层：透出条件

对每个岁运相关藏干检查同一实际时间片段内是否存在完全相同的表层天干或日主参照：

```text
藏干癸 → 表层癸：完全同干表层条件匹配
藏干癸 → 只有表层壬：不满足完全同干透出条件
```

原局月支藏干单独标记为“月令藏干”。这是因为《子平真诠》所举“甲生辰月，透戊、癸、乙”的透干示例明确围绕月令藏干展开。项目同时保留其他地支的广义同干位置匹配，但不把两种语义混为一个月令格局结论。

输出只能称为：

- 完全同干表层条件匹配；
- 缺少完全同干表层；
- 月令藏干或一般藏干。

不能称为“透干有效”“透干得力”“已经成格”或“藏干已发动”。

## 4. 表层到藏干：根气条件

每个岁运相关表层天干分三档记录：

| 状态 | 确定性条件 | 输出口径 |
| --- | --- | --- |
| 严格同干根候选 | 同片段存在完全相同的实际藏干 | 只说明同干位置成立 |
| 仅同五行支持参照 | 没有完全同干，但存在同五行不同干藏干 | 不冒充严格同干根 |
| 缺少藏干支持 | 没有同干或同五行实际藏干 | 不直接推导天干无力 |

例如：

```text
表层丙 + 藏干丙：严格同干根候选
表层丙 + 只有藏干丁：仅同五行火支持参照
表层丙 + 无丙丁藏干：缺少实际藏干支持
```

这一分离同时兼容项目 M9-3 既有的“同五行实际藏干根气”证据，又为后续需要严格同干的规则保留更窄口径。

## 5. 坐支同干位置

只有以下条件同时满足才标记坐支同干：

1. 表层天干与藏干完全同干；
2. 两者属于同一个原局柱、大运节点或流年节点；
3. 两者位于同一实际时间片段。

标记只描述位置，不自动输出“坐根有力”“强根”“真根”或力量增减。

## 6. 动态相关过滤

M9-10 是岁运审计，不把纯原局静态证据复制到每一个年份：

- 动态藏干可以匹配当前片段的原局、大运或流年表层；
- 原局藏干只有在匹配动态表层时进入年度候选；
- 动态表层可以检查当前片段的原局、大运或流年藏干；
- 原局表层只有在出现动态藏干支持时进入年度候选；
- 纯原局根气继续由 M9-3 静态解释证据负责。

因此每个 M9-10 候选至少包含一个大运或流年位置。

## 7. M9-9 回指

完全同干的表层／藏干动态匹配必须回指同片段 M9-9 同干簇：

- 回指成功：保存 `repeatClusterId`；
- 没有完全同干匹配：上游簇检查记为“不适用”；
- 理论上应有完全同干动态匹配但找不到 M9-9 簇：引擎直接报错，避免两个版本静默分叉。

同五行不同干不属于 M9-9 同干簇，因此不会伪造回指。

## 8. 条件检查模型

每个候选保留逐项检查：

- 片段内实际藏干／表层是否存在；
- 是否有完全同干表层／藏干；
- 是否有同五行实际藏干；
- 是否同节点坐支同干；
- 是否可回指 M9-9 同干簇。

状态只有：

- `met`：条件满足；
- `missing`：条件缺失；
- `not_applicable`：当前状态不适用。

这些状态不是分数，也没有自动优先级。

## 9. 跨运分段

M9-10 继承 M9-8／M9-9 的真实交运片段。流年跨越交运时：

```text
交运前：原局 + 流年
交运后：原局 + 新大运 + 流年
```

前后片段分别审计。后段大运藏干、表层和根气条件不会倒灌到交运前。

新增允许能力：

- `transparency_root_condition_audit`。

新增禁止能力：

- `transparency_root_effect_verdict`；
- `root_strength_verdict`。

输出守卫继续拦截仅凭显隐同见宣告透干／通根，并新增拦截：

- 把条件匹配宣告为透干有效、得力或作用完成；
- 把严格同干根、同五行支持或坐支位置宣告为强根、弱根、真假根或力量增强。

“不等于透干有效”“不代表根气有力”等边界说明允许正常输出。

## 13. 来源与方法边界

- [《子平真诠评注》电子文本](https://ctext.org/wiki.pl?chapter=974137&if=gb)：用于核对月令藏干透出示例；
- [《滴天髓》维基文库文本](https://zh.wikisource.org/zh-hans/%E6%BB%B4%E5%A4%A9%E9%AB%93/02)：用于核对通根用语；
- [《滴天髓阐微》地支章节](https://zh.wikisource.org/zh-hant/%E6%BB%B4%E5%A4%A9%E9%AB%93%E9%97%A1%E5%BE%AE)：用于核对地支可藏一至三干及本气优先的结构说明；
- [6tail lunar-java `EightChar` 官方实现](https://github.com/6tail/lunar-java/blob/master/src/main/java/com/nlf/calendar/EightChar.java)：用于核对表层天干、藏干和藏干十神的数据分离；
- 项目 M9-9 版本：用于完全同干动态匹配的上游簇回指。

古籍文本用于说明传统术语来源，不代表现代科学验证。本项目只实现可复核的位置条件，不输出超出证据的数据化强弱等级。
