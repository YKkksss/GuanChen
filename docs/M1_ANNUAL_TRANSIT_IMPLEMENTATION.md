# M1 年度运势分析第一版实现说明

## 1. 当前交付范围

本阶段完成 M1 的“年度分析”基础能力与只读年度总结报告，暂不开放流月和流日。系统将规则计算、结果存储和 AI 解读拆成四层：

1. 运限引擎生成确定性的年度快照。
2. SQLite 按会话、年份和引擎版本缓存快照。
3. Context Builder 只在用户处于年度分析页时，把当前选中年份的必要事实传给模型。
4. 年度报告服务使用独立模板生成完整报告，并按年份和版本持久化。

AI 不负责计算流年命宫、流年四化或宫位映射，只负责解释程序已经算出的结构。

## 2. 年度快照内容

每份 `AnnualTransitSnapshot` 包含：

- 所选年份、代表日期和年界策略。
- 流年干支与虚岁。
- 当年所在大限及其本命落宫。
- 流年命宫及其本命落宫。
- 流年四化与四化星在本命盘中的落宫。
- 流年十二宫到本命十二宫的逐宫映射。
- 流年命宫三方四正和四化落宫形成的重点宫位。
- 事业、感情、财运、健康专题宫位索引。
- 可供页面展示和调试的规则证据。

当前引擎版本为 `transit-v1-iztro-2.5.8`。相同命盘、年份和引擎版本必须返回相同快照。

## 3. 年界处理

年度选择统一使用当年 `07-01` 作为代表日期，只用于定位该年的年度运限结构。这样可以避免公历一月到春节前后发生“用户选了 2027，但历法仍处于上一年”的交互歧义。

页面和快照会明确记录 `selectedYear`、`representativeDate` 和 `boundaryPolicy`。未来增加精确日期的流月、流日分析时，应按真实目标日期计算，不能沿用年度代表日期。

## 4. 数据库

数据库第 3 版迁移新增 `transit_snapshots`：

- `(conversation_id, level, target_date, engine_version)` 唯一。
- 只缓存用户实际访问过的年份，不预生成一生数据。
- 删除会话时通过外键级联删除对应快照。
- 引擎版本升级后，新旧快照可以并存，不会静默覆盖旧规则结果。

数据库第 4 版迁移新增 `transit_reports`：

- 按会话、年份、运限引擎版本和报告模板版本唯一保存。
- 保存生成状态、报告正文、模型信息、Token 用量和完成时间。
- 已完成报告优先直接读取，不重复请求模型。
- 并发打开同一年时只有一个生成任务能够获得生成权。
- 手动重新生成期间保留旧正文，新报告成功后再覆盖。

## 5. API 与页面

年度快照接口：

    GET /api/conversations/[id]/transits?level=year&date=2027

年度报告接口：

    GET /api/conversations/[id]/transit-reports?level=year&date=2027
    POST /api/conversations/[id]/transit-reports

年度分析页面：

    /chart/[id]/timeline

页面支持年份切换、盘面流年四化叠加、年度事实卡、重点宫位、规则证据、完整只读年度报告和携带年份上下文的 AI 追问。

年度报告固定覆盖年度总览、命格、感情、事业、财运、健康、性格人际和行动建议。当前模板版本为 `annual-report-v2`。切换年份时先读取数据库，缺失或失败才自动生成；用户只有通过“重新生成”按钮才会主动覆盖缓存。

## 6. AI 上下文约束

年度页发出的消息会保存当前年份元数据。Context Builder 根据本条消息读取对应快照，并增加 `L2.5 选定时间运势事实`。该层只含当前年份的精简事实，不会把所有已查看年份都传给模型。

模型回答必须区分：

- 排盘事实：程序计算，可复现。
- 传统解释：对规则含义的解释。
- 行动建议：非确定性建议，不得描述为必然事件。

## 7. 验证

已覆盖以下自动化验证：

- 同一命盘同一年结果完全一致。
- 不同年份的干支、命宫和四化正确变化。
- 四化数量和十二宫映射完整。
- 同年重复请求命中同一 SQLite 缓存记录。
- 年度事实正确进入 AI 上下文清单。
- 年度报告模板包含八个固定分析维度，并且不发送姓名和出生地点。
- 已完成报告命中缓存，并发生成不会重复调用模型。
- 重新生成期间保留旧报告，成功后覆盖为新内容。
- 删除会话后快照级联清理。
- 删除会话后年度报告级联清理。
- 原有会话历史与上下文管理测试继续通过。

验证命令：

    npm run test:transits
    npm run test:conversations
    npm run test:context
    npm run build

## 8. 后续边界

下一小步建议增加年度报告历史版本或导出能力，然后再进入流月。流月、流日必须先明确历法边界、流派规则和固定测试案例，不能通过提示词临时模拟成已计算结果。
