# M1-3 紫微流日确定性排盘第一版实现说明

## 1. 本阶段完成内容

M1-3 在年度、流月事实层之上增加按公历自然日查询的紫微流日快照。用户可在时间运势页切换“年度分析 / 流月分析 / 流日分析”，选中某一天后查看：

- 公历日期及对应农历日期；
- 当前大限、流年和流月背景；
- 流年、流月、流日干支；
- 流日命宫及十二宫映射；
- 流年、流月、流日三层四化；
- 流日流曜、三方四正与四化落宫形成的重点宫位；
- 换日口径、计算事实和证据；
- 可直接用于当天追问的 AI 流日上下文。

本阶段只交付确定性排盘事实和观察工具，不把流日包装成“当天一定发生什么”，也不提供医疗、投资等高风险决策结论。

## 2. 日期与换日边界

### 2.1 第一版采用的口径

流日快照以一个公历自然日为最小粒度，每个 `YYYY-MM-DD` 只生成一份快照。当前采用 iztro 2.5.8 在未传入时辰时的早子时代表盘，并将口径固定为：

```text
civil-date-early-rat-hour-representative
```

对应字段为：

```text
representativeTimeIndex = 0
```

这表示页面里的“2026-03-18 流日”代表该公历日期从早子时口径观察的日级结构，确保日期选择、缓存和 AI 上下文具有唯一结果。

### 2.2 为什么第一版不把晚子时并入流日

iztro 的运限计算允许传入时辰；晚子时会涉及跨日干支处理。若只选日期而不选出生地、时区和具体观察时刻，就无法表达“当天晚子时”这一更细粒度语义。因此本版本明确：

- 流日页面采用早子时代表盘；
- 页面、证据和 AI 上下文都显示该边界；
- 用户询问晚子时或某个具体时刻时，不能把日级快照当作精确流时结论；
- 晚子时换日、流时盘和时区规则留给后续独立“流时”模块。

这样可以避免同一个日期因隐含时辰不同而出现两个缓存结果，也防止模型在没有时刻信息时伪造流时精度。

## 3. 确定性计算链路

```text
公历观察日 YYYY-MM-DD
  → 严格校验真实日期和出生日期范围
  → lunar-javascript 取得农历年月日
  → iztro horoscope 以早子时代表盘计算运限
  → 对齐大限 / 流年 / 流月 / 流日
  → 提取流日十二宫、四化和流曜
  → 计算流日命宫三方四正及重点宫位
  → 生成 DailyTransitSnapshot 和 EvidenceItem[]
  → 按“会话 + day + 公历日期 + 引擎版本”写入 SQLite
```

流日引擎版本独立固定为：

```text
transit-day-v1-iztro-2.5.8-early-rat-hour
```

年度和流月引擎版本保持不变。未来如果换日流派、依赖版本或算法变化，可以升级流日版本号并生成新快照，不会静默覆盖旧口径。

## 4. 快照与缓存

`DailyTransitSnapshot` 的主要字段：

| 字段 | 作用 |
| --- | --- |
| `targetDate` | 用户选择且已经规范化的公历日期 |
| `representativeDate` | 本次计算使用的代表日期 |
| `representativeTimeIndex` | 固定为 `0`，代表早子时 |
| `boundaryPolicy` | 固化日期级换日口径 |
| `lunarDay` | 农历年、月、日、闰月、月名与日名 |
| `year` / `decadal` | 流年与大限背景 |
| `flowYear` / `flowMonth` / `flowDay` | 三层命宫与干支事实 |
| `yearlyTransformations` | 流年四化背景 |
| `monthlyTransformations` | 流月四化背景 |
| `transformations` | 流日四化及本命落宫 |
| `palaceMappings` | 流日十二宫、流曜与本命宫逐宫对齐 |
| `keyPalaces` | 三方四正和四化落宫形成的重点宫位 |
| `evidence` | 边界、历法、宫位、四化、流曜等依据 |

数据库继续复用 `transit_snapshots` 表。相同会话、日期、层级和引擎版本直接读取同一条缓存；切换到另一天才按需创建新记录，不会预先计算大量无用日期。

## 5. 接口与页面

### 5.1 运限接口

```http
GET /api/conversations/:id/transits?level=day&date=2026-03-18
```

校验规则：

- `date` 必须为实际存在的 `YYYY-MM-DD`；
- 日期不得早于出生日期；
- 上限受出生年后 130 年及公历 2200 年双重保护；
- 返回快照日期与请求日期一一对应。

### 5.2 时间运势页

流日模式提供：

- 日期选择器；
- 前一日、后一日与“回到今天”；
- 日期同步到 URL，可刷新、收藏和直接分享；
- 公历、农历、三层干支和早子时口径提示；
- 流日四化、重点宫位、流曜、十二宫映射与证据；
- 流日事实作为当前聊天追问上下文。

年度总结报告仍只属于年度模式，不会错误套用为流日报告。

## 6. AI 上下文

流日页面发送消息时保存元数据：

```json
{
  "transit": {
    "level": "day",
    "targetDate": "2026-03-18"
  }
}
```

上下文构建器按元数据读取或创建对应快照，并强制采用以下层次：

```text
大限背景 → 流年主题 → 流月触发 → 流日观察
```

系统同时向模型声明：

- 流日只适合日记式观察和复盘；
- 不能把盘面关系描述为必然事件；
- 现实建议必须独立于传统解释；
- 涉及晚子时或具体时间，需要补充时刻并进入未来流时能力。

## 7. 测试与验收

新增 `npm run test:daily-transits`，覆盖：

- 相同日期生成相同快照；
- 早子时代表盘及边界字段固定；
- 2026-03-18 到 2026-03-19 的农历正月三十 / 二月初一边界；
- 流日干支、四化、十二宫、流曜与关联宫位完整性；
- 同日缓存复用、跨日新建记录；
- 流日事实、四层分析结构和晚子时边界进入 AI 上下文；
- 无效日期及出生日前日期被拒绝。

流月、年度回归测试与 TypeScript 类型检查同步通过，保证本次扩展没有破坏既有年度报告和流月缓存链路。

## 8. 当前限制与下一步

本阶段已经实现单日排盘、展示、缓存和追问闭环，暂不包含：

- 指定具体时刻的流时盘；
- 晚子时与时区精确换日；
- 将现实事件直接挂到选中日期；
- 多日期横向比较；
- 自动生成“今日吉凶”或确定性事件预测。

下一阶段建议进入 M1-4“全年十二流月时间轴与重点月份对比”，复用已验证的流月快照并提供全年浏览；随后与 M2 人生事件时间轴打通，支持把用户确认的现实事件精确挂到年月日。
