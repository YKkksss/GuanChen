# 观辰 v2.0.0 范围锁定

锁定日期：2026-10-18。状态：**P0 执行中，范围已按本文件冻结**。变更需走“范围变更”记录，不允许在 P4/P5 阶段临时加功能。

## 1. 版本定位

`v2.0.0` 是观辰第一个**统一账号、多用户隔离、可正式部署**的版本。

相对 `v1.0.0` 的不兼容变化：

1. 所有页面与业务 API 需要登录，数据按账号隔离。
2. 数据目录从单一 `data/ziweidoushu.sqlite` 变为 `ACCOUNT_DATA_DIR/accounts.sqlite + users/<uuid>/ziweidoushu.sqlite`。
3. 业务库从 v47 迁到 v56。
4. 部署形态变为集中后端 + HTTPS + 持久磁盘 + 备份恢复。
5. 模块矩阵扩展到八字、合参、择日、梅花、六爻、奇门、校时、学习、案例、提醒、报告与 PDF。

因此按语义化版本升 major，不发布为 1.2。

## 4. 冻结决策

| 决策 | 结论 | 说明 |
| --- | --- | --- |
| 五合去留是否进 v2.0 | **不进，放 v2.1** | 规则深化不改变 v2.0 的发布理由 |

| 是否新增数据库迁移 | 默认不新增 | 若必须新增，需单独评审并更新回滚方案 |

## 5. “模块完成”的定义

v2.0 的“模块完成”不等于术数理论完整，而是：

1. 有稳定入口与主流程。
2. 有空状态、错误状态、加载状态、重试。
3. 有账号隔离与权限边界。
4. 有实施文档与已知限制。
5. 有至少一个专项自动测试。
6. 有桌面/窄屏验收记录；关键模块有真机记录。
7. 旧报告、旧聊天不补算、不串版本。

未满足第 6、7 项的模块，只能标“功能完成、验收待补”，不能标“已交付”。

## 6. 兼容与迁移

- v1.0.0 用户：先备份，再注册空白账号，停服后 `accounts:manage -- import-legacy` 接收旧库。
- v2 数据不能直接交给 v1 代码运行；回退必须用升级前备份。
- 旧报告按实际字段回退 v1～v6，不补算新层。
- `v1.0.0` 标签不移动，旧分支不删除。

## 7. 范围变更规则

P3 功能冻结后，只有以下情况允许变更：

1. 修复 P0 缺陷所必需的最小改动。
2. 修复 P1 缺陷且不引入新数据模型。
3. 合规/安全要求。

任何新功能、新面板、新规则层、新数据库迁移，一律进入 v2.1 清单，不在 v2.0 开发。
