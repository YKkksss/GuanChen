# M9-0 八字方法论与确定性排盘基础实施说明

## 1. 阶段目标

M9-0 建立八字模块的独立领域边界和可测试的确定性排盘引擎。出生数据先经过明确的历法、时间标准与晚子时规则，再生成四柱事实；AI 不参与四柱计算，也不能改写排盘结果。

本阶段完成：

- 四柱排盘。
- 藏干与对应十神。
- 天干十神、纳音、十二长生和旬空。
- 表层五行与藏干五行的结构计数。
- 民用时间和地方视太阳时两种时间标准。
- 晚子时两种换日规则。
- 未知时辰的安全降级。
- 方法论、引擎、接口、基础页面和自动化测试。

本阶段不提供旺衰、格局、用神、大运、流年和具体吉凶判断。

## 2. 独立领域边界

新增 `lib/bazi` 模块，八字事实不写入紫微命盘 JSON，也不复用紫微宫位、星曜或四化类型。模块包含：

- `types.ts`：八字输入、四柱、藏干、五行计数和方法论类型。
- `methodology.ts`：版本、流派边界、允许输出、延后内容和来源注册。
- `validator.ts`：方法论静态校验。
- `engine.ts`：唯一确定性排盘入口。
- `index.ts`：稳定导出边界。

当前基础盘为无状态计算，不创建数据库表，不进入紫微会话上下文。下一阶段在出生档案与八字命盘持久化设计完成后再保存结果。

## 3. 历法计算口径

### 3.1 输入与范围

- 输入使用公历日期。
- 支持 1900-2100 年。
- 默认历史时区为 `Asia/Shanghai`。
- 采用 `lunar-javascript` 的精确八字接口。

### 3.2 年柱与月柱

- 年柱以立春的精确交接时刻为界，不以公历元旦或农历正月初一为界。
- 月柱以十二“节”的精确交接时刻为界，不以公历每月一日为界。
- 出生日期遇节气时，结果会显示边界提示。

### 3.3 晚子时

23:00-23:59 的日柱提供两种显式选项：

1. `same_day`：日柱仍按当前民用日期，映射到 `lunar-javascript` 流派 2。
2. `next_day`：日柱从 23 点起按次日，映射到 `lunar-javascript` 流派 1。

默认采用 `same_day`，与当前项目所使用历法库的默认行为保持一致。接口结果保存实际选项，后续持久化时不得只保存四柱而丢失流派规则。

## 4. 时间标准

### 4.1 民用时间

默认直接使用出生记录中的当地民用时间。时区仍被记录，为后续出生档案统一和跨地区数据迁移保留语义。

### 4.2 地方视太阳时

用户主动选择后，复用 M5 校时模块的时间服务：

1. 通过 IANA 时区数据库解析出生地当时的 UTC 偏移和夏令时。
2. 按出生地经度计算相对标准经线的时间修正。
3. 按 NOAA 分数年公式计算均时差。
4. 得到地方视太阳时，再交给八字引擎计算四柱。
5. 保存原始时间、历史偏移、均时差、经度修正、跨日结果和算法版本。

本阶段同时修正共享时间服务的闰年分母：平年使用 365 天，闰年使用 366 天，与 NOAA 公式说明一致。

## 5. 未知时辰策略

用户勾选出生时辰未知时：

- 不生成时柱。
- 年、月、日柱使用当天中午作为技术计算锚点。
- 五行结构只统计前三柱，表层总数为 6 而不是 8。
- 明确提示：如果实际出生在节气交接时刻或 23 点附近，年、月或日柱也可能变化。

该策略避免用默认的“子时”或“中午”伪装成真实时柱。

## 6. 五行结构计数

结果分两层展示：

- 表层：每柱的天干元素与地支本元素。
- 藏干：各地支藏干对应的元素出现次数。

结构计数仅用于核对构成，不等于旺衰。旺衰至少还涉及月令、透干、通根、刑冲合会、季节与不同流派权重，不能用“哪个元素数量多”直接判断身强身弱，也不能据此确定用神。

## 7. 服务接口与页面

新增接口：

- `POST /api/bazi/calculate`：接收出生信息与规则选项，返回确定性基础盘、时间换算快照、规则清单和边界提示。

新增页面：

- `/bazi`：填写出生日期、时刻、时间标准、经度、时区和晚子时规则。
- 展示四柱、日主、藏干十神、纳音、十二长生、旬空和五行结构。
- 未知时辰以占位卡展示，不伪造时柱。
- 首页桌面导航增加“八字”入口。

## 8. 自动化校验

新增 `npm run test:bazi-foundation`，覆盖：

- 方法论版本、来源和安全边界。
- 官方公开样例 `2005-12-23 08:37` 的四柱、藏干、十神、纳音和十二长生。
- 官方晚子时样例 `1988-02-15 23:30` 的两种日柱结果。
- 未知时辰不生成时柱，五行表层只统计前三柱。
- 地方视太阳时换算和缺少经度时的输入拦截。
- TypeScript 完整类型检查与 Next.js 生产构建。

## 9. 安全边界

- AI 不参与四柱计算。
- 不把五行数量包装成旺衰评分。
- 不隐藏时间标准或晚子时流派。
- 不在未知时辰时生成虚假时柱。
- 不在缺少规则和大规模校验时上线格局、用神或吉凶预测。
- 健康、投资、婚姻等重大决策不能依赖本模块作确定性判断。

## 10. 下一阶段：M9-1

M9-1 建议建立“出生档案—八字命盘”持久化关系：保存输入快照、规则版本、时间换算快照、四柱事实和指纹；同一出生档案可以按不同时间标准或晚子时流派保留多个可对照版本。完成持久化后，再接入八字独立会话和上下文，仍不在该阶段加入旺衰与用神。
