# M9-2 八字独立会话与上下文管理实施说明

## 1. 阶段目标

M9-2 把已保存的八字命盘版本升级为可持续追问、刷新可恢复的独立对话工作台。该阶段只解释 M9-0 已经确定性计算出的基础事实，不扩展旺衰、格局、用神、大运、流年或具体吉凶预测。

核心原则是“算法先给事实，AI 只做受限解释”：

- 会话必须绑定一个已保存的 `bazi_chart_versions` 版本。
- 每次请求都读取绑定版本的结果快照，模型不能重新排盘或改写四柱。
- 八字消息、摘要和上下文运行记录使用独立数据表，不进入紫微会话表。
- 上下文只包含八字基础事实、滚动摘要、最近消息和当前问题。
- 模型输出经过服务端边界检查后才返回前端。

## 2. SQLite v24 数据模型

### 2.1 `bazi_conversations`

保存八字会话主记录：

- 固定关联 `chart_version_id`。
- 记录方法版本、引擎版本和提示词版本。
- 保存结构化滚动摘要、摘要覆盖序号和摘要版本。
- 独立维护消息序号与更新时间。

同一命盘版本默认恢复最近的活动会话；用户在工作台显式选择“新建本版本会话”时才创建新的会话。

### 2.2 `bazi_messages`

保存用户和助手消息、顺序、来源、状态、Token 估算和错误码。开发服务意外退出后，遗留的 `streaming` 消息会在数据库重新打开时转为失败，避免页面永久显示生成中。

### 2.3 `bazi_context_runs`

每次模型调用保存：

- 供应商与模型。
- 上下文上限、输出预留和输入预算。
- 估算及实际输入、输出 Token。
- 摘要版本与最近消息范围。
- 上下文清单、状态和错误码。

清单只保存事实版本、层级名称和消息 ID，不复制完整敏感内容。

### 2.4 级联关系

删除八字命盘版本时，关联的八字会话、消息和上下文运行记录会级联删除；删除出生档案也会沿同一关系完整清理。界面删除提示已明确说明该影响。

## 3. 独立 Context Builder

上下文按固定顺序构建：

1. 八字基础解释系统边界。
2. 权威八字命盘事实快照。
3. 已有滚动摘要（如有）。
4. 摘要之后的最近 4 至 10 轮对话。
5. 当前问题。

事实快照包含：

- 方法版本和引擎版本。
- 输入日期、时间、性别及有效计算时间。
- 民用时间或地方视太阳时口径。
- 公历、农历、节气和日主。
- 四柱、天干地支五行、十神、藏干、纳音、十二长生和旬空。
- 五行结构计数、完整性、已应用规则和警告。

出生档案备注不会注入系统事实层，避免非结构化文本改变模型指令。

## 4. Token 预算和自动压缩

Context Builder 继续使用项目统一的模型容量配置：

- 默认上下文上限：32,768 Token。
- 默认输出预留：2,400 Token。
- 默认目标输入：12,000 Token。
- 事实层最多约 4,500 Token。
- 滚动摘要最多约 1,800 Token。
- 最近消息最多保留 10 轮，并尽量保证至少 4 轮。

滚动摘要满足任一条件时自动触发：

- 摘要之后达到 12 轮对话。
- 待摘要消息达到约 6,000 Token。

压缩时保护最近 6 轮不进入摘要；每批最多约 7,000 Token。摘要结构固定保存已讨论主题、已解释事实、用户问题、用户纠正、待继续问题、已重申边界和禁止假设。摘要模型同样被禁止新增命盘事实或推导高级判断。

自动摘要在一次回答落库后异步执行。摘要失败不会影响已完成的问答，下一次达到条件时仍可重试。

## 5. 安全边界

当前允许解释：

- 四柱的基础定位。
- 日主与基础十神关系。
- 藏干。
- 纳音、十二长生和旬空的术语含义。
- 历法、节气、时区、地方视太阳时和晚子时规则。
- 五行结构计数，但必须说明它不等于旺衰。

当前禁止输出：

- 身强、身弱或强弱评分。
- 格局认定。
- 用神、喜神、忌神或喜忌建议。
- 大运、流年和具体吉凶事件。
- 医疗、投资、婚姻等决定性建议。
- 紫微星曜、宫位和四化术语。

服务端会检测明显越界断语。命中时不返回原始内容，而是用安全边界说明替换，并在消息与上下文运行记录中写入 `output_guard_replaced`，便于后续审计。

## 6. 接口与页面

新增接口：

- `GET/POST /api/bazi/conversations`
- `GET/PATCH/DELETE /api/bazi/conversations/[id]`
- `GET /api/bazi/conversations/[id]/messages`
- `GET /api/bazi/conversations/[id]/context`
- `POST /api/bazi/conversations/[id]/respond`

新增页面：

- `/bazi/chat/[id]`

工作台包含可收缩的八字会话历史、当前固定命盘事实、基础问题快捷入口、有界高度的消息区和输入区。消息保存在 SQLite 中，刷新页面或重新启动本地服务后可以继续。

八字排盘页的已保存版本新增“开始基础解读”。尚未保存的一次性计算结果不能直接进入对话，从入口上保证模型始终引用可追踪版本。

## 7. 验收与回归

自动化测试覆盖：

- SQLite v24 迁移。
- 同版本恢复活动会话和显式新建会话。
- 消息顺序、刷新读取和上下文运行记录。
- 权威事实层、摘要层和最近消息层。
- 10 轮上限、Token 预算和摘要触发条件。
- 越界输出识别。
- 删除命盘版本后的完整级联删除。
- 生产构建与既有 M9-0、M9-1 回归。

运行方式：

```bash
npm run test:bazi-conversations
npm run test:bazi-foundation
npm run test:bazi-persistence
npm run build
```

## 8. 下一阶段：M9-3

M9-3 建议先建立旺衰、格局和用神的版本化方法论，不直接开放自由生成。需要明确月令权重、通根、透干、合冲刑害、调候与扶抑等规则的适用次序，记录流派差异和证据来源，并先通过公开案例测试。只有确定性规则结果稳定后，M9-2 的对话边界才按能力标识逐项开放。
