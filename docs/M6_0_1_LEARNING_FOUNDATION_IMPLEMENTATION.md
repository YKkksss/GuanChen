# M6-0/M6-1 紫微学习基础与命盘结构讲解实施说明

> 完成时间：2026-08-16
> 范围：学习内容契约、确定性七步读盘、来源追溯、学习模式界面、宫位笔记

## 1. 阶段目标

M6 的目标不是让 AI 临时生成一套教程，而是将项目已有的确定性排盘、规则和公版古籍组织成可审核、可版本化、可练习的教学系统。

M6-0 与 M6-1 先完成最小教学闭环：用户打开自己的单人命盘，切换到“学习模式”，选择任意宫位后，系统按照固定七步流程讲解当前命盘结构。第一版只教结构识别，不根据单一星曜或宫位作吉凶断言。

## 2. 内容分层

学习内容严格分为：

1. **程序事实**：宫位、地支、星曜、命身宫、四化、三方四正和空宫借星，由命盘快照确定。
2. **项目方法论**：规定读盘顺序、时间层级和解释边界。
3. **古籍参考**：引用项目已收录的公版古籍段落，并保存可跳转定位。
4. **现代教学说明**：解释“应该先看什么、为什么这样看、常见错误是什么”。

当前阶段没有让 AI 参与命盘结构计算或生成标准课程内容。

## 3. 七步读盘流程

`buildPalaceLearningLesson` 对任意宫位生成固定步骤：

1. 确定本宫及宫位干支。
2. 识别当前宫是否为命宫或身宫。
3. 分层读取主星、辅星和煞星。
4. 建立本宫、对宫和两个三合宫组成的三方四正。
5. 只读取命盘快照中的本命四化。
6. 空宫时读取程序保存的借对宫关系。
7. 明确当前没有加入大限、流年或现实经历。

每一步同时保存：

- 当前命盘事实。
- 教学说明。
- 知识点 ID。
- 来源 ID。
- 关联宫位。

## 4. 内容与来源契约

学习知识点包含：

- 分类和难度。
- 学习目标。
- 固定现代解释。
- 常见错误。
- 来源列表。
- 知识版本。

来源分为：

- `project_rule`：项目确定性算法与类型契约。
- `classic`：项目古籍库中的具体段落。
- `methodology`：项目学习方法论。

当前版本：

- 学习方法版本：`learning-method-v1`
- 知识内容版本：`learning-foundation-v1`

## 5. 页面交互

单人命盘顶部新增“学习模式”开关。

开启后：

- 默认选中命宫。
- 命盘继续使用原有三方四正连线和宫位高亮。
- 右侧 AI 解读面板替换为结构化学习面板。
- 用户可以从关系标签跳转到本宫、对宫和两个三合宫。
- 每个宫位拥有独立学习笔记。
- 古籍来源可以打开到具体章节和段落。

关闭学习模式后恢复原有 AI 对话，不改变聊天记录。

## 6. 数据持久化

SQLite 第 14 版迁移新增 `learning_notes`：

- `conversation_id`：所属单人命盘会话。
- `knowledge_point_id`：当前笔记类型。
- `palace_branch`：对应宫位地支。
- `content`：用户笔记，最多 4000 字。
- `created_at`、`updated_at`：创建和更新时间。

同一会话、知识点和宫位只有一条笔记。空内容表示清空笔记；删除命盘会话后笔记自动级联删除。

## 7. 接口

- `GET /api/conversations/[id]/learning?branch=宫位地支`
  - 返回当前宫位的确定性课程和已保存笔记。
- `PUT /api/conversations/[id]/learning/notes`
  - 新增、更新或清空当前宫位笔记。

## 8. 自动化验收

`npm run test:learning-foundation` 覆盖：

- 七步读盘顺序。
- 三方四正地支关系。
- 命宫识别。
- 空宫借对宫事实。
- 内容来源契约。
- 非法宫位保护。
- 笔记新增、更新和清空。
- 4000 字长度限制。
- 会话删除后的级联删除。
- SQLite 第 14 版迁移。
