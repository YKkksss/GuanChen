# M2-3 人生事件专项回溯分析实现说明

## 1. 阶段目标

本阶段把人生事件从“可记录、可挂接”升级为“可复盘、可追溯”。用户可以针对一条已经确认的现实事件，结合对应的流年、流月、流日确定性快照，生成一份可保存、可重新打开的 AI 回溯分析。

回溯分析不是重新算命，也不用于证明命理造成了现实事件。产品固定分开四层内容：

1. 已确认的现实事实。
2. 程序计算的运限结构。
3. 带条件措辞的谨慎解释。
4. 仍待用户核对的现实问题和其他解释。

## 2. 数据模型

SQLite 第 46 版迁移新增三张表。

### `event_ai_analyses`

每条人生事件最多对应一条回溯分析主记录，保存当前生效版本。删除事件或会话时自动级联删除。

### `event_ai_analysis_versions`

每次成功或失败的生成尝试形成独立版本，记录：

- 事件与运限依据指纹。
- 事件回溯引擎版本和提示词版本。
- 模型供应商和模型名称。
- 首次生成、手动重新生成、事实依据变化或模板升级等生成原因。
- 上一生效版本、生成状态、错误摘要和 Token 用量。
- 结构化报告 JSON。

已完成版本不会被覆盖。重新生成成功后，新版本成为当前生效版本，旧版本继续可读。

### `event_ai_analysis_evidence`

按版本和章节保存实际引用的证据快照。证据来源只能是：

- `user_confirmed`：用户确认的人生事件。
- `rule_engine`：程序生成的流年、流月、流日或区间摘要。

## 3. 缓存与失效策略

系统根据以下内容生成 SHA-256 依据指纹：

- 事件标题、分类、日期、描述、影响程度、来源和确认状态。
- 每条运限关联的快照 ID、层级、目标日期、关系和引擎版本。

处理规则：

1. 当前版本已完成、依据指纹一致、引擎与提示词版本一致：直接返回缓存，不调用模型。
2. 用户点击重新生成：创建 `manual_regenerate` 新版本。
3. 事件或运限关联变化：旧报告显示“依据已变化”，再次生成时创建 `source_changed` 新版本。
4. 引擎或提示词升级：创建 `template_upgraded` 新版本。
5. 三分钟内已有同一分析在生成：复用生成中版本，避免并发重复请求。

## 4. 证据收敛

单日事件通常包含一条事件事实，以及流年、流月、流日三个快照。日期范围可能覆盖很长时间，因此不会把全部年度细节无限发送给模型：

- 六个及以内的年度快照全部保留。
- 超过六个年度时，只保留最早两个和最晚两个年度。
- 另外生成区间摘要，记录覆盖年份数、首尾年份和收敛口径。
- 起止流月与起止流日始终保留。

这样既能保留边界证据，又能控制模型输入长度。

## 5. 输出结构与安全校验

模型必须输出合法 JSON，并完整包含：

- `confirmed_facts`：已确认的现实事实。
- `timing_structure`：当时的运限结构。
- `cautious_interpretation`：谨慎回溯解释。
- `open_verification`：仍待验证与继续观察。
- 摘要、现实复盘建议和待核对问题。

服务端不会直接相信模型输出，而会再次校验：

- 四个章节必须齐全，标题由系统固定。
- 证据 ID 必须真实存在，未知 ID 自动剔除。
- 现实事实章节只能引用用户确认事件。
- 运限结构章节只能引用程序证据。
- 存在运限快照时，结构章节必须至少引用一条程序证据。
- 出现“必然导致”“命中注定”“百分之百”等确定性因果表述时拒绝保存。
- 免责声明由服务端固定写入，模型不能修改。

## 6. API

```text
GET  /api/conversations/[id]/events/[eventId]/analysis
GET  /api/conversations/[id]/events/[eventId]/analysis?version=2
POST /api/conversations/[id]/events/[eventId]/analysis
```

首次生成：

```json
{ "regenerate": false }
```

手动重新生成：

```json
{ "regenerate": true }
```

人生事件列表接口额外返回轻量 `analyses` 摘要，用于展示“查看回溯 vN”“回溯需更新”等状态，不在列表请求中传输完整报告正文。

## 7. 页面交互

人生事件卡片新增“事件回溯”入口：

- 未生成：展示说明和生成按钮。
- 已生成：原地展开报告，无需离开时间轴。
- 已有多个版本：可切换历史版本。
- 事件依据变化：显示橙色过期提示，但不隐藏或删除旧报告。
- 重新生成期间：继续显示上一个成功版本。

报告页面同时展示用户确认的原始事件、程序证据标签、四层回溯正文、现实复盘建议、待核对问题和固定免责声明。

## 8. 验证

```bash
npm run test:event-analyses
npm run test:events
npm run test:event-candidates
npm run test:context
npx tsc --noEmit
npm run build
```

测试覆盖：

- 年月日证据构建和提示词边界。
- 首次生成与本地持久化。
- 相同依据下缓存复用且不调用模型。
- 手动重新生成和不可变版本历史。
- 事件修改后的过期识别与 `source_changed` 新版本。
- 历史版本 API 和无效版本处理。
- 未知证据过滤和确定性因果措辞拒绝。
- 跨会话访问隔离。
- 删除事件后的主记录、版本和证据级联清理。
