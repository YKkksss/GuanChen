# 统一账号服务验收记录

日期：2026-10-08（UTC+08:00）。版本：1.1.0-dev；分支：codex/user-accounts。

## 执行结果

- 原有业务全量回归及账号专项共 79 项全部通过，结构化结果见 qa-evidence/2026-10-08-accounts-regressions.json。第一次执行有两项备份断言仍指向旧目录；调整测试目标到当前账号目录后，全量重跑通过。
- 账号专项包含登录跳转规范化、账号恢复互不覆盖、维护窗口隔离、旧资料指定迁移、管理员会话撤销及密码校验期间的并发变更，最新 `npm run test:accounts` 为 **245 项通过**。该专项不关闭鉴权，使用真实合成账号与会话，并纳入上述全量回归。
- 最新生产构建上的 HTTP 专项 **203 项通过**，见 qa-evidence/2026-10-08-accounts-http.json；验证所有业务方法未登录拒绝、本人聊天持久化、跨账号读写拒绝、八字档案/版本/对话隔离、报告详情/PDF 下载隔离、跨站登录拒绝及改密/退出后的会话重放拒绝。
- 类型检查通过；最终生产构建通过，生成 80 个静态页面。测试构建目录与运行服务独立，不覆盖正式数据。

## 依赖复核

本次账号阶段复核发现 v1 冻结之后新增的依赖公告，完整审计原为 10 项。已将 Next.js 更新到 15.5.27、sharp 到 0.35.5、source-map-js 到 1.2.2，并再次验证构建与账号链路。当前生产依赖审计为 **0 项**，完整审计仍有 **7 项（5 高、2 中）**，均来自 Tailwind 3 构建工具链的 braces/选择器解析依赖，不将完整审计宣称为清零。

这些剩余告警涉及构建时不受信任的 glob/选择器输入，业务 API 不调用 Tailwind 编译器。npm 给出的消除方案是强制升级 Tailwind 4，会改变全站样式构建方式；本阶段保留已验证的 Tailwind 3，将该迁移作为独立维护项，构建环境只接受可信项目源文件。审计结构化结果见 qa-evidence/2026-10-08-accounts-audits.json。

对应来源：[Next.js 公告](https://github.com/advisories/GHSA-4jqv-mc3x-m676)、[sharp 公告](https://github.com/advisories/GHSA-wq5f-xc86-pv6w)、[braces 公告](https://github.com/advisories/GHSA-vfj7-8cjw-p6xm)。

## 浏览器真实操作

在独立生产 QA 服务上使用合成资料，通过实际页面完成：

1. 甲注册、录入出生资料、生成命盘、发送聊天、刷新后重读保存的对话。
2. 退出甲并注册乙，乙历史列表为空；直接访问甲的会话接口返回 404。
3. 在部署侧指定甲为管理员，登录管理页；搜索乙、停用/启用、变更管理员/普通用户，确认操作均经网页执行。
4. 账号设置拒绝错误当前密码，正确修改后回到登录页；用新密码按 Enter 登录，重新打开甲的原会话，记录保留。手机布局先切换“AI 解读”标签再查看聊天，隐藏面板不算内容丢失。
5. 最终构建再次退出甲、登录乙；退出后的页面无甲的聊天文本，乙列表无甲的命盘，直接请求仍为 404；见 qa-evidence/2026-10-08-accounts-switch.json。

登录、注册、账号设置和用户管理在桌面 1440px 与手机模拟 390px 共 8 个状态进行 axe WCAG 2 A/AA、2.1 AA 检查，无自动违规、无横向溢出、无页面 JavaScript 异常。结果见 qa-evidence/2026-10-08-accounts-browser.json。设置页保留各 2 个自动工具无法判定的人工复核项，不宣称 WCAG 认证或真实手机专项验收；HTTP 故意拒绝的 400/401/404 请求可能出现在浏览器网络日志中，不冒充页面运行异常。

## 数据与发布边界

测试目录、账号、密码、AI 和迁移资料均为合成。没有将真实旧资料自动分配给首个注册者，没有运行真实库恢复，也没有上传账号库或私密备份。

245 项专项包含两个用户并行读取、相同 ID 的生成/取消隔离、跨上下文流保存、个人备份不含统一身份库、甲恢复不覆盖乙或账号会话，以及本机命令将旧合成资料复制给指定账号且保留原库。密码派生期间发生改密或停用时，旧密码登录失败；并行改密不能覆盖已经提交的另一密码。新增接口必须继续使用 withAccount；缺少上下文的服务端数据库/报告访问会拒绝，不回退到旧共享数据。

本阶段实现集中式账号服务代码及单进程部署说明。正式域名、HTTPS 证书和云主机尚未部署，多实例部署及规模压测不在本次结果中。管理员初始化与真实旧资料归属按 ACCOUNT_SERVICE.md 执行。v1.0.0 标签继续指向已冻结版本。

## 登录与注册页重设计

重新设计品牌入口，保留观辰标识、中文字体和注册/登录字段。原页缺少品牌视觉，浅色表单下方露出暗色背景；新版统一铺满视口，使用独立生成的透明浑天仪主视觉、清晰的双栏布局与明暗主题，手机端优先展示表单。设计参数为 DESIGN_VARIANCE 6、MOTION_INTENSITY 3、VISUAL_DENSITY 4，仅用加载状态动画并尊重减少动态效果设置。

桌面 1440px 与手机模拟 390px 的登录/注册页、明暗主题共 8 个状态均通过 WCAG 2 A/AA 和 2.1 AA 自动检查，无横向溢出或页面 JavaScript 异常。实际点击完成合成账号注册、密码不一致校验、密码显示/隐藏、错误密码提示、退出及 Enter 登录恢复目标页面；补充注册关闭、改密成功通知、网络故障和代理返回非 JSON 时的中文提示、大写锁定事件检查。测试账号与资料只在独立临时目录。

发现并修正匿名跳转来源被 Next 内部规范化为 localhost 的问题，真实 HTTP 验证 localhost 和 127.0.0.1 均保留当前来源；局域网 Host 和 HTTPS 反向代理来源由请求边界回归覆盖。配置依据 [Next.js 15 中间件文档](https://nextjs.org/docs/15/app/api-reference/file-conventions/middleware#advanced-middleware-flags)，业务鉴权继续在各路由中执行。最终生产构建与类型检查通过，账号专项 245 项、最新生产服务 HTTP 专项 203 项及请求边界回归通过。

Lighthouse 13.5.0 对独立生产服务的本机样本：桌面性能/无障碍/最佳实践为 100/100/100，手机模拟为 99/100/100。桌面 LCP 约 0.6 秒，手机模拟约 2.0 秒，CLS 均为 0；属于本机实验室结果，不代表所有实际设备或网络。结构化结果见 qa-evidence/2026-10-08-auth-design.json，页面截图见 qa-evidence/2026-10-08-auth-login-desktop.png 与 qa-evidence/2026-10-08-auth-login-mobile.png。
