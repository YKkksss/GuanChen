## 1. 交付范围

本批完成 F11、F12：个人命盘、运限、合盘、八字聊天共用一套会话状态和生成生命周期。学习与聊天视图切换保留当前消息、输入草稿和生成任务；停止、失败及空回答都有可操作的恢复入口。

- 工作台持有 `ChatSession`，视图通过 `useConversationChat` 订阅，移除各面板重复的消息数组和流解析代码。
- 生成中可点击“停止生成”。服务端停止供应商请求，保存已收到的正文并标为 `cancelled`；首字前停止显示“尚未收到正文”。
- 失败回答可“重试这条回答”，完成或停止的回答可“重新生成”；新回答单独保存，保留旧回答。
- “恢复原问题”回填输入框。有其他草稿时，在页面内选择“替换草稿”或“保留草稿”。快捷分析和重试不会清空当前草稿。
- 失败、停止和部分正文在刷新后恢复；重启遗留的 `streaming` 消息按既有规则变为 `failed / interrupted_by_restart`。

本批没有展开 F13–F25，没有实现报告长任务恢复或多实例任务调度。

## 3. 持久化与接口契约

SQLite 新增 **v47**，在 `messages`、`bazi_messages` 中加入：

| 字段 | 用途 |
|---|---|
| `reply_to_message_id` | 本回答对应的原用户问题 |
| `retry_of_message_id` | 本次重新生成针对的旧回答 |
| `request_id` | 请求标识，非空值有唯一索引 |

普通发送提交 `message` 和 `requestId`。重试另带 `retryOfAssistantId`，服务端只接受同一会话的终态回答，并从数据库恢复原问题及专题、宫位、四化、运限日期等参数。重试不会再次插入用户问题，也不允许客户端篡改旧问题的参数。旧消息优先通过上下文运行记录、其次通过前一用户消息兼容恢复。

响应头返回 `X-User-Message-Id`、`X-Assistant-Message-Id`、`X-Chat-Request-Id`。客户端按任务及消息 ID 更新，避免串写其他回答。同会话并发或重复请求标识返回 409。

停止接口接收 `{ requestId }`；已完成的回答不能被迟到的停止请求改写。停止先于提交到达时，服务端会短暂记住该请求，阻止它随后启动供应商调用。

单命盘导入副本重映射问答及重试关系，同时清空原 `request_id`，避免跨副本引用或唯一索引冲突。

**备份兼容边界：**项目现有恢复/导入策略要求包版本与当前数据库结构一致，本批保持该策略。因此 v46 旧包不能直接导入 v47；需要在匹配的旧版环境恢复后，再升级应用数据库。已有部署数据库可自动从 v46 升至 v47。不要删除旧备份，也不要承诺尚未实现的跨版本直接恢复。

## 4. 生成终态与 AI 边界

- 浏览器断开、主动停止均传递 `AbortSignal` 到供应商请求；关闭工作台会发送取消并中止本页请求，学习视图切换不卸载工作台任务。
- 紫微/合盘收到约 300 字新增正文或达到约 800 毫秒时持久化部分内容，终态再保存完整已收内容。
- 上游必须明确发出 `[DONE]` 才记为完成。提前断流记 `failed / incomplete_stream`，保留正文，不伪装成成功。
- 180 秒未结束记 `failed / generation_timeout`，释放任务并中断上游。
- 八字仍在完整生成后执行 `findBaziOutputViolations`，审查后才展示正文；停止不能绕过输出审查，拦截标记 `output_guard_replaced` 保留。
- 只有成功完成才启动摘要维护；个人命盘/运限的普通问题仍可进入人生事件候选提取，候选需要用户确认。

任务句柄只在部署进程中共享，适用于项目现有的本地单实例模式。多进程/多机器部署需要单独引入共享调度。输入草稿保证当前工作台内切换保留；浏览器刷新后的原问题从数据库恢复，不承诺未发送草稿跨刷新持久化。
