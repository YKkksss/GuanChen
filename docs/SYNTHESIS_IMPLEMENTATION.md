# 紫微与八字合参实施记录

后续进展：已增加动态阶段的双体系运限、流年与流月对照，见 [动态合参实施记录](./SYNTHESIS_DYNAMIC_IMPLEMENTATION.md)。下文保留本命第一版的原范围和验收历史。

开发日期：2026-10-12（UTC+08:00）。第四模块第一版，属于 `1.1.0-dev`，冻结的 `v1.0.0` 保持原版本。本模块只比较本命原局，下一模块是择日工具。

## 使用流程

从首页或工作台“紫微八字合参”进入 `/synthesis`，录入一份公历出生日期、准确时分、性别与名称，可先预览时间口径，再建立双盘。保存后进入综合、事业、感情、财运、学习五个主题，先查看两套确定性依据，再手动生成合参解读。

报告包含紫微视角、八字视角、共同观察、不同观点与待核条件、行动与复核建议。每节的引用可展开，引用保留所属体系，不能用八字证据替代紫微证据。相似观察不构成独立事实互证；没有充分共通依据时允许说明不足。每个主题独立保存历史版本，重新生成保留旧版，生成失败仍可回看。

从已有紫微命盘的“紫微八字合参”进入时只预填名称、日期、性别与经度，用户需核对原始公历日期并补充准确时间。原盘可能保存过换日或简化太阳校正后的日期，因此不从旧时辰猜测准确时分。本入口创建独立的新紫微命盘和八字版本，原盘仍可使用。

## 时间口径

- 第一版统一按北京时间标准时 UTC+08:00 输入，内部固定 `Etc/GMT-8`。其他时区及历史夏令时记录须先换算；本版没有宣称支持任意时区合参。
- 真太阳时复用现有精细时间服务，含经度与均时差，两盘使用同一次有效日期和时刻，不再叠加旧紫微简化校正。
- 时辰由校正后的时分确定。有效时刻 23 点且采用次日口径时，紫微使用次日早子时日期，八字保留有效时刻并采用次日日柱；采用当日口径则保留当日。
- 紫微年月按农历，八字年柱按立春、月柱按精确节界。两盘的年、月标签允许不同，不以标签强行统一规则。
- 时辰未知时只开放标准时：紫微子时试排，八字省略时柱，其他柱的代表时刻仍有节界不确定性。页面与报告明确降级，不能确定命宫或最终喜忌。
- 校正或换日超出 1900–2100 年范围时拒绝创建，不留下部分档案。

## 数据与安全

业务库升级至 v51，新增 `synthesis_sessions` 与 `synthesis_report_versions`。建立双盘和合参关系在同一事务内完成，相同规范资料与来源重复提交复用已建立的合参。五个主题各有版本序列，同一主题只允许一个生成任务，超过 150 秒恢复失败状态，迟到响应和错误任务标识不能覆盖新版本。

新接口全部使用统一账号验证，资料位于当前账号数据库。匿名拒绝，跨账号读取、写入、来源预填和删除均不可用；写操作继续经过同源校验。供应商错误脱敏，AI 不自动调用，完整生成有 100 秒超时与取消处理。

合参中心的“移除”只删除该份合参与报告，独立紫微、八字档案仍保留；页面确认框明确说明。删除任一关联的新底层命盘会级联删除合参与报告，删除最初的旧来源盘仅解除来源链接。

整库备份包含双盘、合参关系和版本。单紫微命盘包不包含依赖独立八字版本的合参，导出边界有明确提示。旧版备份和单盘包仍需按原有严格版本策略，在对应版本还原后升级，不能直接作为 v51 文件导入。

## 验收边界

专项测试使用独立临时账号、合成出生资料与本机模拟 AI，覆盖时辰、闰年、晚子时、真太阳时跨日、春节与立春差异、输入校验、事务回滚、缓存、主题隔离、双侧引用、版本失败恢复、并发、取消、账号隔离、删除语义、备份恢复及 v50 迁移。

浏览器功能验收使用运行中的真实应用和独立数据库，模拟供应商只负责返回可检查的报告格式。该验收不等于真实模型的命理解释质量已被校核，也不替代实际手机及外部主机测试。八字精细调候规则继续沿用第三模块已说明的覆盖范围。
