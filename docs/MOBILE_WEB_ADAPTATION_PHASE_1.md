# 移动端网页版适配第一阶段实施记录

## 1. 阶段目标

本阶段先解决手机和平板上最影响核心使用流程的问题，不改变已有业务路由、数据结构和命理功能：

- 手机宽度下可以从首页完成起盘。
- 起盘页的历史记录不再挤占首屏。
- 命盘可以在手机宽度内完整查看。
- 命盘与 AI 解读可以直接切换，不需要滚过整张命盘寻找聊天区。
- 平板竖屏使用聚焦视图，平板横屏尽量同时显示命盘与 AI 解读。
- 二级功能页面不再使用超长横向导航条。

## 2. 响应式分层

| 屏幕范围 | 主要布局 |
| --- | --- |
| 0-520 像素 | 手机紧凑布局，命盘与 AI 解读分视图，表单字号防止移动浏览器自动缩放 |
| 521-900 像素 | 手机大屏与平板竖屏布局，历史抽屉和命盘／解读切换 |
| 901-979 像素 | 平板横屏过渡布局，保留紧凑历史栏并让内容单列滚动 |
| 980-1080 像素 | 平板横屏双栏布局，历史默认收起，命盘与 AI 解读并列 |
| 1081 像素以上 | 原有桌面三栏工作台 |

## 3. 已完成内容

### 3.1 全局移动端基础

- 显式声明设备宽度、初始缩放和安全区域适配。
- 页面根节点统一限制横向溢出，并使用动态视口高度。
- 手机端表单输入字号统一到 16 像素，避免 iOS 聚焦输入框时自动放大页面。
- 首页关键入口和菜单按钮统一到至少 44 像素的触控高度。

### 3.2 二级页面导航

- 820 像素以下将原有横向滚动功能目录替换为左侧抽屉。
- 顶部保留首页入口和“功能”按钮。
- 抽屉继续显示全部既有功能，保持导航名称和跳转地址不变。
- 支持点击遮罩、点击导航项和按 Escape 键关闭。
- 抽屉打开时锁定背景滚动，避免双层页面同时移动。

### 3.3 命盘工作台

- 1080 像素以下默认收起历史栏，减少非核心区域占用。
- 900 像素以下将历史记录改为抽屉，并在命盘页头提供独立入口。
- 900 像素以下增加“查看命盘／AI 解读”切换，不再纵向串联两个长区域。
- 手机命盘取消 540 像素最小宽度，按当前可用宽度完整缩放十二宫布局。
- 手机端压缩宫位文字、中央摘要和时间导航，但保留全部宫位、四化和年份操作。
- 980-1080 像素横屏下使用紧凑历史栏，并恢复命盘与 AI 解读双栏展示。
- AI 解读区域在手机端按动态视口计算高度，消息列表独立滚动，输入区始终位于面板底部。

### 3.4 起盘流程

- 手机和平板竖屏不再把历史列表堆叠在起盘表单上方。
- 起盘表单扩大可用宽度，减少双层容器造成的横向空间浪费。
- 首页和独立起盘页保留原有字段顺序、校验逻辑和本地保存行为。

## 4. 本阶段验收基线

本阶段使用以下典型视口进行验证：

- 手机：390 × 844。
- 平板竖屏：768 × 1024。
- 平板横屏：1024 × 768。

验收要求：

1. 页面根节点无横向溢出。
2. 首页起盘入口和移动菜单可以触控操作。
3. 历史抽屉默认关闭，打开后不改变当前页面地址。
4. 手机命盘十二宫完整落在内容容器内。
5. 命盘和 AI 解读切换后仅显示当前视图。
6. 平板横屏可以同时看到命盘与 AI 解读。
7. 二级页面功能抽屉包含全部既有导航项。

## 5. 后续移动端阶段

第一阶段完成核心入口和工作台骨架。下一阶段继续按业务使用频率覆盖：

1. 合盘工作台和双方资料录入。
2. 八字命盘、八字对话和大运流年页面。
3. 年度报告、人生时间轴和事件录入。
4. 生时校正的候选矩阵与事件表单。
5. 学习、练习、案例和古籍阅读页面。
6. 数据保险箱、提醒中心和长表单弹窗。
7. 移动端性能、离线能力和添加到主屏幕体验。

每一阶段继续使用手机、平板竖屏和平板横屏三档真实视口验收，并保持桌面端回归检查。
