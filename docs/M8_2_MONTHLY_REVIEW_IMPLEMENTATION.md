# M8-2 月度复盘工作流实施说明

## 1. 阶段目标

M8-2 把 M8-1 的月度提醒扩展成完整的现实反馈工作流。用户不再只是“完成一条待办”，而是可以留下可验证、可追踪、可选择沉淀的月度记录。

本阶段遵循四条原则：

1. 现实事实与既往预测分开保存。
2. 草稿不进入模型上下文。
3. 只有用户明确确认后，内容才可以写入人生事件或长期记忆。
4. 同一单人命盘、同一月份只保留一份复盘，避免重复统计。

## 2. SQLite v22 数据模型

新增 `monthly_reviews` 表，核心字段包括：

- 所属单人命盘与复盘月份。
- 可选的来源提醒实例。
- 草稿或已确认状态。
- 本月重要事件。
- 事业、感情、健康、财务四项 1 至 5 分自评。
- 上月原始预测、本月实际结果和兑现判断。
- 需要修正的判断与下月观察重点。
- 确认后生成的人生事件编号和长期记忆编号。
- 确认时间、创建时间和更新时间。

约束与索引：

- `conversation_id + review_month` 唯一。
- 一个提醒实例最多关联一份复盘。
- 删除来源提醒时保留复盘，只清空来源编号。
- 删除命盘时级联删除其复盘。
- 删除已经沉淀的人生事件或记忆时，复盘仍保留，只清空对应编号。

## 3. 复盘内容结构

### 3.1 现实记录

- 本月发生的重要事件。
- 本月实际情况。
- 事业、感情、健康和财务自评。

### 3.2 预测检验

- 上月预测或判断保留原意，不能与现实结果共用一个字段。
- 兑现结果分为暂不判断、基本符合、部分符合和明显不符。
- 判断修正单独记录，供未来分析识别曾经的偏差。

### 3.3 后续观察

- 下月观察重点鼓励使用可验证表达。
- 不要求给出新的绝对预测。

## 4. 状态流转

```text
创建或打开当月复盘
        ↓
      草稿
  ├─ 可重复保存
  ├─ 可删除
  └─ 不进入 AI 上下文
        ↓ 用户确认
      已确认
  ├─ 内容锁定
  ├─ 自动完成来源提醒
  ├─ 可选写入长期记忆
  └─ 可选生成已确认人生事件
```

确认接口具有幂等性。重复调用不会再次生成人生事件或长期记忆。

## 5. 用户确认与数据沉淀

确认弹窗提供两个独立选项：

### 5.1 保存为长期记忆

将本月实际情况、判断修正和下月观察重点组成一条带复盘来源键的长期记忆。后续只有在相关问题中，Context Builder 才可能按现有记忆策略召回。

### 5.2 同步重要人生事件

用户必须主动开启并填写事件标题、事件类型和影响程度。系统使用复盘月份作为月份级日期，创建用户已确认的人生事件，并通过现有运限服务关联当年流年快照。

两个选项均未勾选时，复盘仍可确认，只保存在月度复盘表中。

## 6. 页面与提醒联动

新增页面 `/reviews`：

- 选择单人命盘和复盘月份。
- 开始新复盘或继续已有草稿。
- 左侧查看历史草稿和已确认复盘。
- 填写五段式结构化复盘。
- 查看已确认记录及沉淀状态。

提醒中心新增：

- 顶部“月度复盘”入口。
- 月度提醒实例的“开始月度复盘”入口。
- 月度提醒规则可以选择关联单人命盘。
- 从提醒进入时自动携带月份、提醒实例和已关联命盘。

## 7. 服务接口

- `GET /api/monthly-reviews`：查询复盘列表。
- `POST /api/monthly-reviews`：创建或返回同命盘同月份已有复盘。
- `GET /api/monthly-reviews/:id`：读取单份复盘。
- `PATCH /api/monthly-reviews/:id`：更新草稿。
- `DELETE /api/monthly-reviews/:id`：删除草稿。
- `POST /api/monthly-reviews/:id/confirm`：确认并按用户选择执行数据沉淀。

已确认记录拒绝修改和删除，保证后续上下文与事件时间轴引用稳定。

## 8. 自动化验证

新增 `npm run test:monthly-reviews`，覆盖：

- SQLite v22 迁移。
- 同命盘同月份草稿幂等。
- 四项评分和预测、现实字段分离。
- 确认后内容锁定。
- 用户授权后生成事件与记忆。
- 生成事件自动关联流年数据。
- 重复确认不重复沉淀。
- 确认后自动完成来源提醒。
- 非法月份与确认后修改拦截。

同时继续执行 M8-0、M8-1 测试，避免提醒基础和提醒中心接口发生回归。

## 9. 阶段结论

M8 已形成“规则生成提醒—提醒进入复盘—草稿隔离—用户确认—现实数据沉淀”的完整本地闭环。外部推送和跨设备同步仍不在本地部署版本的默认范围内。

按照产品路线图，下一大阶段为 M9 八字体系。进入算法开发前应先完成 M9-0 方法论、流派边界、历法输入和公开校验样例的立项设计，不能直接让 AI 自由生成四柱结果。
