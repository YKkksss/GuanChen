# M5-2 校时事件证据与候选年度事实矩阵实施说明

> 完成日期：2026-08-16
> 范围：人生事件证据快照、事件去重、候选年度事实、输入门槛和基础接口
> 不包含：规则命中、相对证据指数、候选排序、比较工作台和 AI 校时结论

## 1. 阶段结果

M5-2 已完成“候选命盘”与“已发生人生事件”之间的确定性数据连接。用户可以把 M2 人生事件关联到校时会话，也可以直接录入一条符合 M2 契约的事件。系统会冻结事件证据，并为每个候选命盘生成事件年份的大限、流年命宫、流年四化、关键宫位和专题宫位交集。

```text
M2 人生事件或校时直接录入
→ 不可变事件证据快照
→ 事件去重与评分资格判断
→ 提取事件涉及年份
→ 候选命盘 × 事件年份
→ 复用 M1 年度运限引擎
→ 专题宫位事实矩阵
→ 为 M5-3 规则评分提供只读事实
```

本阶段没有生成“支持”“冲突”“得分”或“排名”。这些判断必须在 M5-3 由版本化规则统一完成。

## 2. 事件证据快照

每条校时事件保存：

- 来源人生事件编号；直接录入时可以为空。
- 标题、分类、起止日期、日期精度、说明和影响程度。
- 证件记录、多人确认、单人回忆、对话抽取或未确认等证据质量。
- 用户是否明确确认、是否具备后续评分资格。
- 来源事件更新时间、方法论版本和创建时间。
- 基于分类、日期和标准化标题生成的 SHA-256 去重键。

来源事件只是输入来源，不是校时历史的唯一载体。关联完成后，即使原事件被编辑或删除，校时证据快照和已经生成的年度事实仍然保留，保证历史可解释。

## 3. 评分资格与最低门槛

事件只有同时满足以下条件，才标记为 `scoreEligible`：

1. 用户已经确认。
2. 证据质量不是“未确认”。
3. 日期精度不是“不详”。
4. 事件分类已经映射到标准专题宫位；未映射的自定义分类不能评分。

准备状态按 M5-0 方法论计算：

- 最低 3 个可评分事件。
- 最低覆盖 2 个可评分类别。
- 推荐 5 个事件、3 个类别。

门槛检查只表示“是否允许进入规则评估”，不代表结果可靠，也不产生分数。

## 4. 候选年度事实矩阵

矩阵的最小计算单位是：

```text
一条校时事件 × 一个候选命盘 × 一个事件年份
```

每个单元保存完整 `AnnualTransitSnapshot`，并提取：

- 事件年份所在大限及本命宫位。
- 流年命宫落入的本命宫位。
- 流年关键宫位与事件主、辅助宫位的交集。
- 流年四化所在本命宫位与事件专题宫位的交集。
- 候选命盘指纹、运限引擎版本、方法论版本和输入指纹。

范围事件逐年生成，并区分 `starts_in`、`continues_in` 和 `ends_in`。为防止误填超长范围造成大量命盘计算，校时模块限制单条范围最多 30 年；更长经历应拆成具有辨识度的起点、转折点或终点事件。

## 5. 去重和不可变策略

- 同一校时会话中，相同分类、日期、标题的事件不能重复加入。
- 标题在去重前执行 Unicode 规范化并移除空白和标点。
- 更新证据质量或确认状态不会重算年度命盘事实。
- 修改来源事件不会静默覆盖既有快照；需要使用新证据时应移除后重新关联。
- 删除校时事件会级联删除其候选年度事实。
- 删除校时会话会级联删除全部事件证据和事实。
- 删除来源对话只解除会话来源关系，不删除独立校时记录。

## 6. SQLite 迁移

数据库迁移版本升级到 `10`，新增：

- `rectification_event_evidence`：事件证据快照、质量、确认状态、评分资格和去重键。
- `rectification_candidate_event_facts`：候选、事件年份、年度快照、专题事实和版本指纹。

事件证据及其全部候选事实采用同一事务写入，避免发生“事件已创建但候选矩阵只生成一部分”的状态。

## 7. 接口

| 方法 | 路径 | 作用 |
| --- | --- | --- |
| `GET` | `/api/rectifications/:id/events` | 获取事件证据、年度事实和准备状态 |
| `POST` | `/api/rectifications/:id/events` | 关联 M2 事件或直接录入事件 |
| `PATCH` | `/api/rectifications/:id/events/:eventId` | 更新证据质量和用户确认状态 |
| `DELETE` | `/api/rectifications/:id/events/:eventId` | 移除事件并级联删除事实 |
| `GET` | `/api/rectifications/:id/event-matrix` | 获取完整候选年度事实矩阵 |

接口不接受客户端上传年度运限、专题宫位交集或评分，所有核心事实均由服务端重新计算。

## 8. 自动验证

新增 `npm run test:rectification-events`，覆盖：

- M2 事件关联和直接事件录入。
- 相同事件去重。
- 单年、月份、日期范围和日期不详事件。
- 每个候选的年度运限及专题事实生成。
- 已确认事件数、类别数、最低门槛和提示信息。
- 证据质量与确认状态更新。
- 来源事件修改后的快照不变性。
- 来源事件删除、事件移除和来源对话删除的级联策略。
- 数据库迁移版本与输入指纹。

## 9. 下一阶段：M5-3

M5-3 将在本阶段事实矩阵之上实现版本化规则评估：

1. 原始时间窗口匹配。
2. 大限专题宫位匹配。
3. 流年命宫专题匹配。
4. 年度关键宫位和四化专题匹配。
5. 多层汇合、候选区分度过滤和中性保护。
6. 事件贡献封顶、类别占比封顶和相对证据指数。
7. 留一事件稳定性、并列候选和低置信度保护。
