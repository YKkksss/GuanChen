# M2-8 密码保护的认证加密备份实现说明

## 1. 阶段目标

普通 `.ziweibackup` 适合当前设备上的快速恢复，但文件一旦被复制到移动硬盘、共享目录或云盘，能够拿到文件的人也能读取其中的 SQLite 和报告附件。本阶段新增 `.ziweibackupx` 加密格式，使用户可以在离开本机边界前为完整备份设置密码。

原有普通备份、自动备份、健康检查和整库恢复继续兼容；加密层只包装现有经过验证的 `.ziweibackup`，解密后仍走同一套清单、指纹、SQLite、外键、版本和附件预检，不建立第二套恢复逻辑。

## 2. 密码学方案

- 密钥派生：`scrypt`
- 工作参数：`N=32768`、`r=8`、`p=1`
- 盐：每份文件独立生成 16 字节密码学随机盐
- 密钥：256 位
- 认证加密：AES-256-GCM
- IV：每份文件独立生成 12 字节密码学随机值
- 认证标签：128 位
- 密码规范：Unicode NFC 归一化，最少 10 个字符，最多 256 个字符／1024 字节

实现依据 Node.js 官方 `crypto` 文档：通过 `scrypt` 派生密钥，使用 `createCipheriv`／`createDecipheriv`，IV 应不可预测且唯一；GCM 解密必须设置认证标签，密文被修改或标签不匹配时 `final()` 会失败。

参考：[Node.js Crypto 官方文档](https://nodejs.org/api/crypto.html)

## 3. 二进制文件格式

`.ziweibackupx` 不使用整体 Base64 JSON，避免让大文件额外膨胀约三分之一。文件按以下顺序组成：

```text
固定魔数 ZIWEIBACKUPX1\n
4 字节大端序加密头长度
UTF-8 JSON 加密头
AES-GCM 密文
16 字节 GCM 认证标签
```

加密头只记录解密所必需的非敏感元数据：格式版本、算法、盐、IV、scrypt 参数、内层文件名、内层字节数和 SHA-256。完整加密头作为 GCM 的附加认证数据，因此即使攻击者只修改算法参数、文件名、体积或指纹，也会在认证阶段失败。

## 4. 双层校验

加密备份恢复包含两层独立保护：

### 4.1 外层认证加密

1. 检查魔数、文件上限和头长度。
2. 严格限定算法与 scrypt 参数，拒绝攻击者注入超高资源参数。
3. 校验盐和 IV 的 Base64 编码与固定长度。
4. 使用密码派生密钥并验证 GCM 认证标签。
5. 密码错误或密文被修改统一返回同一错误，不向外暴露判断差异。

### 4.2 内层业务备份预检

1. 解密结果的字节数和 SHA-256 必须与加密头一致。
2. 再执行原有 `.ziweibackup` 的 Gzip、清单、数据库、记录数、外键、PDF 和 schema 版本检查。
3. 只有两层全部通过，页面才开放整库恢复确认。

## 5. 密码生命周期

- 密码仅保存在当前浏览器组件状态和当前 HTTP 请求内存中。
- 不写入 SQLite、自动备份策略、浏览器存储、文件名或日志。
- 导出下载完成后立即清空页面中的两次密码输入。
- 恢复成功后立即清空解锁密码。
- 系统不提供密码找回或后门；遗忘密码意味着该文件无法恢复。

## 6. 页面与接口

数据保险箱新增“加密导出”入口。用户必须输入两次一致且符合长度要求的密码，才可生成 `.ziweibackupx`。

选择恢复文件时，页面会同时识别扩展名和文件魔数：

- 普通备份：选择后直接预检。
- 加密备份：先展示密码输入，再执行“解密并预检”。
- 预检通过后明确显示“已认证解密”，再要求输入原有整库覆盖确认文字。

接口变化：

- `POST /api/backups/export/encrypted`：生成加密完整备份。
- `POST /api/backups/inspect`：新增可选 `password`，自动识别普通或加密格式。
- `POST /api/backups/restore`：新增可选 `password`，加密文件先认证解密再恢复。

## 7. 自动化验收

独立临时数据库测试覆盖：

- 加密文件魔数和扩展名正确。
- 密文中搜索不到命盘标题明文。
- Unicode 组合形式不同但语义一致的密码可以通过 NFC 归一化解密。
- 正确密码可还原并通过现有完整预检。
- 错误密码和任意密文篡改均被 GCM 认证拦截。
- 弱密码在服务端被拒绝。
- 加密导出、上传预检和整库恢复接口完整跑通。
- 恢复后 SQLite 完整性与外键检查通过。

## 8. 安全边界

- 加密保护的是静态备份文件，不能防御已经控制当前电脑、浏览器或运行进程的攻击者。
- 不会自动上传云盘；用户决定把加密文件复制到哪里。
- 密码强度仍取决于用户选择，长度门槛不能替代唯一且难猜的密码短语。
- 当前内存式实现限制加密包最大约 130 MB；未来数据显著增长后应升级为流式容器。
- 跨设备自动同步仍需单独解决授权、远端删除、冲突、限流和供应商锁定问题。
