# M5-1 时间换算、校时会话与候选命盘实施说明

> 完成日期：2026-08-16
> 范围：历史民用时间换算、十三候选命盘、稳定指纹、SQLite 持久化和基础接口
> 不包含：人生事件绑定、候选评分、排序、工作台页面和 AI 校时结论

## 1. 阶段结果

M5-1 已把 M5-0 的方法论落成可运行的数据底座。系统现在可以创建一条独立的校时会话，保存原始出生时间证据，生成 2 至 13 个候选命盘，并在服务重启后恢复全部候选。

完整链路如下：

```text
出生日期、地点和民用时间
→ IANA 历史时区解析
→ 夏令时重复／跳过时刻检查
→ 经度修正 + NOAA 均时差
→ 地方视太阳时与跨日结果
→ 早子、丑至亥、晚子十三时段
→ iztro 候选命盘
→ 稳定结构指纹与重复候选标记
→ SQLite 原子保存
```

## 2. 时间换算设计

`lib/rectification/time-service.ts` 新增独立的版本化换算服务，没有修改旧单盘页面的简化经度校正，因此现有历史命盘不会被静默改变。

每个精确或近似时间快照保存：

- 原始民用日期、时间、IANA 时区和经度。
- 所有合法 UTC 候选、最终采用的 UTC 时刻和历史偏移。
- 均时差、经度修正、总修正分钟数。
- 最终视太阳日期、时间、跨日量和十三时段映射。
- 时间策略版本、运行时 tzdb 版本和人工核验警告。

### 2.1 夏令时边界

- 民用时间处在“春季跳过”区间时，系统拒绝换算并要求核对记录。
- 民用时间处在“秋季回拨”重复区间时，系统返回两个合法偏移；创建会话前必须明确选择一个偏移。
- 1970 年前的时间会保留人工核验警告，因为历史时区资料可能不完整。

自动测试特意使用 1990 年北京案例。IANA 数据返回当时中国大陆夏令时 `UTC+9`，证明服务使用的是出生当年的法定时间，而不是把今天的 `UTC+8` 套到所有历史日期。

## 3. 候选命盘

默认生成十三个候选：

- 早子时使用 iztro 引擎序号 `0`。
- 丑至亥使用 `1` 至 `11`。
- 晚子时使用 `12`，与早子分别保存。

用户也可以提交 2 至 13 个不重复的候选时段。每个候选保存实际排盘日期、跨日量、命盘快照和 SHA-256 结构指纹。指纹排除当前年龄等随年份变化的展示状态；结构完全相同的候选仍保留记录，但通过 `duplicateOfCandidateId` 标记，后续评分时不会重复计算。

当精确时间换算发生跨日时，与换算时段相符的候选使用最终视太阳日期排盘，并把跨日量写入指纹。范围和时段型证据暂不强行选择单一换算结果，留给 M5-2 的候选范围服务处理。

## 4. SQLite 数据模型

数据库迁移版本升级到 `9`，新增：

- `rectification_sessions`：基础出生信息、原始时间证据、换算快照、方法论与引擎版本、状态和最终候选引用。
- `rectification_candidates`：时段、排盘日期、跨日量、命盘快照、结构指纹、重复关系及预留评分字段。

关键约束：

- 会话和候选在一个事务中创建，避免只写入一半。
- 同一会话的时段不可重复。
- 删除会话会级联删除候选。
- 删除来源对话只解除关联，不删除独立校时记录。
- 候选分数初始为空、置信度固定为低，不在没有事件证据时伪造排名。

## 5. 接口

| 方法 | 路径 | 作用 |
| --- | --- | --- |
| `POST` | `/api/rectifications` | 创建会话并生成候选 |
| `GET` | `/api/rectifications` | 按状态或来源对话列出会话 |
| `GET` | `/api/rectifications/:id` | 恢复会话和完整候选 |
| `DELETE` | `/api/rectifications/:id` | 删除会话并级联删除候选 |

列表接口支持 `status`、`conversationId` 和 `limit`，最多返回 100 条。接口只接收出生事实和候选范围，不接收外部传入的命盘快照、分数或引擎版本，避免客户端伪造核心事实。

## 6. 自动验证

新增 `npm run test:rectification-sessions`，覆盖：

- IANA 历史偏移和 NOAA 均时差换算。
- 美国夏令时回拨重复时刻和春季不存在时刻。
- 早子至晚子十三引擎序号。
- 候选命盘、排盘日期、指纹和 SQLite 恢复。
- 无效日期、候选数不足和证据字段校验。
- 数据库迁移及会话删除级联。

同时继续运行 M5-0 方法论测试、TypeScript 类型检查和生产构建。

## 7. 下一阶段：M5-2

下一阶段应接入“已确认人生事件证据”，但仍不开始评分：

1. 校时会话关联 M2 人生事件，保存证据质量和日期精度快照。
2. 为每个候选生成事件年份的大限、流年与关键宫位事实。
3. 对同一现实事件去重，防止重复录入放大权重。
4. 提供事件新增、确认、解除关联和候选事件矩阵接口。
5. 把确定性事实准备好后，M5-3 再实现可审计规则评分与稳定性排序。
