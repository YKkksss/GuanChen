# M3-3 报告确认、备注与人工修订实现说明

> 实施日期：2026-08-31  
> 数据库版本：SQLite v44  
> 适用报告：专题报告、合盘报告、年度报告、出生时辰校正报告

## 1. 本阶段目标

M3-2 已经解决“不同生成版本之间发生了什么变化”，M3-3 进一步解决用户拿到报告后的三个问题：

1. 用户是否认可当前报告版本。
2. 用户有哪些现实反馈或待核实备注。
3. 用户能否调整 AI 的表达，同时继续保留原始生成内容和审计依据。

本阶段采用“AI 原始版本不可变，用户修订独立覆盖显示”的设计。用户修改不会直接写回 `report_versions`、`transit_report_versions` 或 `rectification_report_versions`，因此原始模型输出、证据映射和版本对比能力不会被破坏。

## 2. 产品行为

四类报告统一提供“报告确认与个人修订”面板：

- `未确认`：当前版本尚无人工处理记录。
- `修订中`：已保存备注或人工修订稿，尚未确认。
- `已确认`：用户明确认可当前报告版本。
- `待调整`：用户认为当前版本仍需修改或继续核实。
- `个人备注`：记录现实反馈、补充事实和待观察事项，最多 4000 字。
- `编辑人工副本`：基于当前显示内容创建可编辑副本。
- `恢复 AI 原文`：删除当前版本的人工正文覆盖，重新显示原始生成内容。

所有状态和内容严格绑定“报告来源 + 报告版本 ID”。重新生成 v2 后，v1 的确认、备注和人工修订仍保留，但不会自动套用到 v2。

## 3. 人工编辑边界

### 3.1 可以修改

- 报告摘要。
- 各章节解释正文。
- 执行清单。
- 待确认问题。
- 年度报告完整正文。

### 3.2 系统锁定

- 报告与章节标题。
- 章节键和结构顺序。
- `evidence` / `synthesis` 依据类型。
- 结构化证据 ID 映射。
- 免责声明。
- 引擎、提示词、模型和生成原因元数据。

服务端会根据原始报告重新组装结构化修订稿，即使客户端提交了伪造的章节标题、依据类型或免责声明，也不会覆盖系统审计字段。

## 4. 数据模型

SQLite v44 新增 `report_user_revisions`：

| 字段 | 作用 |
|---|---|
| `source_kind` | `topic`、`heming`、`annual`、`rectification` |
| `source_report_id` | 报告主记录 ID |
| `source_version_id` | 不可变报告版本 ID |
| `source_version` | 用户可见版本号 |
| `review_status` | `draft`、`confirmed`、`needs_revision` |
| `note` | 用户个人备注 |
| `edited_content_json` | 结构化或纯文本人工修订稿 |
| `edit_revision` | 人工修订稿递增编号 |
| `confirmed_at` | 最近一次确认时间 |

四组删除触发关系确保来源版本被级联删除时，对应用户修订记录同步清理，不产生孤儿数据。

## 5. API

统一接口：`/api/report-user-revisions`

### GET

查询参数：

- `sourceKind`
- `reportId`
- `version`

返回当前报告版本的用户修订记录；没有记录时返回 `revision: null`。

### PUT

请求体：

- `sourceKind`
- `reportId`
- `version`
- `reviewStatus`
- `note`
- `editedContent`

服务端先解析真实来源版本、验证报告已完成，再按原始内容格式校验并保存修订。专题与合盘来源还会核对会话类型，防止错误类型跨用。

## 6. PDF 导出

PDF 仍以不可变报告版本为基础，但会优先读取该版本已保存的人工修订稿：

- 文件名标识 `vN-人工修订rN`。
- 导出元数据显示用户确认状态和人工修订稿号。
- 个人备注作为独立章节追加到 PDF。
- 用户修订内容参与来源指纹计算；修订变化后不会错误复用旧 PDF 缓存。
- 没有人工修订时，导出行为与 M3-1 保持一致。

报告版本差异比较仍比较 AI 原始版本，不把用户编辑混入生成质量与事实依据审计。

## 7. 验证结果

新增 `npm run test:report-revisions`，覆盖：

- 四类来源统一身份解析。
- AI 原始内容不可变。
- 章节标题、证据映射和免责声明不可被覆盖。
- 确认状态、个人备注和修订稿号。
- 年度纯文本报告修订。
- PDF 优先使用人工修订稿。
- SQLite v44 迁移和删除级联清理。

同时继续运行专题报告、年度报告、PDF、版本比较、合盘报告与校时报告回归测试，保证 M3-3 不改变已有生成与版本管理行为。

## 8. 后续方向

M3 的报告闭环已经具备生成、版本化、差异比较、确认、备注、人工修订和 PDF 导出。后续不再继续扩大报告编辑器范围，回到路线图中的紫微主线：优先补齐流月、流日确定性排盘，再增强事件回溯与公共数据备份能力。
