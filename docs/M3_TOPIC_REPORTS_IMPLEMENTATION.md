# M3 专题报告第一版实施说明

> 实施状态：第一版已完成
>
> 范围：单人命盘专题报告、报告版本、结构化依据和打印导出
>
> 说明：M3 第一版不包含合盘报告、时辰校正报告和服务端 PDF；三项能力后来分别由 M4、M5 与 M3-1 阶段补齐。当前专题、年度、合盘、校时四类报告均已支持统一的服务端 PDF 导出。

## 1. 第一版目标

把聊天中的零散解读升级为结构稳定、可以刷新恢复、可以重新生成并保留历史版本的正式报告。报告只引用命盘快照、规则引擎结果以及用户明确确认的人生事件，AI 负责组织解释，不负责补算命盘或编造现实经历。

## 2. 已支持的报告

- 命格总览报告
- 性格与天赋报告
- 事业发展报告
- 感情婚姻报告
- 财富模式报告
- 健康关注报告
- 当前大限报告
- 年度运势报告继续复用 M1 年度分析模块

合盘关系报告在 M4 实施；时辰校正报告在 M5 实施。

## 3. 数据模型

数据库第 6 版迁移增加：

- `reports`：报告主记录，同一会话同一报告类型只有一条。
- `report_versions`：不可变的历史版本；重新生成创建新版本。
- `report_evidence`：保存每个章节使用的命盘事实、规则结果或用户确认事件。

M3-2 的 SQLite v43 为版本补充生成原因与基准版本引用，并增加统一版本对比能力；用户可以区分事实依据变化、文字表达变化和生成元数据变化。

新版本生成成功后才会切换 `active_version_id`。如果生成失败，旧的有效版本继续可用。

## 4. 证据链

报告上下文由服务端生成，包含：

- 本命核心数据；
- 与报告主题相关的宫位、星曜、四化和空宫借宫信息；
- 当前大限；
- 程序识别的格局；
- 用户已经确认的人生事件。

AI 返回固定 JSON 结构，并为章节填写 `evidenceIds`。服务端会删除不存在的证据编号；没有有效证据的章节明确标记为“综合观察”。

## 5. 页面与接口

- `/chart/[id]/reports`：专题报告中心。
- `/chart/[id]/reports/[reportId]`：报告正文和版本历史。
- `GET /api/conversations/[id]/reports`：报告列表。
- `POST /api/conversations/[id]/reports`：创建或读取报告。
- `GET /api/reports/[reportId]`：读取当前或指定版本。
- `POST /api/reports/[reportId]/regenerate`：创建新版本。

报告正文页面继续提供“打印 / 另存为 PDF”。M3-1 已增加统一服务端 PDF 文件、导出记录、版本缓存、SHA-256 完整性校验和重复下载能力，覆盖专题、年度、合盘与校时报告。详见 `docs/M3_1_SERVER_PDF_EXPORT_IMPLEMENTATION.md`。

## 6. 安全边界

- 不把自由聊天中的未确认描述当成事实。
- 不允许 AI 编造职业、收入、疾病或婚姻状态。
- 健康报告不诊断疾病。
- 财富报告不提供具体买卖指令。
- 感情报告不替用户作出结婚或分手决定。
- 所有报告固定附带传统文化参考免责声明。

## 7. 后续迭代

- 增加两个版本的并排差异比较。
- 增加报告确认、备注与人工编辑层。
- 在 M4 接入双命盘合盘报告。
- 在 M5 接入候选时辰比较报告。
