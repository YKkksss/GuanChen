# M2-6 单命盘可移植导出、预检与事务导入实现说明

## 1. 阶段目标

整库备份适合灾难恢复和整台设备迁移，但不适合把某一份命盘合并进已有档案。本阶段新增独立的单命盘数据包，在不覆盖当前数据库的前提下，把命盘及其真正拥有的业务记录导入为一个新副本。

页面入口仍为 `/settings/data`，用户可在“整库备份与恢复”和“单命盘迁移”之间切换。

## 2. 数据包格式

- 扩展名：`.ziweichart.json`
- 编码：UTF-8 JSON
- 当前格式版本：`1`
- 最大文件体积：64 MB
- 最大业务记录数：100,000 条
- 完整性校验：SHA-256
- 数据库兼容策略：当前版本要求导出端与导入端迁移版本完全一致

JSON 文件包含来源命盘信息、数据表记录清单、明确的迁移边界、业务载荷和完整性指纹。指纹同时保护来源信息、记录清单、边界说明与业务数据，任意静默修改都会在预检阶段被拒绝。

## 3. 迁移数据范围

### 3.1 随命盘迁移

1. 单人命盘会话和完整命盘快照。
2. 聊天消息、上下文运行记录和长期记忆。
3. 流年、流月、流日快照及年度报告版本。
4. 人生事件、候选事件、运限关联和 AI 回看版本。
5. 专题报告、报告版本和证据记录。
6. 与该命盘关联的学习笔记和练习记录。
7. 本地提醒规则、提醒实例和月度复盘。

### 3.2 保持独立

1. 匿名案例：属于独立学习资料，不随来源命盘复制。
2. 生时校正工程：可能关联多份候选盘，不能归属于单一命盘。
3. 派生八字档案：拥有独立版本链，避免重复复制另一套规则数据。
4. PDF 文件：属于可重建缓存；报告正文和版本会迁移，导入后可以重新生成 PDF。

完整 PDF 和整套独立资料仍可通过 `.ziweibackup` 整库备份保护。

## 4. 关联闭包

导出不是简单查询带有 `conversation_id` 的数据表。服务会从 `conversations` 根记录开始，根据 SQLite 外键关系反复向下收集，直到没有新的子记录：

```text
命盘
├─ 消息 ─ 上下文运行 ─ 事件抽取候选
├─ 记忆 ─ 月度复盘
├─ 运限快照 ─ 运限报告版本 ─ 事件运限关联
├─ 人生事件 ─ AI 回看版本与证据
├─ 专题报告 ─ 报告版本 ─ 报告证据
└─ 提醒规则 ─ 提醒实例
```

如果一个可选外键指向数据包范围之外，导出时会将该引用断开为 `NULL`；必要外键存在外部依赖时会停止导出，不能生成一份表面成功但无法恢复的数据包。

## 5. 导入前预检

预检只读执行以下检查：

1. 文件大小、JSON 结构、数据包类型和格式版本。
2. 来源单人命盘必须且只能有一份。
3. SHA-256 指纹。
4. 数据表白名单，拒绝任何未授权表名。
5. 记录清单和实际记录数一致性。
6. 当前数据库字段与数据包字段完全一致。
7. 必填字段、数据类型和主键唯一性。
8. 数据包内部所有外键均有对应记录。
9. 当前数据库迁移版本兼容性。
10. 原记录编号与当前数据库的冲突数量。

原编号冲突不会阻止导入，因为正式导入不会复用这些编号；冲突数量用于向用户解释重映射范围。

## 6. 冲突处理与 ID 重映射

第一版只提供 `create_copy` 策略：

- 永远创建新命盘，不更新或覆盖现有命盘。
- 同名命盘自动建议“原名称（导入）”，再次冲突时继续增加序号。
- 为每张表中的每个主键生成新 UUID。
- 按 SQLite 外键元数据重写所有外键。
- 对未声明为外键但以 `*_id` 命名的内部引用进行二次映射。
- 递归解析 `*_json` 和 `content_json`，同步替换数组或对象中的消息、版本等内部编号。

这能保证导入后的命盘完全独立，删除原命盘或副本都不会影响另一份数据。

## 7. 事务安全

正式导入在单个 SQLite 事务中完成：

1. 重新解析并预检上传文件，不能信任浏览器之前的结果。
2. 预先生成所有 ID 映射。
3. 开启延迟外键检查。
4. 写入白名单内的全部业务表。
5. 在提交前执行 `foreign_key_check`。
6. 任意唯一约束、字段约束或外键失败都会回滚整份命盘。

不会出现只导入了命盘、却丢失一半消息或报告的中间状态。

## 8. 页面与接口

- 导出：`GET /api/chart-packages/export?conversationId=:id`
- 预检：`POST /api/chart-packages/inspect`
- 导入副本：`POST /api/chart-packages/import`

用户导入前可以查看来源名称、时间、数据表和记录数量、各业务分类数量、数据库版本、指纹以及 ID 冲突数量，并可修改新命盘名称。正式导入要求输入“导入为新命盘”。

## 9. 自动化验收

测试使用独立临时 SQLite，覆盖：

- 命盘、消息、上下文、记忆、事件、运限和报告的关联闭包导出。
- 接口下载和上传预检。
- 在存在原始 ID 冲突的同一数据库中创建副本。
- 主键、外键、普通 `*_id` 与 JSON 内嵌编号全部重映射。
- 报告活动版本、消息来源和上下文清单仍指向导入后的新记录。
- 缺少确认文字时阻止导入。
- 来源信息或业务内容被篡改时阻止导入。
- 制造消息唯一约束冲突后，整份导入事务完整回滚。
- 导入完成后 SQLite 完整性和外键检查通过。
