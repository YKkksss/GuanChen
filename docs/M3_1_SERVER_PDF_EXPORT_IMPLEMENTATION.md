# M3-1 服务端 PDF 导出实施说明

> 状态：已完成
>
> 日期：2026-08-30
>
> 数据库：SQLite v42
> PDF 渲染器：`report-pdf-v1`

## 1. 阶段结果

M3-1 将原有“浏览器打印／另存为 PDF”升级为可持久化、可校验、可重复下载的服务端 PDF 文件。当前统一支持：

1. 单人命盘七类专题报告；
2. 合盘关系报告；
3. 年度总结报告；
4. 出生时辰校正报告。

浏览器打印入口继续保留，作为临时打印和客户端兼容方案。服务端导出不会重新调用 AI，只消费已经完成并保存在 SQLite 中的报告内容和结构化依据。

## 2. 统一导出流程

```text
用户选择已完成报告版本
  -> POST /api/report-exports
  -> 校验报告类型、状态和版本
  -> 生成不可变来源指纹
  -> 命中同来源指纹 + 同渲染器版本时复用文件
  -> 未命中时使用 PDFKit 和嵌入式中文字体生成 A4 PDF
  -> 临时文件原子改名
  -> 保存字节数和 SHA-256
  -> GET /api/report-exports/:id/download 下载
```

PDF 生成失败不会修改原报告，也不会影响历史报告版本。

## 3. PDF 内容

统一 PDF 文档包含：

- 报告类型、标题和版本；
- 报告完成时间；
- 规则引擎、提示词、模型等版本元数据；
- 核心结论摘要；
- 完整章节正文；
- 每个章节的依据数量、依据名称和简要事实；
- 行动建议；
- 待观察问题；
- 使用边界与免责声明；
- 页脚、当前页码和总页数。

年度报告原本是 Markdown 风格纯文本，导出前会将 `【章节】` 标题转换成统一章节结构，不修改报告原文。

## 4. 中文字体

PDF 必须嵌入可分发的中文字体，否则跨设备打开时可能出现方块或字体替换。字体解析顺序为：

1. `REPORT_PDF_FONT_PATH` 和 `REPORT_PDF_BOLD_FONT_PATH`；
2. 项目 `assets/fonts/` 中的 Noto Sans SC；
3. Windows 的 Noto Sans SC、等线或微软雅黑；
4. Linux 的 Noto Sans CJK；
5. macOS 的苹方。

找不到中文字体时接口返回明确配置错误，不会退回不支持中文的 PDF 内置字体。

## 5. SQLite v42

新增 `report_exports`：

- `source_kind`：`topic`、`heming`、`annual`、`rectification`；
- 三类互斥来源外键：普通报告、年度报告、校时报告；
- `source_version_id` 和 `source_fingerprint`；
- `renderer_version`；
- 下载文件名与相对存储路径；
- MIME、字节数和 SHA-256；
- `generating`、`completed`、`failed` 状态；
- 错误码、创建时间、更新时间和完成时间。

数据库约束保证一条导出记录只能关联一种来源。删除来源报告时导出记录级联删除；磁盘文件在后续维护时按数据库有效路径清理。

## 6. 缓存与版本策略

唯一键由以下内容组成：

```text
报告类型 + 来源版本 ID + 来源内容指纹 + PDF 渲染器版本
```

因此：

- 同一版本重复点击下载直接复用文件；
- 专题、合盘和校时的新报告版本会产生新 PDF；
- 年度报告虽然复用同一报告记录，但内容重新生成后指纹变化，也会产生新 PDF；
- PDF 模板升级后修改 `renderer_version`，旧文件继续保留，新导出自动使用新版模板。

## 7. 文件安全

- 默认目录：`data/report-exports/`；
- 可通过 `REPORT_EXPORT_DIR` 修改；
- 数据库只保存相对路径；
- 真实路径必须位于配置目录内部，阻止目录穿越；
- 先写随机临时文件，再原子改名为正式文件；
- 下载前重新检查文件大小、PDF 文件头和 SHA-256；
- 下载响应使用 `private, no-store`，不允许公共缓存；
- 服务只导出已完成报告，不导出生成中或失败版本。

## 8. API

### `POST /api/report-exports`

请求示例：

```json
{
  "sourceKind": "topic",
  "reportId": "report-id",
  "version": 2
}
```

成功时返回导出记录、是否复用以及下载地址。并发请求遇到同一文件正在生成时返回 `202`，前端短轮询后重试。

### `GET /api/report-exports?sourceKind=topic&reportId=...`

列出指定来源的全部 PDF 导出记录。

### `GET /api/report-exports/:exportId/download`

完成完整性检查后下载 PDF，文件名同时提供 ASCII 回退和 UTF-8 中文名称。

## 9. 页面入口

- 专题报告详情：按当前选中版本下载；
- 合盘报告详情：按当前选中版本下载；
- 校时报告详情：按当前选中版本下载；
- 年度报告卡片：下载当前年份已完成的报告；
- 原“打印／另存为 PDF”入口保留。

导出失败会直接显示在按钮旁，不会把报告页面切换到错误状态。

## 10. 自动化与视觉验收

`npm run test:report-pdf` 覆盖：

- SQLite v42 迁移和互斥来源约束；
- 中文多章节、多页 PDF；
- 来源指纹和重复导出复用；
- 年度报告适配；
- 报告类型错配拦截；
- API 创建与下载；
- 文件头、字节数和 SHA-256；
- 文件损坏后自动重新生成；
- 来源删除后的记录级联和孤儿文件清理。

真实样例使用 Poppler 渲染为 PNG 后逐页检查，确认：

- A4 页面尺寸正确；
- 中文字体已嵌入且无方块；
- 长文本换行正常；
- 章节不被右侧依据标签挤压；
- 无额外空白页；
- 页脚和页码不覆盖正文；
- 首尾章节、建议和免责声明完整。

## 11. 当前边界

M3-1 暂不包含：

- PDF 密码和加密；
- 电子签名；
- 用户上传字体；
- 报告人工编辑；
- 两个报告版本的差异比较；
- 云端文件存储和公开分享链接。

下一阶段为 M3-2：报告版本差异比较。重点比较章节内容、结构化依据、规则引擎、提示词和模型元数据，并区分“事实依据变化”和“文字表达变化”。
