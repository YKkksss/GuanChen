# P3 安全与账号功能收口

日期：2026-10-18。范围：本地/局域网多用户使用所需的安全与账号功能，不以公网部署为前提。

## 1. 本轮功能

### 1.1 管理员本地重置密码

新增命令：

```bash
npm run accounts:manage -- reset-password 用户名
```

行为：

- 生成 24 字符随机一次性密码（base64url）。
- 更新密码哈希，撤销该账号全部会话。
- 清理该账号的登录/改密限额，避免重置后仍被旧失败次数挡住。
- 密码只在命令输出中显示一次，不写入数据库明文、日志或文档。
- 不提供邮件/短信找回；这是本地运维兜底，面向忘记密码的局域网用户。

### 1.2 每账号每日 AI 配额

新增 `AI_DAILY_LIMIT`：

```dotenv
# 默认 200；0 或负数表示不限制
AI_DAILY_LIMIT=200
```

实现：

- 在 `createChatCompletion` 与 `createChatCompletionStream` 调用供应商前扣减额度。
- 计数保存在账号库 `ai_usage(day, user_id, count, updated_at)`，按北京时间日期分桶。
- 只在有登录账号上下文时扣减；脚本/无账号任务不扣减。
- 超限抛出 `AiQuotaError`（`code=AI_QUOTA_EXCEEDED`，`status=429`），不会发起供应商请求。
- 失败/取消的请求也会计入额度，避免通过失败重试绕过成本控制。

数值边界：

- 未设置：默认 200。
- `0` 或负数：不限制。
- 非数字：按不限制处理（避免配置错误把所有人锁死）。

### 1.3 供应商错误脱敏

`lib/ai/deepseek.ts` 不再把供应商响应正文拼进抛给上层的错误：

- 对外统一为 `AI 请求失败（HTTP <status>）`。
- 服务端结构化日志只记录 `provider`、`status`、`detailLength`，不记录响应正文。
- 避免供应商错误里可能包含的请求片段、内部 ID 或用户内容进入客户端/日志正文。

## 2. 已复核/沿用的安全边界

- 所有业务 API 经 `withAccount`，未登录 401；`/api/health` 是唯一公开 API。
- 请求体 JSON 根对象、1 MiB 上限、同源写入、跨站拒绝、Cookie HttpOnly/SameSite/7 天绝对有效期。
- 登录限额按用户名与全局持久化，不信任可伪造的 `X-Forwarded-For`。
- 管理员不能停用/降级自己；改密、停用、角色变更撤销会话。
- 上传/备份大小、PDF 导出、账号隔离继续由既有专项覆盖。

## 4. 明确不做

- 邮件/短信找回密码、2FA、账号自助注销。
- 管理员网页端重置密码（当前只做本机命令，避免远程接管账号）。
- 按 IP/设备的细粒度风控、验证码、WAF。
- 全局 AI 预算/账单平台；当前是每账号每日次数上限。
- 真实公网安全验收（HTTPS、代理、渗透测试）由用户自行部署后按 P2 手册执行。
