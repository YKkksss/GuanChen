# M5-0 出生时辰校正基础实施说明

> 完成日期：2026-08-16
> 范围：方法论调研、时间口径、数据契约、规则配置、静态校验和自动测试

## 1. 阶段结果

M5-0 已完成校时模块的工程边界，但尚未创建数据库和用户页面。下一阶段可以直接依据结构化配置实现候选生成，而不需要让 AI 临时决定校时规则。

核心实现位于 `lib/rectification`：

- `types.ts`：校时会话、十三时段、候选、事件证据、规则命中、评分和评估结果契约。
- `methodology.ts`：版本化时间策略、事件宫位映射、八类初始规则、权重、安全边界和来源。
- `validator.ts`：检查时间段完整性、事件分类、宫位、权重、规则来源和禁用证据。
- `index.ts`：模块统一导出。

## 2. 关键决策

1. 结果名称从“准确率”改为“相对证据指数”。
2. V1 明确标记 `provisional-unvalidated`，权重不是统计校准后的概率。
3. 真太阳时必须同时考虑历史时区、经度和均时差。
4. 候选模型保留 iztro 的早子 `0` 和晚子 `12`。
5. 复用 M1 年度快照和 M2 人生事件，不让 AI 补算命盘事实。
6. 所有候选都命中的规则不计分。
7. 单事件和单类别贡献均封顶，并引入留一事件稳定性检查。
8. 发旋、姿势、外貌、疤痕和纯性格反推不进入规则。

## 3. 自动验证

新增 `npm run test:rectification-methodology`，覆盖：

- 十三个早晚子时段及引擎序号完整性。
- IANA、NOAA 和 iztro 时间策略声明。
- 十类人生事件映射及自定义事件禁评。
- 未确认、日期不详和无区分证据权重归零。
- 相对证据指数不能改名为正确概率。
- 安全规则、禁用证据和规则来源不可缺失。
- 未知宫位、重复时段、错误权重和未知来源能够被拦截。

## 4. 已识别技术债

当前单盘表单的真太阳时函数只做经度修正。M5-1 应新增独立的版本化时间转换器，并以回归测试保护现有排盘；不应直接修改旧函数后让历史命盘静默变化。

## 5. 下一阶段

M5-1 将实现：

- 校时 SQLite 会话与候选表。
- 原始时间证据保存。
- 历史时区、均时差和真太阳时换算快照。
- 2 至 13 个候选命盘生成、指纹和去重。
- 创建、恢复和删除校时会话的接口测试。
