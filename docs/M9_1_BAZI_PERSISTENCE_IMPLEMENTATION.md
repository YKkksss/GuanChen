# M9-1 出生档案与八字命盘持久化实施说明

## 1. 阶段目标

M9-1 将 M9-0 的一次性八字计算升级为本地可保存、可回看、可对照的排盘工作台，同时保持“出生事实”和“排盘规则”分离：

- 出生档案保存用户记录的民用出生事实。
- 八字版本保存一次确定性计算使用的时间标准、晚子时规则、算法版本和完整结果。
- 同一个出生档案可以拥有多个排盘版本。
- 相同档案、相同输入、相同算法版本不会重复保存。
- 八字数据继续与紫微命盘、紫微会话和紫微上下文隔离。

## 2. SQLite v23 数据模型

### 2.1 `bazi_birth_profiles`

保存字段：

- 档案名称。
- 公历出生日期和民用出生时间。
- 性别和时辰未知状态。
- IANA 历史时区。
- 出生地经度与地点备注。
- 用户备注。
- 可选的来源紫微会话编号。
- 创建时间和更新时间。

数据库约束：

- 性别只能为男或女的内部枚举。
- 已声明时辰未知时，出生时间必须为空。
- 已声明时辰已知时，出生时间不能为空。
- 经度必须在 -180 到 180 之间。
- 删除来源紫微会话只解除关联，不删除出生档案。

### 2.2 `bazi_chart_versions`

保存字段：

- 所属出生档案。
- 输入指纹和命盘事实指纹。
- 时间标准和晚子时规则。
- 方法论版本和引擎版本。
- 规范化输入快照。
- 有效时间与真太阳时换算快照。
- 完整确定性排盘结果。
- 创建时间和更新时间。

数据库约束：

- `birth_profile_id + input_fingerprint` 唯一。
- 删除出生档案时，全部八字版本级联删除。
- 删除单个版本不会删除出生档案或其他版本。

## 3. 出生事实不可变原则

已经保存的档案只允许修改：

- 档案名称。
- 出生地点文字备注。
- 用户备注。

出生日期、出生时刻、性别、时区、经度和时辰未知状态不能通过档案更新接口直接改写。用户在页面修改这些字段时，当前档案关联自动解除，再次保存会建立一份新档案。

这样可以避免“修改生日后旧八字版本仍挂在同一档案下”的历史污染。

## 4. 双指纹设计

### 4.1 输入指纹

输入指纹由以下内容计算 SHA-256：

- 方法论版本。
- 引擎版本。
- 规范化出生输入。
- 时间标准。
- 晚子时规则。
- 时辰未知状态。

用途：同一档案重复保存完全相同的计算条件时，直接返回已有版本，不产生重复记录。未来引擎版本升级后，即使出生信息和规则相同，也可以保存新版本进行迁移对照。

### 4.2 命盘事实指纹

命盘事实指纹包含：

- 引擎版本。
- 实际用于排盘的有效日期与时刻。
- 四柱、藏干、十神等柱级事实。
- 日主事实。

用途：识别不同输入或不同规则是否最终生成相同的确定性命盘结构，为后续差异对照和数据迁移提供依据。

## 5. 服务接口

- `GET /api/bazi/profiles`：读取出生档案历史。
- `POST /api/bazi/profiles`：创建出生档案并保存首个八字版本。
- `GET /api/bazi/profiles/:id`：读取档案及全部版本。
- `PATCH /api/bazi/profiles/:id`：修改档案名称和备注。
- `DELETE /api/bazi/profiles/:id`：删除档案及其全部版本。
- `POST /api/bazi/profiles/:id/charts`：按档案出生事实创建或复用一个排盘版本。
- `GET /api/bazi/charts/:id`：读取单个八字版本。
- `DELETE /api/bazi/charts/:id`：删除单个八字版本。

服务端始终根据出生档案重新调用确定性引擎，不接受客户端直接提交命盘 JSON，避免篡改或保存过期计算结果。

## 6. 页面工作流

`/bazi` 页面新增：

- 已保存出生档案列表。
- 新建档案入口。
- 档案名称和出生地点备注。
- “保存当前排盘”操作。
- 当前结果是否已保存的状态提示。
- 同档案多版本横向列表。
- 版本规则、四柱摘要和保存时间。
- 重新打开历史版本。
- 删除单个版本。
- 删除档案及其全部版本前的明确确认。

工作流：

```text
填写出生事实并计算
        ↓
保存出生档案 + 首个版本
        ↓
切换时间标准或晚子时规则
        ↓
重新计算并保存为同档案新版本
        ↓
在版本列表中来回对照
```

## 7. 自动化验证

新增 `npm run test:bazi-persistence`，覆盖：

- SQLite v23 迁移。
- 新建出生档案及首个八字版本。
- 相同输入的版本幂等复用。
- 晚子时双规则形成不同日柱和不同双指纹。
- 输入与有效时间快照完整保存。
- 出生事实不能通过展示字段接口改写。
- 相同出生数据可以属于不同档案。
- 档案列表、详情和单版本读取。
- 删除单个版本后其他内容保留。
- 删除档案后版本级联删除。

同时继续执行 M9-0 基础测试、会话测试、校时测试、TypeScript 检查和生产构建，避免共享数据库与时间服务回归。

## 8. 阶段边界

M9-1 仍不加入：

- AI 八字自由推断。
- 旺衰分数。
- 格局和用神。
- 大运、流年和具体事件预测。
- 紫微与八字综合断语。

持久化的首要目的，是为后续上下文、算法升级和流派对照提供可追踪的数据基础，而不是提前扩大解释范围。

## 9. 下一阶段：M9-2

M9-2 建议实现八字独立会话与上下文：会话只能引用已保存的八字版本；Context Builder 只注入确定性八字事实、实际计算口径和允许的基础知识，不注入紫微宫位、星曜或四化术语，也不允许模型重新计算四柱。第一版对话只解释基础结构和术语，不开放格局、用神及吉凶预测。
