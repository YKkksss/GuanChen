# M5-3 可审计规则评估与稳定性排序实施说明

> 完成日期：2026-08-16
> 范围：规则命中、区分度过滤、权重封顶、相对证据指数、候选排序、稳定性和评估历史
> 不包含：候选比较页面、设为当前命盘、AI 校时解释和校时报告

## 1. 阶段结果

M5-3 已把 M5-0 方法论和 M5-2 候选年度事实矩阵连接成确定性评估引擎。系统现在能够为每个候选输出当前候选集合内的相对证据指数、名次、支持依据、冲突依据、信息不足项和留一事件稳定性。

评估固定执行以下管线：

```text
版本化候选与事件事实
→ 八类规则原始命中
→ 全候选无区分证据归零
→ 单事件绝对贡献封顶
→ 单类别正向贡献封顶
→ 候选原始证据分
→ 当前候选集 0～100 相对归一化
→ 留一事件重算
→ 稳定性、并列和低置信度保护
```

AI 不参与上述任何一步，也不能修改命中、权重、分数或排名。

## 2. V1 规则实现

| 规则 | 实现口径 |
| --- | --- |
| 出生时间记录范围 | 候选真太阳时段是否落入换算后的记录窗口 |
| 事件年份大限主题 | 大限本命宫位是否命中事件主、辅助宫位 |
| 流年命宫专题落点 | 流年命宫对应本命宫位是否命中专题 |
| 年度重点宫位专题 | 流年三方四正或四化重点宫位是否命中专题 |
| 年度四化专题 | 四化星所在本命宫位命中专题，只记弱支持 |
| 多层证据汇合 | 同一事件至少两个独立规则层同时命中 |
| 事件不足保护 | 事件少于 3 个或类别少于 2 类时禁止稳定结论 |
| 候选不可区分保护 | 缺少区分规则、第一名并列或差距不足时禁止强选 |

业务规则未命中时一律是 `neutral`，不会自动变成冲突。V1 只有出生时间记录允许产生明确冲突，并且范围外冲突只适用于出生证明、医院记录和户籍记录等强时间来源；家庭或本人回忆的范围外候选保持中性。

## 3. 原始权重

事件规则的原始贡献为：

```text
基础规则权重
× 结果系数
× 事件证据质量
× 日期精度
× 影响程度调节
× 范围年份衰减
```

范围事件增加宽度衰减：

```text
范围年份衰减 = max(0.35, 1 / sqrt(事件覆盖年份数))
```

它避免持续十几年的模糊经历与精确到日的关键事件获得相同辨识力。影响程度与证据质量仍然分开计算，高影响不能替代可靠时间来源。

## 4. 防止重复放大

### 4.1 无区分证据归零

系统按“校时事件 + 规则编号”比较全部非重复候选。若所有候选得到相同结果，该规则即使全部命中也将 `adjustedWeight` 置为 `0`，因为它不能解释候选差异。原始权重和事实证据仍然保留，便于审计。

### 4.2 单事件封顶

同一事件的五类业务规则先聚合，再把绝对贡献限制在 `1.5`。超过上限时按比例缩放该事件各条规则，避免同一现实事件因为同时命中大限、流年和四化而被重复放大。

### 4.3 单类别封顶

每个候选先计算所有事件的正向贡献总量，再把单一类别限制在封顶前正向总量的 `45%`。超过限制的类别按比例缩放，避免大量事业事件压过感情、家庭或迁移等其他人生领域。

### 4.4 重复候选

结构指纹相同的候选不重复参与区分度、归一化和稳定性计算。重复候选继承原候选名次与指数，并通过 `equivalentToCandidateId` 明确指向原候选，不伪造第二组规则命中。

## 5. 相对证据指数与排名

非重复候选按封顶后的原始证据分排序，并在当前候选集合内线性归一化到 `0～100`：

```text
相对证据指数
= (候选分 - 当前最低分)
  / (当前最高分 - 当前最低分)
  × 100
```

全部候选同分时统一显示 `50` 并列。增加候选、事件或修改证据质量后，指数可以变化，因此该数值不能跨会话比较，更不是正确概率。

前两名差距比使用“出生时间规则最大正负差 + 每个事件的单事件上限”作为理论分母。低于 `10%` 时标记不可区分。

## 6. 留一事件稳定性

可评分事件不少于 4 个时，引擎依次移除一条事件，完整重跑区分度过滤、事件封顶、类别封顶和排序，记录每个候选成为第一名的比例。

第一候选只有同时满足以下条件才标记为中等置信度：

- 达到最低事件数和类别数。
- 第一名不并列。
- 存在有效区分规则。
- 前两名差距达到 `10%`。
- 留一事件第一名保持率达到 `75%`。

V1 不会输出高置信度。其他候选和不满足条件的第一候选均为低置信度。

## 7. 版本和持久化

数据库迁移版本升级到 `11`，新增：

- `rectification_evaluations`：评估版本、完整输入指纹、方法论版本、评估引擎版本、结果快照和稳定性。
- `rectification_rule_hits`：候选、事件、规则、原始权重、调整后权重、区分状态和结构化依据。

输入指纹包含：

- 出生时间证据和真太阳时快照。
- 候选命盘指纹及重复关系。
- 事件快照、证据质量、确认状态和评分资格。
- 全部候选年度事实指纹。
- 时间策略、方法论和评估引擎版本。

相同输入重复评估会直接读取缓存；任何证据或事实变化都会创建新版本，不覆盖旧评估。最新结果会同步回候选当前名次、指数和置信度。

事件新增、移除、确认状态或证据质量发生变化时，会话会立即从 `evaluated` 回到 `ready`，并清空候选当前名次和指数；旧评估历史仍然保留，直到用户重新执行评估生成新版本。

## 8. 接口

| 方法 | 路径 | 作用 |
| --- | --- | --- |
| `POST` | `/api/rectifications/:id/evaluation` | 执行评估或复用相同输入缓存 |
| `GET` | `/api/rectifications/:id/evaluation` | 获取最新评估及其是否仍匹配当前输入 |
| `GET` | `/api/rectifications/:id/evaluations` | 获取完整评估历史 |

接口不接收客户端分数、规则命中或排名。

## 9. 自动验证

新增 `npm run test:rectification-evaluation`，覆盖：

- 强时间来源的支持与范围外冲突。
- 真太阳时时间范围跨多个候选时段。
- 事件规则、弱支持和多层汇合。
- 无区分证据调整权重归零。
- 单事件贡献绝对值封顶。
- 范围事件宽度衰减。
- 相对指数、并列名次和低／中置信度边界。
- 事件不足保护及留一事件稳定性。
- 相同输入缓存、输入变化新版本和历史恢复。
- 评估、规则命中和校时会话级联删除。

## 10. 下一阶段：M5-4

M5-4 将开发候选比较工作台：

1. 候选时段、命宫、身宫、主星、指数和名次列表。
2. 事件 × 候选对照矩阵。
3. 支持、弱支持、中性、冲突和信息不足依据展开。
4. 两个候选的命盘结构差异高亮。
5. 并列、低置信度和指数非概率提示。
6. 在保留完整校时历史的前提下，将候选设为当前工作命盘。
