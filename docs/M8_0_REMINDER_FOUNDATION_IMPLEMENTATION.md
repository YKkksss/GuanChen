# M8-0 本地提醒基础与到期计算实施文档

## 1. 阶段目标

M8-0 建立主动提醒与周期复盘的工程底座，但暂不实现提醒中心页面和外部通知。本阶段解决：

- 提醒规则如何长期保存。
- 重复规则如何生成具体提醒实例。
- 到期、完成、忽略和关闭如何区分。
- 月度、生日、流年、大限、事件周年和自定义日期如何确定性计算。
- 本地应用未运行时，产品如何避免承诺实时通知。

## 2. 领域模型

### 2.1 提醒规则

`reminder_rules` 保存长期计划：

- `kind`：提醒类型。
- `status`：`enabled`、`disabled` 或 `archived`。
- `conversation_id`：可选的单人命盘关联。
- `event_id`：可选的人生事件关联。
- `timezone`：IANA 时区，默认 `Asia/Shanghai`。
- `config_json`：按类型区分的时间和重复配置。
- `engine_version`：当前为 `reminder-v1`。
- `last_materialized_at`：最近一次生成实例的时间。

### 2.2 提醒实例

`reminder_instances` 保存某一次具体提醒：

- `occurrence_key`：规则内唯一的发生键，防止重复生成。
- `scheduled_for`：被提醒事项实际对应的本地日期。
- `due_at`：考虑提前天数和时区后的绝对时间戳。
- `status`：`pending`、`completed` 或 `dismissed`。
- `payload_json`：来源标签、边界说明和可选阶段信息。

“到期”不是单独写入数据库的状态，而是读取时由 `pending && due_at <= now` 计算得到。这样系统时间前进后不需要批量修改记录。

## 3. 支持的规则

| 类型 | 配置 | 日期来源 | 边界 |
| --- | --- | --- | --- |
| 月度复盘 | 每月几日、时分 | 本地日历月 | 只表示复盘周期 |
| 生日回顾 | 提前天数、时分 | 单人命盘公历生日 | 只用于年度回顾 |
| 新流年观察 | 年度、提前天数、时分 | 每年 1 月 1 日 | 年度命盘仍使用既有代表日策略 |
| 新大限阶段 | 大限、提前天数、时分 | 出生年加大限起始年龄，对应公历生日 | 属于观察提醒，不替代精确历法校核 |
| 事件周年 | 提前天数、时分 | 已确认且精确到日的人生事件 | 不暗示事件会重复发生 |
| 自定义 | 日期、时分、一次/每月/每年 | 用户设置 | 本地待办规则 |

生日或自定义年度规则遇到 2 月 29 日且目标年份不是闰年时，安全落到 2 月最后一天。每月 29–31 日遇到短月份时，同样落到当月最后一天。

## 4. 日期与时区

- 日期在领域层使用 `YYYY-MM-DD`，避免服务器本地时区造成日期偏移。
- 规则保存 IANA 时区，默认使用 `Asia/Shanghai`。
- `due_at` 由“本地日期＋本地时分＋时区”确定性换算为 Unix 毫秒时间戳。
- 默认实例窗口为当前日期前 31 天至后 400 天，既能找回最近漏看的提醒，也能覆盖下一年度。
- 大限边界沿用当前项目的公历年龄口径，不额外引入未经验证的命理规则。

## 5. 生成与幂等

规则创建后立即生成实例。应用后续可调用批量生成接口，在启动或打开提醒中心时补齐未来窗口。

数据库使用 `(rule_id, occurrence_key)` 唯一约束：

- 重复生成不会增加重复实例。
- 配置或时区变化时，删除尚未处理的实例并按新规则重建。
- 已完成或已忽略的历史实例不会被配置修改覆盖。
- 停用规则后保留历史，但不进入到期列表，也不继续生成。

## 6. 关联与级联

- 生日、流年和大限提醒必须关联包含出生信息与命盘快照的单人会话。
- 事件周年提醒必须关联已确认且日期精度为 `day` 的人生事件。
- 事件提醒会自动继承事件所属会话，并拒绝跨会话错误关联。
- 删除来源会话或事件时，相关规则与实例通过 SQLite 外键级联删除。
- 删除规则时，其所有实例级联删除。

## 7. 服务端接口

- `GET /api/reminders`：按状态、类型或会话列出规则。
- `POST /api/reminders`：创建规则并生成实例。
- `GET /api/reminders/[id]`：读取规则。
- `PATCH /api/reminders/[id]`：修改标题、状态、时区或配置。
- `DELETE /api/reminders/[id]`：删除规则。
- `POST /api/reminders/materialize`：补齐全部启用规则的实例。
- `GET /api/reminder-instances`：按规则、会话、状态和时间范围列出实例。
- `GET /api/reminder-instances/[id]`：读取实例。
- `PATCH /api/reminder-instances/[id]`：完成、忽略或重新打开实例。

所有操作仅针对本地 SQLite，不发送短信、邮件、微信或系统推送。

## 8. SQLite v21

迁移新增：

- `reminder_rules`
- `reminder_instances`
- 规则状态、会话和事件索引。
- 实例状态与到期时间索引。
- 规则内发生键唯一约束。
- 会话、事件和规则删除级联。

## 9. 自动化测试

`npm run test:reminder-foundation` 使用独立临时 SQLite 验证：

- SQLite v21 迁移。
- 上海时区本地时间到绝对时间戳的换算。
- 五类提醒规则和流年、大限两类运限配置。
- 闰日生日与短月份月末收敛。
- 实例生成幂等。
- 到期、完成、忽略、重新打开和规则停用。
- 配置变化只重建待处理实例。
- 关联要求、日期精度和配置范围校验。
- 删除事件和规则后的级联清理。

## 10. 已知边界

1. M8-0 只提供数据、计算和接口，提醒中心页面在 M8-1 实现。
2. 本地应用没有运行时不会执行后台任务，也不承诺准时弹窗。
3. 当前不接入操作系统通知、邮件、短信或第三方消息平台。
4. 复盘填写、预测与现实反馈隔离、确认后写入人生事件将在 M8-2 实现。
5. 当前批量生成每次最多处理 100 条启用规则，适合本地单人部署。

## 11. 下一阶段 M8-1

M8-1 将实现本地提醒中心：

- 今日到期、未来提醒和历史记录分区。
- 完成、忽略和重新打开交互。
- 创建月度、生日、流年、大限、事件周年和自定义提醒的表单。
- 提醒规则的启用、停用、归档和删除管理。
- 应用打开提醒中心时自动补齐未来实例。
- 首页或主要导航显示本地到期数量，但不进行外部推送。
